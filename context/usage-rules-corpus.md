# Usage Rules Corpus — `codegen-document` + `shared/usage_rules/`

Machine-generated hex library API summaries — one file per library-version, generated by
`codegen-document <dep_name>` and regenerated whenever a locked dep version changes.

## Naming Bijection

`shared/usage_rules/<lib>-<version>.md` — one file per exact version. `INDEX.md` maintains a bijective
mapping; a parity gate checks every corpus file has an INDEX entry and vice versa.

## `INDEX.md` Is Cache-Scoped, NOT a Full Corpus Listing

**Load-bearing correction**: `INDEX.md`'s header states explicitly: "This index is cache-scoped to
[the consuming platform] and lists the usage-rules files relevant to its direct dependencies. The
shared corpus contains 90+ files covering many more libraries; only the deps listed here are direct
dependencies of the platform today." Do NOT treat `INDEX.md` as an inventory of the whole
`shared/usage_rules/` directory — it is a curated subset scoped to one consumer's direct deps.

## Planner-Only Grep-Guard

Only the planner role greps `shared/usage_rules/` for API surface during planning — developer/reviewer
do not re-grep this corpus; the planner's delegation prompt is expected to carry any needed usage-rules
citations forward.

## `codegen-document` Record Format

`extract_dependencies` emits pipe-delimited records carrying git coordinates alongside version info:

```
dep_name:version|repo_url|tree_ref
```

- Colon-delimited head (`dep_name:version`) — parsed by `cut -d:` at 4 call sites (pass1, pass2, count
  loop, single-dep mode). Colon separator is stable.
- Pipe-delimited tail (`|repo_url|tree_ref`) — optional, git deps only. Hex deps have empty tail fields
  (nil-guard-safe).

Chained-cut extraction: `cut -d: -f2 | cut -d'|' -f1` → version only. `cut -d: -f2 | cut -d'|' -f2` →
repo_url.

## `generate_usage_rule` — Backward-Compatible 3rd Param

Accepts an optional `$3` (full record). Single-dep mode constructs it explicitly:

```bash
dep_record="${dep_arg}:${dep_version}|${dep_repo_url}|${dep_tree_ref}"
generate_usage_rule "$hex_url_stub" "$output_dir" "$dep_record"
```

Calling without `$3` (hex deps, no git coords) is safe.

## Pass Distinction

- **Pass 1** (`usage_rule_needs_update` freshness check) — only needs `dep_name:version`; strips pipe
  tail since git coords aren't needed yet.
- **Pass 2** (rule generation loop) — passes the full record as `$3`. Definitive invocation where git
  coordinates matter.

## URL Priority Logic (3-tier)

1. **Git fork primary** — non-empty `repo_url` → fetch from GitHub tree URL at the locked commit.
2. **Hex versioned docs fallback** — no git coords, version-format regex matches → `hexdocs.pm/<dep>/<version>`.
3. **Hex latest fallback** — neither condition met → latest hexdocs.

The fork check MUST run first so tag-format deps (e.g. `2.2.0`) routing via GitHub tree aren't shadowed
by the version-format regex.
