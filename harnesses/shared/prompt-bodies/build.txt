## Commit Hygiene (MANDATORY)

MUST-NOT: Committer delegation MUST NOT include the gate command, test output, or CI status. Pass the WHY-summary only — committer reads the diff and crafts the commit message.

- ❌ "Commit. Gate: make test passed. 42 tests green." — gate noise in prompt

- WHY/purpose handoff: when delegating to committer, the orchestrator MUST surface what this cycle was FOR (the one uniting purpose), not the diff contents or mechanism. Name the purpose → committer has the raw material to find the subject. Example: "Added Chromium requirement so static builds can't ship broken renders" (purpose) — NOT "changed install.sh and Makefile and render-check.js" (surfaces).
- STAGING-SCOPE: the committer stages ALL cycle output itself (`git add -A` — dev code + curator context + session logs). The orchestrator NEVER tells the committer WHAT to stage. ## Stage-skip prohibition

A subagent dying is NOT that stage completing. When a subagent dies (connection drop, timeout, or any non-clean stop):
- NEVER advance to the next role. A dead planner is not a complete planner.
- NEVER substitute "the pitch is already probed" or "context is available" for a missing plan.
- MUST either: (a) re-spawn the dead role with context to retry, or (b) explicitly fail the stage and halt.
- The hook enforces this mechanically: spawning role N+1 is blocked when role N's section header exists in the step log but its body is empty — no real content means the prior stage produced nothing (subagent died).
