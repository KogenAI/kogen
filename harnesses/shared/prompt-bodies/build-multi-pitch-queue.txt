- **Multiple pitches** — When the operator names two or more slugs, or gives a "build all" instruction:

  **When the operator names NO slugs** (e.g. "build all ready pitches", "run everything in ready"):
  1. Enumerate `codegen/pitches/ready/*.md` using your harness's native file-listing tool — the **Glob tool** on claude, a **find/ls tool** on pi — NEVER a denied Bash exploration verb (`ls`/`find` via Bash, blocked by orchestrator-read-discipline on claude; equivalent blocked verbs on pi).
  2. If enumeration returns zero files, report "no ready pitches found" and stop.
  3. If enumeration returns one or more files, extract the slug from each filename (strip directory prefix and `.md` suffix). These slugs are the full pitch set — skip slug resolution entirely (files are already confirmed to exist).
  4. Apply the **"When NO order is given"** path below: read each pitch's `## Dependencies / Blocks-on:` edges, derive execution order by topological sort, then run the full Execution rules (one session log per pitch, strict sequencing, mid-queue halt).

  **Slug resolution (applies to all multi-pitch paths)**:
  Resolve each named slug to `codegen/pitches/ready/<slug>.md` using the Read tool — never `ls`, `find`, or Bash to enumerate. If any slug has no `ready/<slug>.md`, report the unresolved slug(s) plus the resolved ones and HALT before building any pitch.

  **When the caller provides a build order** (argv sequence `a b c`, or an explicit ordered list in prose/image):
  1. Treat that order as authoritative — never auto-reorder.
  2. Read each pitch's `## Dependencies / Blocks-on:` edges and validate against the provided order. If any declared edge contradicts the provided order, STOP and report the contradiction — do NOT silently reorder.
  3. Proceed with the validated order.

  **When NO order is given** (multiple slugs named without a specified sequence):
  1. Read each pitch's `## Dependencies / Blocks-on:` edges.
  2. Derive execution order by topological sort directly from those edges — no planner or subagent delegation to determine order.
  3. If edges are cyclic or ambiguous, report the conflict and HALT.

  **Execution rules (both order-provided and no-order paths)**:
  1. **One cycle log per pitch**: each pitch gets its own `<ts>_<slug>_cycle.jsonl`; never combine pitches into a shared `build-queue_cycle.jsonl` or any combined log.
  2. **Strict sequencing**: complete the full build for pitch[i] (including ready/→shipped/ move) before starting pitch[i+1]. Never overlap or parallelize. On claude that means the full planner→dev→gate→review→committer cycle; on pi it means the pitch's entire step queue.
  3. **Mid-queue halt**: if pitch[i]'s build fails (gate fails after one dev retry), HALT at position i; do NOT skip ahead to pitch[i+1].
  4. **Queue continuity is autonomous**: after pitch[i] ships, immediately run `codegen-log init --slug <next-slug>` for the next pitch's session log and begin its build — emit zero chat text, ask zero questions. NEVER ask the user permission to continue ("Should I proceed with pitch #2?", "Should I continue?", "are you stopping these builds intentionally?"). The ONLY legitimate stop is rule 3 (Mid-queue halt on gate failure).
  5. **Queue manifest (multi-pitch only)**: at queue start, Write `codegen/gate-pending/build-queue.json` = `{"slugs":["<ordered slugs>"],"position":0,"started_at":"<ISO ts>"}` using the topo-sorted slug list. After each pitch's ready/→shipped/ move completes, Edit the manifest to increment `position` by 1. When `position` reaches the slug count, delete the manifest (`rm codegen/gate-pending/build-queue.json`). A SINGLE-pitch or free-form build writes NO manifest. Do NOT end the session while the manifest still lists remaining pitches.

- **Prose/image-named pitches** — When the first-turn prompt names two or more pitch slugs in free-form prose or in an attached image, WITHOUT `@`-mentioning them as files and WITHOUT them arriving as discrete argv tokens — resolve each named slug to `codegen/pitches/ready/<slug>.md` via Read tool (never Bash), then apply the Multiple-pitches rules above. A single named pitch → one cycle. Never treat N prose/image-named pitches as one combined task. Error paths: a named slug with no `ready/<slug>.md` → report the unresolved slug plus the resolved ones and HALT before building any; cannot read an attached image → report it and ask the user to name the slugs in prose or `@`-mention them, never guess or proceed.

Post-commit stage (pitch-driven builds): after committer commits, move the pitch from ready/ to shipped/: `mv codegen/pitches/ready/<slug>.md codegen/pitches/shipped/<slug>.md` (plain `mv`, NEVER `git mv`). The pitch-shipped guard enforces the ready→shipped move before the session ends.
