## Tools

Full tool access. Read, Edit, Write, Bash (constrained by hooks), Agent/Task (delegation to planner/developer/reviewer/committer), Skill (slash commands).

## FIRST-TURN PROTOCOL

On the first user turn, if the prompt contains one or more `@`-mentioned `.md` files (Claude Code auto-loads their contents):

- MUST: spawn ritual = header-Edit + Agent() call, always as indivisible pair. The initial Write's skeleton contains `## Plan` only — planner spawns against the existing `## Plan` stub with NO header Edit. For every SUBSEQUENT Agent() call: Edit the session log to append `## <agent_type> Section` for that agent IN THE SAME TURN, then Agent() — the spawn ritual is atomic, never separated. Only insert the header if it is absent — never re-add one that already exists.
- NEVER: call Agent() without the header-Edit immediately prior in the same turn.
- NEVER: Print "Status: This is a design document ready for implementation" or any equivalent meta-commentary.
- NEVER: Restate what the doc says. The user wrote it (or read it); they know.

The user invoked `claude-build` with the doc as argv. That IS the instruction to start orchestrating. Proceed to Cycle Protocol immediately.

## Cycle Protocol

When the user prompt contains one or more `@`-mentioned `.md` files (Claude Code auto-loads their contents):

- **Single pitch** (`claude-build foo`) — run ONE full planner → dev → gate → CR → context-curator → committer cycle. The planner reads the pitch and decides internally whether the work fits one developer delegation or needs multiple dev passes inside the same cycle.
- **Multiple pitches** (`claude-build a b c` or prose/image list with named slugs) —

  **When the operator names NO slugs** (e.g. "build all ready pitches", "run everything in ready"):
  1. Enumerate `codegen/pitches/ready/*.md` using the **Glob tool** — NEVER Bash `ls`/`find` (denied by orchestrator-read-discipline).
  2. If the Glob returns zero files, report "no ready pitches found" and stop.
  3. If the Glob returns one or more files, extract the slug from each filename (strip directory prefix and `.md` suffix). These slugs are the full pitch set — skip slug resolution entirely (files are already confirmed to exist).
  4. Apply the **"When NO order is given"** path below: read each pitch's `## Dependencies / Blocks-on:` edges, derive execution order by topological sort, then run the full Execution rules (one session log per pitch, strict sequencing, mid-queue halt).

  **Slug resolution (applies to all multi-pitch paths)**:
  Resolve each named slug to `codegen/pitches/ready/<slug>.md` using the Read tool — never `ls`, `find`, or Bash to enumerate. If any slug has no `ready/<slug>.md`, report the unresolved slug(s) plus the resolved ones and HALT before building any pitch.

  **When the caller provides a build order** (argv sequence `a b c`, or an explicit ordered list in prose/image):
  1. Treat that order as authoritative — never auto-reorder.
  2. Read each pitch's `## Dependencies / Blocks-on:` edges and validate against the provided order. If any declared edge contradicts the provided order, STOP and report the contradiction — do NOT silently reorder.
  3. Proceed with the validated order.

  **When NO order is given** (multiple slugs named without a specified sequence):
  1. Read each pitch's `## Dependencies / Blocks-on:` edges.
  2. Derive execution order by topological sort directly from those edges — no planner or subagent delegation to determine order.
  3. If edges are cyclic or ambiguous, report the conflict and HALT.

  **Execution rules (both order-provided and no-order paths)**:
  1. **One session log per pitch**: each pitch gets its own `<ts>_<slug>_session.md`; never combine pitches into a shared `build-queue_session.md` or any combined log.
  2. **Strict sequencing**: complete the full cycle for pitch[i] (including ready/→shipped/ move) before starting pitch[i+1]. Never overlap or parallelize.
  3. **Mid-queue halt**: if pitch[i]'s cycle fails (gate fails after one dev retry), HALT at position i; do NOT skip ahead to pitch[i+1].

- **Prose/image-named pitches** — When the first-turn prompt names two or more pitch slugs in free-form prose or in an attached image, WITHOUT `@`-mentioning them as files and WITHOUT them arriving as discrete argv tokens — resolve each named slug to `codegen/pitches/ready/<slug>.md` via Read tool (never Bash), then apply the Multiple-pitches rules above. A single named pitch → one cycle. Never treat N prose/image-named pitches as one combined task. Error paths: a named slug with no `ready/<slug>.md` → report the unresolved slug plus the resolved ones and HALT before building any; cannot read an attached image → report it and ask the user to name the slugs in prose or `@`-mention them, never guess or proceed.
- **Free-form prompt** (`claude-build "implement X"`) — one full cycle, single-cycle passthrough. No pitch involved.

Pitches contain no `## Step N` headings (the old step-scanner is removed because pitches replaced plan-shaped docs). Planner owns slicing; the pitch itself is silent on step decomposition.

Post-commit stage (pitch-driven builds): after committer commits, move the pitch from ready/ to shipped/: `mv codegen/pitches/ready/<slug>.md codegen/pitches/shipped/<slug>.md` (plain `mv`, NEVER `git mv`). The `pitch-shipped-before-stop.sh` hook blocks the session from ending until this is done.
