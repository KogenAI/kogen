### Selection and public data contract

`provider list --json` exits 0 with one JSON object, `schema_version: 1`, and `profiles`, an ordered array of exactly two objects in the order in acceptance. Additional existing local-login information may be included, but never credentials. Each profile exposes its `id`, `provider`, `model`, `route`, `limits`, `settings`, `documented_efforts`, `qualifications`, and `evidence` as specified in acceptance. `evidence` is an ordered array of independently scoped citation objects with unique `id` values within the profile; each qualification row has an ordered nonempty `evidence_ids` array resolving to those objects. Shape/high and Build/medium on Sol and Review/medium on Sonnet cite only `go-live-2026-10-24`; Sol Review/high cites only `native-go-sol-review-2026-10-24`. Do not merge the two evidence sources into a profile-wide claim. The text form exposes the same scopes in human-readable form, preserving existing login lines. Documentation must distinguish recommended/configurable from official, and documented capability from demonstrated Kogen behavior.

A newly emitted attempt's `compatibility` is `{status, profile, role, provider, model, effort}`. `status` is `supported` only for an exact qualified role/provider/model/effort on its normal route with text/tool input; otherwise `experimental`. `profile` is the exact known profile ID or null for an unknown model/provider pair. Keep configured strings unchanged, including experimental efforts. Use the actual native role from request context; absent/unrecognized roles cannot be official. Refine uses Shape's selection; optional workers are not automatically Shape. A `KOGEN_PROVIDER_URL` or `KOGEN_AUTH_URL` override makes the selection experimental even if the model matches. A generic compatible host, including a host advertising one of the known IDs, cannot inherit official subscription/API-route status. Response-reported names cannot grant qualification. Typed image requests are not included in this text/tool qualification: keep existing ChatGPT typed-image plumbing experimental and all existing Anthropic/chat-wire image refusals and external pixel-review handoffs.

For provider rejections, retain the provider's error and no-retry behavior. Contextual diagnostics must identify role, provider and configured model/effort, say whether the selection is experimental, and identify the role's editable mapping, e.g. `.kogen/project.yaml models.review.model` / `models.review.effort`. This mapping is the actionable source selector; do not fabricate a numeric line number. Preserve callers' stage stop behavior. In particular, review/supergrok/no-such-model with HTTP 400 `model not found` sends exactly one request, not a fallback.

### Operational settings and limits

Known profile settings apply even when a different role/effort makes that selection experimental; arbitrary unknown IDs retain the existing provider/wire fallback, explicitly experimental, with unknown family limits rather than guessed ones. No new field is sent merely because it appears in documentation.

For Sol 6.1, preserve Responses at `https://api.openai.com/v1/responses`: streamed responses, `reasoning.effort`, encrypted reasoning inclusion and ordered item replay, unchanged native tool schemas with auto tool choice, `store: false`, conversation `prompt_cache_key`, no `prompt_cache_options`, no private session header, and no new max-output parameter. Documented context/input/output bounds are 1050000/922000/128000 tokens. Output/reasoning share the documented output allowance; the 131072 reserve remains conservative accounting, not an extra wire allowance.

For Sonnet 5.5, preserve streamed Messages at `https://api.anthropic.com/v1/messages`, API version `2026-10-21`, adaptive thinking with `output_config.effort`, `max_tokens: 128000`, auto (not forced) tool choice, input_schema conversion without inventing a strict-schema guarantee, exact signed thinking/assistant-message replay once, and existing ephemeral cache breakpoints on last tool, system block and newest eligible message. Documented context is 1000000 tokens, output 128000; a separately documented maximum-input number is unknown/null. Do not send manual thinking budgets, force tools, switch models mid-conversation, modify replay prefixes or enable images. API vision availability is not native Kogen pixel qualification.

Keep the byte proxy inclusive and reserve unchanged in every caller and the provider preflight. For these two profiles its 524288 cap is already below documented context/input capacity after reserve. When evaluating known limits, bound the proxy by the minimum of the global byte cap, any known maximum input, and known context minus reserve, using a conservative byte-as-token proxy, not a claim of measured tokenization. Do not change the guard for unknown families into a claim that they fit; provider context errors below it remain honest failures. Builder unit tests must establish the smaller-known-bound calculation and equality/adjacent boundaries through a callable interface, in addition to preserving the actual serialized-request tests here. No added user budget knobs or speculative tokenizers.

Recommendations and open selection remain the delivered baseline. Preserve arbitrary `model`/`effort`, defaults for omitted role selections, compatible `base_url` and optional own-store key, tool/replay/cache rules and usage recording. Generic hosts get no vendor cache controls or foreign credentials. No new prices: unknown models/unknown prices remain unknown and usage is still recorded. Vendor public API prices do not become subscription cost estimates.
