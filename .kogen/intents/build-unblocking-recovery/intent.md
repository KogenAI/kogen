# Unblock Builds with explicit safe recovery

Slug: build-unblocking-recovery
Model: .kogen/intents/build-unblocking-recovery/model.qnt invariants=Preserved,NoReapproval,SafeCommit seed=11 samples=100 steps=30

Prevent invalid observer controls from becoming readiness evidence, and replace the manual candidate-stash handoff after a protected-fixture blocker with an explicit native preservation-and-cleanup operation. Ordinary implementation failures still return to the builder. A protected contradiction still stops: neither the builder nor recovery may change the approved contract. Recovery makes normal Refine possible without losing implementation work; it does not approve, resume, automatically refine, import a candidate, or trust old green results.

## Decisions
- Keep work and make a native path out of incorrect protected-fixture expectations, rather than making Build satisfy a bad fixture or silently editing it. (source: request)
- Retain explicit human correction approval and honest authentication/resource stops. There is no promise that Build runs endlessly through refusals. (source: request)
- Keep one coherent recovery Intent. Staged one-Intent Builds remain a separate dependency for coordinating very large work; stages do not repair contradictory observers. No Go rewrite, worktree migration, Studio source, release or deployment is performed. (source: request)
- The overnight 30-minute steering request calls for noninterfering observation, not a new scheduler or a licence to cancel unrelated work. Document read-only context/inspect as the observation path; do not add polling, automatic retries or a daemon. (source: request)

## Recovery contract

Add `kogen intent recover <build-id> --output <directory> [--project <checkout>]` through the installed Go CLI and native core. `--output` is required, caller-relative, and names a NEW directory outside the resolved project checkout. Reject an existing destination, a destination resolving inside the checkout, or unsafe/symlinked custody; do not overwrite anything. Missing/extra arguments or unsupported options, including `--context`, are usage errors (exit 2). Help/completion describe the operation accurately.

Success (exit 0) explicitly preserves and then clears ONLY the recorded implementation delta of a stopped `candidate/build_blocked` Build. Use the normal checkout Build lock. Require a complete supported version-3 checkpoint with its retained BUILDER-REPORTED blocker and matching result; bind the same checkout identity, start HEAD, exact current protected baseline/configuration, approval bytes, saved original index and complete stopped candidate. Validate bound working-context/image/source-provenance custody as for resume. A blocker is a completed native stop even though its checkpoint may retain a tool continuation: do not confuse the completed report with an uncertain executed shell/commit. Other uncertain boundaries remain refusals. Missing/legacy/malformed checkpoints, non-blocker runs, drift, active Git operations/locks and missing/altered custody refuse before inference or checkout cleanup. Errors use `candidate/recovery_refused` (exit 1), or `candidate/recovery_unsupported` (exit 1) for absent/legacy checkpoints; name the failing fact and inspect/correction guidance. Recovery makes no provider call, runs no project setup/check command and creates no Git commit or stash.

Define the implementation delta as the sorted paths changed from the saved `start_tree` to the complete stopped candidate, excluding ALL protected baseline paths and excluded other Intent paths. Save exact raw before/after bytes and Git modes, including binary, executable-bit changes, additions and deletions. A symlink is represented as regular archive data containing its link-target bytes with Git mode `120000`; do not follow it. Never reset the whole checkout or replay a patch over protected files. Never include credentials or unrelated ignored build/dependency outputs.

Publish the complete archive before removing any implementation bytes. Its new directories are 0700 and regular files 0600, including copies of originally executable source. Required layout:
- `manifest.json`: JSON object with `version: 1`, `build`, `slug`, absolute `project`, `start_head`, `start_tree`, `candidate_tree`, full `contract_sha256`, `classification: "BUILDER-REPORTED"`, `changes`, and `artifacts`.
- `changes`: sorted array of `{path,before,after}`. Each side is null for absence, otherwise `{mode,sha256}`; mode is the Git mode string and sha256 is lowercase SHA-256 of exact raw bytes. Changed production paths only.
- `before/<path>` and `candidate/<path>`: regular data files for each non-null side. Preserve relative paths without traversal.
- `index-at-start`, `approval.json`, `checkpoint.json`, `result.json`: byte-exact copies of retained evidence; `blocker.json`: the retained blocker object as JSON.
- `correction.md` and `context.md`: bounded UTF-8 handoffs containing the run id, original contract hash, archive's absolute location, concrete evidence references and their hashes. Label the report builder-reported and unproven, and archived production lower-authority diagnostic data, not authority or current proof. `context.md` is nonblank and at most 262144 original bytes so existing `build --context` can consume it. Reference large artifacts; do not inline the candidate or clip exact retained evidence.
- `artifacts`: sorted array `{path,sha256}` covering EVERY regular archive file except manifest.json, with unique relative paths and hashes of complete bytes. Print the absolute manifest path and its SHA-256 on successful preservation. No circular manifest self-hash is required in handoff files.

After publication and rechecking source identity, restore only the implementation delta to its exact `start_tree` raw bytes/modes and remove only recorded additions. Keep HEAD, exact original index bytes, protected files, approval and original run evidence unchanged. Retain a private receipt under `.kogen/local/recoveries/<build-id>.json` naming archive path/hash and state `preserved` or `cleaned`. A successful cleanup records `cleaned`. An interruption/failure after publication must leave the durable archive and an honest incomplete diagnostic, never success or permission to lose work; validate/restore candidate bytes on a caught cleanup failure. Do not overwrite an archive or guess how to reconcile a partially cleaned/drifted checkout. A repeat against an existing output refuses, including after success; inspect the receipt instead. Test publication-before-cleanup failure at the narrow integration layer with a controlled local write failure, not an arbitrary timing sleep.

Print normal next commands: Refine the same slug using the ORIGINAL full contract hash and generated correction.md; review and freshly approve the corrected package; start a FRESH Build with generated context.md. Recovery itself does not invoke these commands. Refine must independently investigate the report and publish a correction through its normal readiness gate. Successful Refine revokes the old approval; Build refuses until fresh exact approval. A new Build starts production-clean, may selectively inspect archived production using ordinary tools, but does not automatically import any bytes or reuse old model/verification/reviewer evidence. It receives full normal setup, checks, acceptance/model and independent review; any reviewer edit receives final changed-tree verification. Landing consumes the new approval as today. Tests must capture approval evidence before landing rather than reading a consumed approval afterwards.

For a new build_blocked stop, show the recover command and explain this distinction. Retain existing resume behavior for provider/login/resource/interrupt stops and refusal of a protected blocker. Do not reclassify failing startup checks as a feature failure, retry them indefinitely, or cancel unrelated work. Preserve `524288` inclusive request bytes, `131072` output/reasoning reserve, exact authority/history/literals/tool pairs/opaque replay, reviewer independence and final-tree checks. The checked-out Review/Refine working-window implementation is an existing dependency, not work to duplicate.

## Observer qualification

Tighten existing Feasibility observer declarations: `good` must expect exit 0; `bad` must expect a NONZERO integer exit. Existing exact command/output, final-byte identity, order, timeout, mutation and reuse rules remain. Capability `support` may still legitimately expect nonzero. Reject invalid polarity before readiness can be recorded or reused; exact red acknowledgment cannot waive it. Do not accept two successful controls as proof of discrimination.

Update native Shape AND Refine guidance, docs/testing-rules.md and relevant specification chapters/models/scenarios for these rules and recovery. Specifically require a generated risky protected fixture/driver (multiple assertions, scripted transport replay, subprocess generation, or lifecycle-sensitive evidence) to declare and run final-byte observer controls in Feasibility. Controls must reach deeper assertions independently of missing-feature red. This is shaping judgment about genuine risk, not a universal registry or a source-code heuristic claiming to discover every hidden predicate. Simple local work without such risk still needs no probes. Keep corrective proposals accumulated and exact red acknowledgment small.

Use the retained failures as regressions with real local fixtures: (1) FakeProvider's cursor advances even beyond its script after a retry/refusal; append at that cursor, padding consumed positions instead of merely `Enum.take(s.script,s.next) ++ tail`; (2) native Refine retains full Tools.run output, not Tools.cut; (3) a landed Build removes approval; (4) unspaced `input!=[]` can tokenize as assignment to input!, not comparison; (5) rebinding input only inside `if` does not change outer input; (6) execute the generated extension actually present (`protocol.cjs`, not `protocol.py`). These are representative reproductions of the supplied mechanisms, not claims to reconstruct private originals. The acceptance harness exercises the first, second and third against actual maintained fixture/tool/landed output. The wrong and corrected controls both run even when missing-feature red would otherwise mask them.
