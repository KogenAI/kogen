### Working-window contract

Use a fixed conservative **524288 UTF-8 byte ceiling on the complete rendered outbound JSON request**, including policy/developer blocks, input, tools and request envelope, with **131072 tokens reserved for output/reasoning**. Bytes are an intentionally conservative input proxy, not observed token usage or a measured provider refusal threshold. Published Sol metadata (1050000 context, 922000 input, 128000 output) and last COMPLETED input 883138 do not establish a rejection threshold; the subsequent failed request's usage/size remain unknown. There is no new CLI/YAML setting, provider field, or total-run cap. Expose the shared calculation as `Kogen.WorkingContext.measure(body_map)`, returning `%{rendered_bytes: integer, input_budget_bytes: 524288, output_reserve_tokens: 131072, fits: boolean}` using the same serializer as transport. Equality fits; one byte above does not. Preflight must measure the request actually sent, not just conversation text.

Before every builder/reviewer request, at a completed request/tool-batch boundary, continue unchanged if it fits. If it does not fit and safe reduction exists, archive the full old window, then start an explicitly labelled new local window. Do not reset between a call and its output, during tool execution, or while execution is uncertain. Do not replay tools to manufacture completed pairs. Within an ordinary window preserve native replay items, their order, assistant phase and opaque encrypted reasoning bytes unchanged. At a reset, entire completed exchanges may move to history; opaque items are not edited, summarized or selectively spliced as if still ordinary replay. Retain the newest completed exchange intact when it fits; if an exchange itself is irreducible, stop rather than loop reset indefinitely.

Every new window carries the exact approved Intent/feature/model, README, testing rules, commands and protection, source-provenance retrieval reference and any frozen diagnostic context. It carries current candidate identity, phase and repair owner, unfinished work, unresolved findings, current honest check status and history references. Keep model-authored progress/unfinished-work/finding statements losslessly unless explicitly superseded; label them as observations, never approvals or proof. Native check results are authoritative only for their exact candidate: editing invalidates current green status; failed, unrun, stale and unknown remain distinguishable. Repeated superseded failure bodies and obsolete whole-file tool arguments may move to history. Do not infer completion from a handoff. A reviewer reset continues the same independent reviewer stage and unresolved findings, never importing the builder's reasoning or starting another whole critique.

Use a user data message starting exactly `Local working-window reset\n` followed by JSON with `version: 1`, `owner` (`build` or `review`), `phase`, `candidate_tree`, `approval_sha256`, `checks` (including `status` and candidate identity), `unfinished`, `findings`, and `history` (ordered `{path,sha256}` references). Additional native factual fields are allowed, not new authority. The runtime derives identities/status; handoff text cannot grant green/review/commit eligibility. Include a bounded progress/reset notice with measured bytes, ceiling, reserve and history reference, not raw prompts.

Archive prior windows under `.kogen/local/runs/<id>/working-context/<owner>/` as immutable ordered JSON files containing `input` arrays, linked by exact-byte SHA-256 references. Together with the checkpoint's active window these recover the full ordered replay history, including complete tool calls/outputs, exact multiline Unicode, and opaque items. Existing individual tool-output caps are unchanged; this feature introduces no further historical truncation. New custody directories are 0700 and files 0600 even under umask 022. Do not put raw history, originals, credentials or authorization headers into console or generic metadata logs. Retain old failed attempts/results/usage, not just the last window.

Checkpoint the active window, archive hashes/order, owner, phase, current findings/progress and source binding atomically with existing candidate/HEAD/index/approval/configuration guards. Resume must continue the saved owner and window without duplicating completed effects, clearing findings or laundering old evidence. Missing, changed, unsafe or unreadable referenced custody is an actionable refusal before inference or mutation. Keep no-commit-on-uncertain-tool/commit safeguards. Version-2 pre-window checkpoints may be safely supported through explicit validated migration or explicitly refused as unsupported with no changes; never silently treat absence of working state as a new Build. New checkpoints expose their continuity state in the decoded saved Build map as `working_context` and source binding as `source_provenance` (both may be nil for a genuinely absent legacy source). Unsupported legacy transitions must remain inspectable.

If mandatory material alone cannot fit, or reduction cannot make progress, fail `candidate/context_budget_exceeded` before sending the oversized request. Report role, measured/mandatory bytes, ceiling, reserve, retained checkpoint/history paths and actionable instructions to inspect custody and use ordinary Refine/new approval if scope must change. Leave candidate/index/HEAD/approval intact. Never retry the identical oversized payload, silently truncate, automatically split the Intent, or claim provider exhaustion was prevented universally. Provider context errors below the conservative proxy remain honest failures, not permission to drop authority.
