# Bound model-facing tool results

Slug: bounded-tool-results
Model: not applicable — this applies an existing stateless text-output transformation at the shared result boundary; it does not add a lifecycle, retry or working-window state
Acceptance:

Prevent the retained long-line read failure without increasing context limits or introducing a supervisor. Apply the existing LOOP-8 text-result contract consistently to model-facing tool outputs in native Shape, Refine, Build, independent Review and optional Shape workers. Text outputs, including errors and control-tool feedback, must be at most 16384 UTF-8 bytes INCLUDING the omission marker. Preserve results of at most 16384 bytes exactly. For larger text, preserve the first 4096 bytes (backing off only an incomplete UTF-8 character), then `\n[... N bytes omitted ...]\n`, then a valid UTF-8 suffix fitting the remaining room, as the existing cutter does (conservative marker-width reservation and incomplete-character backoff may leave a few bytes unused). N is the actual number of original bytes absent from the displayed result. Bounding is idempotent. Use the existing common result construction/capping interfaces, not separate role-specific policies. Update their documentation and the relevant specification prose/scenarios so they describe the same contract.

This replaces Shape/Refine/worker delivery of unbounded text, not exact private authority or history. A line range is not a byte limit: a 514440-byte single-line JSON file read with start_line=1/end_line=35 must receive the same honest bounded display as any other oversized text. This includes explicitly selected git-ignored working-context custody; do not hide .kogen/local or forbid those reads. Ordinary fitting file reads retain current numbering, ranges, whitespace and errors. Large results are visibly incomplete, never presented as complete source delivery. No new pagination API, settings, dependency or provider request parameter is needed. Existing line/path/pattern selection remains available. Complete private originals and working-window archives are not rewritten or clipped; complete pinned Review source parts must still be delivered before approval. Documentation lookup records/progress remain valid structured records; bounding their model display must not corrupt native parsing or claim unperformed discovery. Probe evidence retains actual native outcomes; bounding is only model-facing presentation.

Keep the inclusive 524288-byte complete rendered JSON ceiling and 131072-token reserve. One oversized text result must no longer make the newest exchange irreducible merely because of that result's original length, even after a working-window reset. The bounded display is the actual tool output paired with its call and replayed exactly thereafter; never retroactively recut historical outputs on reset/resume. Keep opaque reasoning, assistant phases, call IDs, argument strings, batch order, source binding and working-context custody. This is not a promise that arbitrary authority, model-generated arguments, observations, large parallel batches or typed images always fit: existing honest irreducible-input/provider/custody refusals remain. Typed view_image content passes unchanged, under its existing image-size, custody and request-budget rules. Do not convert images to text or clip authoritative contract inclusions to make requests fit.

The requested improvement is native progress past avoidable tool-result overflow, not permission to bypass incorrect protected tests or force every Build to land. Preserve builder-reported protected-blocker recovery and normal repair/verification/review. The historical requests are retained literally in the executable scenario packet: 23 October, `"47 minutes across two Builds, each stopped by a different incorrect test expectation." - Why are builds stopping tho? When something is shaped, why doesn't build go on until it's completed? Or was it the problem in incorrect shaping?
