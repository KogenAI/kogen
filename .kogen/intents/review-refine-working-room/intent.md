### R1 — Review continuation source pressure

The current `ReviewMaterial.prepare/8` pins source only when the initial request exceeds the ceiling. If it fits, `WorkingContext.prepare/7` subsequently treats the whole initial source message as mandatory. This explains a continuation failure without invalidating the delivered initial-review repair.

At a completed Review boundary, preflight the complete next request. If it does not fit, remove reproducible candidate source/diff from mandatory active material using the existing private hash-bound source-part mechanism, then attempt one deterministic smaller window. Do this for fresh reviews and supported version-3 inline Review checkpoints, including explicit resume after a provider failure. Do not start a fresh review, rerun the builder, change the independent stage, or require reapproval for this representation-only transition. Small fitting continuations remain unchanged; already-pinned source is not re-pinned on every reset.

Keep verbatim the approved Intent/feature/model, README, testing rules, configured protection/commands, frozen caller diagnostic and exact check results. Preserve the complete originally supplied source message privately, including any duplicated package text, in ordered parts with exact hashes; no source omission is authorized. Keep the existing path/status/mode/blob/byte/hash catalog and candidate/start binding where established. A version-3 inline checkpoint can be converted from its exact saved contract/source blocks: do not reconstruct its historical source from an edited checkout, or label old source as current. If a historical binding cannot be established, retain it honestly as historical evidence and bind newly materialized current candidate evidence separately; never invent a tree association. Only native current-tree results determine eligibility.

Source relocation is not inspection. Review must receive every newly pinned part through a complete matching read_file output in a completed provider continuation before approving. Preserve existing delivered-part evidence across resets/resume, complete tool batches, assistant phase, opaque reasoning, observations and unresolved findings. Same-response read-and-approve, missing/wrong/clipped outputs and archive references alone remain insufficient. Source custody must be checkpoint-bound and validated before inference or effects. Final reviewer edits still receive external exact-final-tree verification and the same reviewer handles failures. Builder conversation/reasoning never enters Review.

### R2 — Refine working windows

Keep Refine's existing frozen-original context index and explicit full originals. In `kogen intent refine <slug> <full-sha256> <correction-file>`, preflight every complete rendered next request, including instructions, tool schemas, envelopes, manifests, replay and cache controls. At a completed response/tool-batch boundary, archive an oversized input exactly and try one deterministic smaller window. Do not reset mid-batch or discard an unexecuted call. Initial mandatory authority includes the exact correction, original owned artifacts, README, testing rules, commands/protection and original contract/source-provenance binding. README is not excluded from authority to make this fit.

The smaller window keeps that exact initial authority, the newest complete exchange, cumulative proposals and formatted-candidate retrieval identities, frozen originals/ownership, exact observed readiness identity and observations, invalid-submission count, discovery/documentation records and assistant observations. These native states remain authoritative in-process; a handoff is diagnostic, not new approval or a model-authored summary substitute. Old manifests can move to exact history; the current complete manifest must be available. Latest well-formed proposal wins, omitted paths persist, an unsafe mixed submission contributes nothing, and explicit originals revert only when submitted. Reset cannot clear invalid counts, fabricate documentation, acknowledge unseen red, waive ownership or change Acceptance/model presence.

Use `.kogen/local/refinements/<attempt-id>/working-context/<n>.json` for ordered version-1 archives with `owner: "refine"`, exact `input` and `previous` path/hash (null first). New custody directories are 0700, files 0600; hashes cover the complete bytes. Validate the linked chain and regular non-symlink custody before each subsequent inference, tool effect and publication. Missing, altered, symlinked or unsafe custody stops as `candidate/context_custody_invalid`; no further inference/publication or approval revocation. Record `working_context_reset` in the existing refinement events with owner, generation, before_bytes, after_bytes, input_budget_bytes=524288, output_reserve_tokens=131072 and archive path/hash. Progress identifies Refine, before/after bytes and retained custody. Keep existing documentation lookup events/progress and honest usage accounting.

All existing Refine publication rules remain: failed/refused attempts preserve original package, successful source custody, approval, HEAD and index. Check the complete accumulated formatted candidate freshly when changed; an exact inspected unchanged red acknowledgment reuses only that same readiness observation. Success publishes the whole corrected package, archives/revokes old approval and requires ordinary new exact approval. No new files, shared steps, Acceptance-path changes or model addition/removal become supported.

### R3 — Honest limits and preservation

A reset is possible only if the one deterministic reduced complete request is both smaller and at most 524288 bytes. Equality fits. For Refine retain the exact unsent input in the same private chain and record `working_context_stop` with owner, measured_bytes, mandatory_bytes, limits and archive. Explain that an identical fresh retry is not recovery; Refine has no persistent resume. Existing Review checkpoint/refusal semantics remain honest and preserved. Do not loop resets until something happens to fit. Provider errors below the proxy remain provider errors; this contract adds no retry policy or account probing.
