## P2. Does the Build's Developer sandbox allow network for `cargo fetch`?

Code at f1d176b0: `Kogen.Build.WriteBoundary.render/1` emits `(allow default)`, `(deny file-write*)`, then allows
writes only under the Candidate, the harness home, the per-Build temp dir (`TMPDIR`), the device files, the
Claude `.oauth_refresh.lock`, the Codex scope minus denials, and the login keychain. There is no `network*` rule, so
network is allowed; `WriteBoundary.environment/1` sets `TMPDIR` to the Build temp dir. `HOME` is the caller's
under Claude (`Kogen.ClaudeCode` moduledoc: "`HOME` stays the caller's") and is restored to the caller's by the
Codex exec-server entrypoint (`Kogen.Codex.Environment`, `executor_entrypoint_contents/0`: `export
HOME="$KOGEN_CALLER_HOME"`), so a Developer shell's cargo uses the real `~/.cargo` and `~/.rustup`, read-only.
Controller-run verification (`Kogen.Build.VerificationRunner.run_target/4`) is not wrapped by the boundary: it runs
`make -C <Candidate> check` with the controller's environment (real HOME, network) minus the scrubbed names.

`evidence/probe-profile.sb` reproduces the boundary for the probe (writes only to the crate dir and a temp dir).
`profile-nonet` = the same plus `(deny network*)`.

## P4. SQLite, FTS5 and tree-sitter-elixir

`evidence/probe-main.rs` → `evidence/probe-main-output.txt`: bundled SQLite 3.53.2; FTS5 with both `unicode61` and
`trigram` tokenizers; a raw user term containing `.` is an FTS5 syntax error unless quoted as a string
(`"ogen.Bu"`), so every user term must be quoted. tree-sitter 0.27 + tree-sitter-elixir 0.3.5 parse the fixture with
no errors; a query captures `defmodule`/`def`/`defp` heads (including a `when` guard head) and `Alias.fun` calls.

`evidence/tree-sitter-sexp.txt`: node shapes the extraction rules rely on (fixture files in `evidence/fixture/`):
`alias Shop.{Pricing, Tax}` = `(arguments (dot left: (alias) right: (tuple (alias) (alias))))`;
`alias X, as: Y` = `(arguments (alias) (keywords (pair key: (keyword) value: (alias))))`; a default argument is
`(binary_operator left: (identifier) right: …)`; pipes are nested `binary_operator`s whose right operand is the call;
`&Shop.Tax.add/1` = `(unary_operator operand: (binary_operator left: (call target: (dot left: (alias) right:
(identifier))) right: (integer)))`; `__MODULE__.total(a)` = `(call target: (dot left: (identifier) …))`; a nested
`defmodule Rules` is an ordinary `defmodule` call inside the outer `do_block`.

`evidence/fts5-bm25-probe.rs` → `evidence/fts5-bm25-probe.txt`: the search fixture's nine chunks in a one-column FTS5
table (`body`, default tokenizer). `the` ranks INTENT.md:9, scenarios.yaml:1, INTENT.md:5 (bm25 order, not
path/line order); `Mix lock` → INTENT.md:5, memory; `rework` → INTENT.md:1, memory (no stemming: `reworked` and
`reworks` do not match); `guard"passes` → the phrase at INTENT.md:9 only.

## P5. Verification wiring (code read at f1d176b0)

- Proof selectors must be ExUnit files: `Kogen.Build.VerificationPlan` (`valid_selector?/4`) accepts `test/**_test.exs`,
  test directories, `scripts/check/rehearsals.exs`, `scripts/check/offline.py`, rehearsal ids and root `*.txt`
  fixture artifacts. A `cargo test` target could not be a proof selector.
- The catalog is not byte-frozen (`Kogen.Build.CatalogChange` moduledoc); a new target would need a Makefile target, a
  catalog entry, `catalog_changes.add` in intent.yaml and a `verified_by` entry on every scenario.
- `make check` runs `scripts/check/offline.py`, whose `main/0` builds phases `[[elixir --version]]`,
  preparation `[mix format --check-formatted, mix compile --warnings-as-errors --force, xcrun clang …]` (run
  concurrently), `[TEST_COMPILE_STAGE]`, credo + full `mix test`, then `rehearsals.exs`. No test pins that phase
  list (`test/kogen/offline_stage_results_test.exs` pins `STAGES`' test command, `TEST_COMPILE_STAGE`,
  `run_ordered/4` with a fixture plan, and `_stage_name/1` for mix commands).
- `priv/kogen/test-reliability.yaml` binds rows by test name (scripts/check/README.md, last paragraph; validated by
  `test/kogen/test_reliability_catalog_test.exs` through `Kogen.TestReliabilityCatalog.validate/3`): a new test needs no
  row, and no existing cataloged test is renamed here.

## P9. Apple `/usr/bin/git` launcher cost

`git rev-parse --show-toplevel`, 30 calls each: `/usr/bin/git` 13.8 ms/call, the resolved
`/Library/Developer/CommandLineTools/usr/bin/git` 5.9 ms/call (≈ 8 ms launcher overhead per call). With
`PATH=/usr/bin:/bin`, every `kogen-ctx` run pays it 2–3 times (`rev-parse`, `ls-files`, `hash-object`): about 70 runs
≈ 1.5–2 s over the three test files, serial within each module.
