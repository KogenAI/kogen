**Bottom line.** The three cycle failures are not three independent bugs. Two are one design contradiction: the controller now keeps verification state in the control checkout, but the Reviewer citation validator and the evidence consumers still assume one root. The third, the terminal probe, is unattributed because the test discards the probe message. The connected owner is predicted to fail at seed admission if it is ever reached.

## Findings, prioritized

1. **Reviewer citation root contradiction, cycle 3.** Category (b) plus a small (a). The Stop hook writes the attempt state under the control tracking directory via the absolute context path (`lib/kogen/build/verification.ex:30-44`, hook `load_context` at `.codex/hooks/stop_runner.py:31-46`). The controller then advertises that file in the record as a path relative to the control root (`lib/kogen/build.ex:540`, same for the context at line 292). The Reviewer copied that advertised string verbatim, as `reviewer-verdict-33239-9.json` evidence[3] shows. The validator resolves relative citations against the Candidate root and admits exactly one absolute path, the tracking record (`lib/kogen/build.ex:678`, `lib/kogen/build/contract.ex:609-612` and `624-643`). So the controller's own locator is uncitable. No cleanup was involved; the file existed in control the whole time. Scenario `exact-candidate-routing` already says tracking paths are "controller-owned absolute paths", so storing relative paths violates it, but the contract never says which controller-owned artifacts a role may cite or how. The offline fakes only ever cite the tracking record itself (`test/support/scenario_lifecycle_harness.py:164-166, 189-191`), which is the one allowed absolute path, so `check` cannot see this. Cycle 1's nested Reviewer simply did not cite the state file, which is why it accepted; the defect is Reviewer-behavior dependent.

2. **Summary locator became absolute; one consumer repaired, its twin not.** Category (b). The build summary now stores the absolute tracking path (`lib/kogen/build.ex:1185-1188`) because the record path is expanded at creation (`lib/kogen/build/tracking.ex:329`), and the committed evidence text now embeds a host path (`lib/kogen/build.ex:1004`). README still says the record resolves "from the checkout root." The rework fixture was normalized (`test/support/live_reviewer_rework_fixture.ex:215-218`). The connected owner's copy is unchanged and would raise the same KeyError (`test/kogen/live_shape_to_build_test.exs:596-602`). Recommendation: restore a control-root-relative locator, since publication syncs control to the commit and the relative path stays valid there; that avoids committing host paths and needs no consumer change. Either way the unrepaired consumer must be fixed before paid work.

3. **Seed-link policy still blanket-rejects, and the fixture hides it by dereferencing.** Category (b), and the strongest "passes checks, misses the outcome" case. `walk/2` raises on every symlink (`lib/kogen/build/workspace.ex:388-389`); the superseded test still asserts that (`test/kogen/build_workspace_test.exs:77`). The nested rework Build only passed admission because the shared fixture helper copies seeds with `cp -cRL`, dereferencing every link (`test/support/compiled_fixture.exs:64`), used by both the rework fixture and the offline lifecycle. The Intent explicitly forbids that. The connected owner never calls that helper; its `_build` comes from a real precompile (`test/kogen/live_shape_to_build_test.exs:117, 435`), which carries the ordinary Mix `priv` link. Prediction: live-shape-to-build fails at "unsafe warm seed symlink" after paying for Shape. Confirm with a five-second probe: list the link in a fresh MIX_BUILD_PATH compile of this repo.

4. **Contract-mandated test work was never done and cannot be detected.** Category (a), enforcement gap. Cycle 1's Candidate id equals the checkpoint tree named in `evidence/reuse-reconciliation.md:20-21`, so Stop ran on an unmodified import. Still missing: the fresh-child standalone owner loader (`test/kogen/live_rework_audit_test.exs` only requires the audit helper), real clone and incremental controls (`test/kogen/workspace_dependency_test.exs:5-26` is a hard-coded map), a publication control that requires success (`test/kogen/commit_failure_rollback_test.exs:84-92` accepts either branch), and contained-link admission. The catalog generator auto-registers whatever declarations exist (`scripts/check/generate_test_reliability.py:100-133`), so it cannot require a missing one. The rehearsal bound to live-reviewer-rework is an unrelated test (`priv/kogen/verification_targets.yaml:81-83`), so "fail before paid" never exercised fixture preparation or retention.

5. **Guard check masks an exhausted verification; installing collision.** Category (c) for the installing controller and (b) for the Candidate, since both share the order. The post-turn guard runs before settlement (`lib/kogen/build.ex:419-421`). The outer record therefore names only the Draft paths and holds no cycles, candidate id, or receipts; the state file alone shows three exhausted cycles. The ignored-file manifest includes `.kogen/intents/drafts/**` because the volatile list omits it (`lib/kogen/build/guarded_paths.ex:4, 150-152`). In the future Candidate route the worktree has no Drafts, so this cannot recur there; for the installing run it recurs whenever anyone shapes in the invoking checkout.

6. **Terminal probe failure is unattributable.** Category (d). The test discards the probe's stderr and asserts only the status (`test/kogen/terminal_probe_test.exs:71, 91`). Every probe failure exits 1 (`test/support/terminal_probe.py:211-213`), including both two-second default deadlines at lines 26-27. Bounded probe: run that one file repeatedly under the same twelve-way load with the message captured. That file is outside the guard list, so a Developer cannot even add the message to the assertion.

7. **Other prescribed requirements not met.** The journal is written (`lib/kogen/git.ex:137-149`) but nothing in lib reads it, so journal-proven post-ref recovery and matching-journal lock takeover do not exist. The lock is an empty exclusive file (`lib/kogen/build.ex:160-172`), not identity-bearing. Clone admission is a bare `cp -cR` with no filesystem or free-space preflight (`lib/kogen/build/workspace.ex:344`); the claim that this flag is clone-or-fail rests on `evidence/apfs-clone-probe.md:5` with no evidence, and macOS cp is widely documented to fall back to a plain copy. That is a (d) item: probe `cp -c` onto a small HFS+ disk image. Snapshot locators keyed on Candidate paths are retained but never rewritten after retirement.

- **Citation roots.** Add to `exact-candidate-routing.then`: every locator the controller writes into the record for a controller-owned artifact is absolute, and the validator admits a role citation only if it equals one of those advertised locators or resolves inside the physical Candidate. Control: a fake Developer and fake Reviewer that cite the advertised verification state and context paths verbatim and are accepted, plus a Candidate-relative citation of a control-only file that is rejected. Owner: `check`, in the scenario-tracking or reviewer-mutation tests.
- **Summary locator.** State in `atomic-main-publication.then` that the summary and evidence locator is relative to the control checkout root. Control: an offline lifecycle assertion that the committed summary path is relative and resolves from control after publication, and that both live retention helpers accept it. Owner: `check`.
- **Required declarations.** Add a maintained list of exact test declaration names per proof file that the catalog test must find present, and a forbidden list containing the superseded blanket-rejection name. Control: catalog validation fails when a required name is absent or a forbidden one remains. Owner: `check`. This is the only offline control that would have failed cycle 1 before any paid target.
- **Fixture preparation.** Require the shared preparation entrypoint to preserve symlinks and to be the one used by both live owners; forbid the dereferencing flag by an explicit control that plants a contained relative link in a seed and asserts it survives as a link. Rebind the live-reviewer-rework rehearsal to the standalone owner loader so it runs inside `check`. Owner: `check`.
- **Retention rehearsal.** Extend the standalone owner control past the dispatch boundary: feed it a synthetic Complete summary with absolute and relative locators and assert retention succeeds, since cycle 1 failed after the paid Build completed. Owner: `check`.
- **Failure precedence.** Add to `failure-preservation-cleanup.then`: when a guard violation and settled verification coexist, the record retains the settlement receipts and names verification exhaustion as primary. Control: a fake run that trips both. Owner: `check`.
- **Clone preflight.** Require a direct clone-capability check on the actual destination filesystem before cloning, with a control that presents a non-clone-capable destination and expects refusal. Owner: `check`, after the bounded cp probe settles what the flag does.
- **Journal and lock.** Either implement the journal reader and identity-bearing lock the scenario already requires, with fault-injection controls, or narrow the scenario text. The former is the contract as written.
