1. **Blocking — Build input is in the wrong lifecycle state** (`all`). `intent.yaml:4` says `approved`, but the package is under `drafts/`; the quality bar requires Drafts to remain `status: draft` (`priv/kogen/prompts/shaping.md:136-145`). `mix kogen.build` reads only `.kogen/intents/approved/<slug>` (`lib/mix/tasks/kogen.build.ex:7-10`, `lib/kogen/build.ex:59-61`), and that directory is absent. **Fix:** move the approved package into `approved/` through the narrow approval bookkeeping, or keep it Draft and do not run this Build.

2. **Blocking — Appetite and build-order contradictions** (`all`). The risk admits this is probably larger than one Build and 30+ files/4–6k lines (`risks.yaml:88-99`), violating the one-Build bar (`shaping.md:19-31`). Current order is simultaneously “fourth, after shaping-preflight-audit” (`intent.yaml:11-14`, `INTENT.md:13-17`) and “third because shaping-preflight-audit is parked” (`INTENT.md:32-43`). The accepted-scope text also includes the Codex retry, then says it moved to the earlier Intent (`INTENT.md:258-274`). **Fix:** split the work or record one explicit Shaper decision; remove stale order/scope claims.

3. **Blocking — Invalid focused selector** (`stop-route-bootstrap-only`). `scenarios.yaml:281-286` lists `scripts/check/rehearsals.exs` as an offline selector. Non-catalog selectors are converted to `mix test <selector>` (`lib/kogen/build/verification_plan.ex:318-322`), while this script is actually run with `mix run` by `check` (`scripts/check/offline.py:292-295`). Several other selectors are absent at HEAD and only “planned” through `affected_paths`: `controller_verification_test.exs`, `verification_reuse_test.exs`, `catalog_change_test.exs`, `proof_selector_verification_test.exs`, `verification_surface_ledger_test.exs`, and `readme_guidance_test.exs` (`scenarios.yaml:71-72,116-118,159-160,389-393,452-455,525-527,607-609,721-723`). **Fix:** replace the script with an existing test or catalog rehearsal id; require every planned selector to exist before handoff.

4. **Blocking — The Intent does not prove its own integrity features** (`all 13 scenarios`). It explicitly says this Build’s contract uses none of the new contract features (`INTENT.md:45-50`), while red-on-base is only described for later fixture contracts (`scenarios.yaml:471-506`). HEAD’s contract validator still accepts only the four proof keys (`lib/kogen/build/contract.ex:195-201`). A plausible wrong implementation can therefore pass the named proofs by leaving Stop verification, rerunning all targets, omitting the ledger, keeping catalog freeze, or weakening each newly added test; the Developer controls those proof files and no base comparison protects this package. **Fix:** bootstrap the integrity mechanism in an earlier Build, or narrow this Intent and add immutable base/rehearsal proof before claiming these outcomes.

5. **Blocking — Dynamic ledger schema conflicts with the outer Build’s Codex Reviewer** (`verification-surface-ledger`). The scenario requires per-launch `ledger` schema and exact-key validation (`scenarios.yaml:568-584`), but main’s Codex adapter always writes the static `Verdict.schema()` to `--output-schema` (`lib/kogen/harness/codex.ex:61-70`), whose exact keys exclude `ledger` (`lib/kogen/harness/verdict.ex:22-86`); the outer Build calls that adapter from main (`lib/kogen/build.ex:744-750`). **Fix:** add an explicit outer-build/no-ledger compatibility proof and preserve the old schema for this Build, or ship the schema transport in an earlier bootstrap Build.

6. **Blocking — Required lifecycle ownership is missing** (`shape-to-build-retains-record-sidecars`, `controller-runs-proof-selectors`, `verification-surface-ledger`). The shaping contract requires ownership metadata for generated/retained files (`shaping.md:190-202`), but `risks.yaml` has no `ownership` entries. The Intent creates retained tracking trees, sidecars, review packets, verification logs, base workspaces and ledger diffs (`scenarios.yaml:751-758`, `484-500`, `557-563`). **Fix:** add scalar ownership records covering creation, runtime owner, permitted mutation, validation, Git state and upgrade behavior.

7. **Blocking — Isolated-workspace `priv/` and Mix-cache behavior is unproven** (`controller-runs-proof-selectors`, `verification-surface-ledger`). Runtime prompt rendering reads relative `priv/kogen/prompts/*` (`lib/kogen/build.ex:1576-1590,1618-1625`). The base workspace requirement only says “git archive plus base_cache” (`scenarios.yaml:484-493`), and the risk admits copied Mix caches were not verified (`risks.yaml:75-87`). **Fix:** add a fixture proving prompts and all runtime `priv/` reads resolve inside the isolated workspace, with an explicit isolated `MIX_BUILD_PATH`; reject fallback to the parent checkout/application path.

8. **Blocking — New plumbing has no caller-to-proof map** (`controller-owns-verification`, `controller-runs-proof-selectors`, `verification-surface-ledger`, `shape-to-build-retains-record-sidecars`). 9. **Advisory — Live fixture wiring is described but not asserted per target** (`controller-owns-verification`, `stop-free-compatibility-fixture`, `shape-to-build-retains-record-sidecars`). The package correctly distinguishes outer hybrid Reviewer Codex from nested default-route Claude (`risks.yaml:113-129`; `INTENT.md:40-50`), and both edited live owners have selected targets. However, the package does not state an acceptance check for each target’s route, profile, login and preflight. HEAD’s Codex-only owner resolves the explicit Codex route (`test/support/route_config.ex:64-91`), while `.kogen/config.yaml` defaults to Claude (`.kogen/config.yaml:1-2`). **Fix:** require paid evidence for nested Shape-to-Build on default Claude and compatibility on the explicit Codex route, including login and preflight receipts.

10. **Advisory — Current-count and reference drift** (`all`). `approval.md:39` and `risks.yaml:91` say 12 scenarios, while the package has 13 (`INTENT.md:38-40`, `approval.md:128`). `references.yaml:17-20` points to a user-home path outside the checkout. **Fix:** normalize the count and use a repository-relative or committed reference.

The Build is not ready: it cannot be admitted from `drafts/`, contains a bad selector, exceeds the one-Build appetite, lacks ownership/caller traces, and claims integrity behavior that this self-hosted Build cannot actually prove under main’s frozen catalog, Stop path and static Codex verdict schema.
