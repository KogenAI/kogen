# Shared execution and delegation obligations

This file owns only the obligations transferred into this slice. Implement them in one concise maintained source under `priv/kogen/prompts/`, expanded once through each initial role route. A shared renderer may live at `lib/kogen/execution_policy.ex`; preserve Boundary enforcement. Keep profile values in `.kogen/config.yaml`, render them from that source, and keep role authority/output contracts in their role templates. Do not embed the historical combined policy wholesale.

Optimize the complete correct task, including preparation, startup, cache/context transfer, coordination, verification and repair. Keep short or tightly coupled work local. Batch independent tools. Delegate bounded independent work when a small sufficient packet and compact return replace root work or enable useful concurrency. Reuse relevant helpers for follow-ups. A coordinating helper is justified only by a coherent independent investigation. No mandatory fanout, quota or automatic escalation chain.

Use explicit configured model/effort with supported native kinds: scout uses explorer, worker uses worker, expert uses default. Do not inherit root profiles or substitute unavailable profiles. Surface native failures. Native metadata, not model self-identification, establishes executed identity.

Packets contain the objective, necessary facts, constraints, allowed operations or exclusive write ownership, interfaces, expected evidence and stopping conditions. Prefer fresh/minimal context. Helpers share the workspace and preserve other work. Roots do useful independent work while children run. Require concise conclusions, source locators, observed evidence, uncertainty and failures; integrate without repeating bulk investigation. Verify consequential contradictions and questionable citations against actual source bytes. Never reconstruct prose and present it as an exact quote.

Helpers remain advisory. Shaping retains human product/UX decisions and explicit same-conversation Intent approval; its helpers do not author the final Draft or approve it. Developer owns implementation and handoff, delegates only within approved paths, and propagates gate restrictions. Reviewer and all its children preserve the Candidate; Reviewer retains independent judgment, resolves all helper work before its verdict, and emits the final schema-valid verdict itself. Shared text must not grant a read-only role write permissions.

Preserve concise observed facts, decisions, rejected approaches and provenance, never private chain-of-thought. Distinguish invalid experiments from valid failures; retain corrections and failures, with no automatic rerun-to-success. When reporting measurements, include root/helper work, treat cached input as a subset and exact-session usage as deltas where available; missing usage is not zero. Unit prices or raw tokens do not establish complete-task savings. This is reporting discipline, not a new accounting subsystem.

Carry authorized work to each role's existing completion conditions. Status questions steer ongoing work; they do not end it. Preserve approval boundaries, gate ownership, same-Developer rework, fresh Review, output schemas and attempt limits. This slice does not change task-file transport, introduce new shaping-quality obligations, alter editing tools, or add production timing limits.
