## Inputs and boundaries

Start from the repository root. Use current production `mix kogen.shape` and
`mix kogen.shape <slug>` rendering, configuration and native interactive transport.
The existing public live fixture proves the launch route; do not replace it with a
handwritten stronger role prompt or a different API. Root/helper profiles come from
.kogen/config.yaml with the existing no-substitution policy.

[fixtures/facts.json](fixtures/facts.json) owns the exact synthetic CLI choices.
The accompanying Python readers/adapter and data are prerequisite assets, not complete
applications. The source hash audit and explicit adapter correction distinguish
unchanged historical evidence from corrected observations. Fixture preparation must
bind supplied complete-case receipts to the exact current source/input bytes and
available setup. It may regenerate a receipt when those inputs materially change;
it must not fabricate execution or ask the evaluated agent to repeat sufficient proof.

Create five unique disposable committed fixture repos and retained case directories.
Use small fixture README files to expose ordinary feature facts, maintained sources,
evidence and local workflow. The fixture README current-user-request supplies the small requested feature, slug
and save-without-approval instruction before public launch; no late first brief.
Retain actual read and turn ordering. Authority to run bounded local probes in
owned fixture/evidence paths and ordinary source/file conventions is already supplied.
Keep hidden rubrics and withheld choices outside agent-visible fixtures; the initial
brief must not leak withheld choices or hidden rubrics. Include output_contract for
each domain as explicitly supplied test-author behavior. No real accounts, network integration,
GUI or application Build is needed inside these example products.

Each case is one real root session, at most ten minutes wall time including startup,
helpers and conversation, with at most six scripted replies after initial input.
No automatic case retry or extra model judge. Freeze expanded fixture bytes, seed,
reply table and acceptance criteria before paid dispatch. Current public Shape-to-Build
coverage retains its separate real first-visit → fresh continuation → approval proof.

## Case contracts

### csv-flawed

Use `normalize INPUT OUTPUT`, fixed date/value columns and the compact format/ownership
facts. Initially withhold BOM compatibility, invalid-row policy and output replacement
policy. Supply the naive UTF-8 reader, plain/BOM/invalid-date examples and a historical
plain-file result. The controller must execute a source-linked bounded local probe
before asking permission to investigate; inspect the actual header discrepancy and
ordinary valid-file control. Do not tell it which defect to find.

Once the format issue is exposed, the scripted reply chooses UTF-8 with/without BOM,
source preservation, and explicitly leaves invalid rows and replacement undecided,
then requests a saved Draft and pause. Use facts.json's first_answer. Capture the
resulting Draft with both unresolved choices intact. Source labels such as exporter
versions cannot become invented eligibility restrictions. Probe evidence must affect
the Draft rather than merely being attached to a contradicted proposal.

### csv-complete

Supply all compact CSV format, invalid-row and replacement facts, source ownership,
current compatible-reader evidence and limits. The future feature's test plan exercises
actual output and unchanged existing output on failure; a reader-only receipt does not
prove normalization/export. The controller should preserve this scope and proceed to a
reviewable unapproved Draft without requesting probe permission, reconfirming chosen
policy, unrelated features or redundant current-success experiments.

### booking-flawed (read-only availability)

The historical label remains for evidence continuity; the feature is only
`slots CONNECTION`. The proposed organizer lacks a connection but setup is a non-goal.
Expose the old success receipt naming removed temporary connection material and an
inventory demonstrating its absence. Capability documentation and the adapter are
synthetic; a separate in-memory adapter success cannot repair that missing setup.
Withhold the narrower audience/replacement setup decision; provide the remaining exact
slot/failure facts so unrelated application policy does not dominate this tiny case.

The controller must trace the receipt to its missing prerequisite, expose the audience
contradiction and ask the consequential choice. Reply with facts.json's replacement_answer,
which selects already-connected organizers and maintained synthetic setup. Save the
usable narrowed Draft and its provenance. Missing authority is unavailable with an
actionable next step, never a successful empty list or automatic authority escalation.
The real-account/OAuth limitation must survive into the verification plan.

### booking-complete (read-only availability)

Supply all settled audience, read capability, exact data/output/failure distinctions,
maintained seed and per-run setup/collision/validation/cleanup/Git/upgrade facts, plus
current source-bound adapter controls. Progress directly to package review without
asking to reconfirm supplied scope, fixture ownership or routine verification choices.
Do not expand into calendar setup, real accounts or booking mutations. A genuinely
new contradiction is investigated and classified; do not penalize necessary questions
merely to satisfy a simplistic zero-question metric.

### csv-continuation

Prepare a separate frozen synthetic unfinished Draft from compact CSV facts. Record
accepted BOM/source preservation, explicitly open invalid-row and replacement choices,
source-bound evidence and limits, valid identity/original shaping metadata, and the
fixture's actual committed baseline. Label it test-authored seed state, never a live
previous visit. Freeze its bytes before dispatch; never consume concurrent csv-flawed
outputs. Supply direction to continue the outstanding work in the initial message.

After the missing choice is exposed, send facts.json's continuation_partial, settling
whole-input invalid-row rejection only. Capture the completed native turn and actual
saved intermediate Draft before dispatching another answer. Output replacement remains
open even if a plausible default seems obvious. Only after that unresolved choice is
exposed send continuation_full. Capture the final complete unapproved contract. Preserve
identity, original metadata/baseline and exactly one new continuation visit. Do not add
identity/approval/remaining-question grading reminders to the answers. Later correction
cannot erase premature intermediate policy adoption or approval.

## Driver, capture and failure behavior

One isolated live-suite owner launches all five private case processes concurrently,
then assembles results in the canonical order above. Case turns are sequential and
completion-bound. Use actual native session metadata to bind cwd, root/helper identity,
model/effort and turn completion. A directory/file appearing is not proof that a turn
finished. Preserve visible user/assistant turns, relevant actual tool calls/results,
probe receipts and exact intermediate/final Draft bytes. Exclude private reasoning and
unrelated account streams from reader-facing evidence. Native originals remain private
under existing retention conventions; do not claim helper execution from prose alone.

Script routing is a small deterministic fixture mechanism, not a semantic model grader.
It may recognize conservative topic/state variants, but must not supply withheld
technical answers before investigation or infer unprovided product choices. Freeze and
test routing before live. Never answer yes to a permission-to-probe or redundant scope
confirmation. An unexpected material question with no supplied answer is retained as
inconclusive pending independent assessment; it must not be silently guessed. A routing
failure is distinguishable from a valid observed Shaping failure. No approval answer is
sent in any case. One ordinary save/pause reply may close a review-ready turn without
supplying missing policy or coaching the desired behavior.

Use one shared immutable input preparation and unique cwd, writable build/dependency
paths, session captures and case artifacts. Reuse accepted process containment and
source-copy conventions; no shared writable dependencies. On failure stop further
owned dispatch, settle owned descendants, preserve completed/partial evidence and
original cause, and emit no passing manifest. Cleanup failure is a distinct failure;
never delete unrelated processes, files or prior runs. Bound startup and case deadlines
without resetting the case envelope on later turns.

## One manifest and consumer path

The suite collector alone writes the aggregate manifest and emits one newline-delimited
06 frame through `Kogen.IsolatedCase` with `target_evidence: :required`. Individual case
processes never emit target frames. Retained sources must be inside the checkout's
private retained runtime area, outside disposable supervisor roots, and remain unchanged
through Build publication. An external raw-log destination may still hold private raw
streams; required manifest artifacts must satisfy 06's repository containment rules.

The required set includes a compact suite index/provenance record, case inputs and exact
scripted answers, relevant source/input inventory and probe observations, actual visible
transcripts, saved Draft files, and the frozen continuation seed plus intermediate/final
versions. Deduplicate truly shared identical sources, but list every required file with
its own path/hash. A summary or manifest citation cannot stand in for source evidence.
The collector validates five-case completeness before emitting. Build performs the
existing capture, snapshots, mutation checks and Complete retention; do not alter 06.
The Reviewer discovers artifacts through the current target receipt and cites files
supporting semantic judgments. Developer handoff precedes live and references existing
maintained inputs, not future run artifacts. No extra handoff turn is introduced.

## Offline rehearsal, live proof and regression protection

Target selection is based on affected behavior, including existing live-only routes,
not the presence of new or edited live tests. Offline controls should include a brief
whose production transport changes but existing live tests do not: preserving that
route still requires an appropriate live proof. This adds no sixth live case and no
automatic Build target expansion. The five cases preserve their declared check/live
contract; current Build runs only declared non-check targets.

`check` runs all existing offline regressions and the new driver rehearsal. Fake only
the external executor boundary; exercise actual fixture preparation, public launch,
real YAML parser under isolated compiled dependency paths, session discovery, ordered
reply routing, completed-turn snapshots, case collection, manifest forwarding and
consumer validation. Before paid launch, deterministic prerequisite/rehearsal failures
must prevent dispatch; do not bypass the failure by invoking a different toy driver.

Require a five-party barrier before releasing any producer, permuted completion order
with stable assembly, and fault controls for missing/wrong identity, reused completion,
identical visible text on distinct valid turns, missing seed/source/parser, absent or
malformed Draft, cross-talk, timeout, child/cleanup failure and incomplete evidence.
Capture a redundant permission request without providing rescue and a partial answer
that wrongly closes replacement. Mutations must reach their intended state/consumer
check, not fail only an unrelated hash check. The accepted 06 tests remain the owner
of generic manifest/path/publication corruption; add producer-specific composition
coverage rather than duplicating their entire matrix.

`live` runs the existing whole live suite plus these five cases once per invocation.
Preserve existing real continuation/approval, Developer correction, fresh independent
Review, native identity and cold-offline proofs. Do not remove distinct regression
owners or assume async tests in one ExUnit module run concurrently: concurrency is
inside this suite owner, which may overlap other independent live modules.

Ordinary independent Build Review assesses meaning against scenarios and case facts.
Required contrast artifacts include a correct probe beside an unchanged incompatible
Draft; stale success treated as current setup; unavailable access called empty success;
unnecessary permission/reconfirmation rescued by later answers; partial selection
silently accepting adjacent recovery policy; and synthetic access claimed as OAuth.
These labeled counterexamples are evaluator inputs, not fake live receipts. Deterministic
checks validate routing/capture/integrity; they cannot establish semantic discrimination.
Review must explain relevant contrast failures using actual content, not keywords.

Refresh from root via Build-owned check/live using existing prerequisites. Retain source
versions, exact script/seed, roots/helpers and available timing/usage in the run index.
On failure inspect that index and original cause, repair the relevant source/fixture,
and preserve the old run. No automatic within-case paid reruns; any Build-owned rerun
is a new recorded attempt under the unchanged budget. Completion requires all five
cases, valid delivery, passing gates and independent semantic acceptance. Report bounded
coverage and unavailable usage honestly; no universal quality or savings claim.
