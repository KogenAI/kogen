1. **Blocking — proof selectors do not exist.** `scenarios.yaml` names `test/kogen/review_packet_test.exs` and `test/kogen/superseded_objection_test.exs` (scenarios.yaml:32, 86), but both files are absent. Shaping requires maintained, repository-relative selectors (shaping.md:176-181). **Fix:** replace them with existing focused tests or add the tests to the Draft’s guarded and ledger-covered scope.

2. **Blocking — the test-reliability ledger is not in the proof/affected-path contract.** The Draft edits cataloged tests but its scenario `affected_paths` omit `priv/kogen/test-reliability.yaml`; the repository requires refreshing that ledger after such edits (INTENT.md:120-125; scripts/check/README.md:166-170). The prior Build demonstrably failed at 747/749 tests for stale hashes (build-failure-2026-09-24.md:8-14). **Fix:** include the ledger and refresh command in affected paths, acceptance evidence, and guarded-path coverage.

3. **Blocking — self-reference handling is underspecified against existing readers and writers.** Current retention always writes inline `content_base64` (build.ex:931-949), `Tracking.verify_reference/3` validates the live record rather than a sidecar (tracking.ex:77-103), and publication writes committed summaries/evidence separately (build.ex:1052-1083). The Draft asserts sidecars and legacy resolution but does not name every writer/reader or publication test that must preserve both formats. **Fix:** specify the sidecar schema, creation/immutability checks, `Evidence.resolve/2` compatibility, `Tracking.verify_reference/3` behavior, committed summary compatibility, and tests for each path.

4. **Blocking — packet integrity is not actually proven at the live boundary.** The scenario requires mutation-after-launch detection and packet binding (scenarios.yaml:25-30), but the listed live audit only checks retained files and raw-stream references. A wrong implementation could rebuild or replace the packet after launch while leaving the prompt text and size assertions unchanged. **Fix:** retain and verify the packet digest/attempt token/Candidate before launch and after Review, and make the live audit fail on any mismatch.

5. **Blocking — Codex limit proof is insufficient for the changed production path.** The only evidence is a probe that the CLI accepts the key (codex-output-limit-probe.md:4-17); the scenario has no paid target (scenarios.yaml:37-53), while the next Intent is treated as future proof. Offline argument tests can pass even if the setting is attached to the wrong launch or omitted by a helper. **Fix:** add a narrow native target, or narrow the claim to argument construction and explicitly remove “every real Codex role/helper” from this Intent’s acceptance.

6. **Blocking — the superseded-objection rule is not fully constrained by controller state.** Main currently stops on any Jev objection before Review (build.ex:403-420). The Draft’s replacement rule says “earlier failed cycle of the same attempt” but does not require the failed and passing cycles to share the same attempt token, Candidate, and verification chronology. A broad implementation could suppress a genuine objection after an unrelated failure. **Fix:** require exact token/Candidate continuity and test: same-attempt failed→passed; passed-only; exhausted; and failed cycle from another attempt.

7. **Blocking — fixture relocation can break managed runtime trust/login.** The fixture currently uses a checkout-relative root (live_reviewer_rework_fixture.ex:48-61). Codex configuration trusts and keys projects by the exact `project_root` path (codex/environment.ex:407-426), while the fixture also rsyncs, copies dependencies, and precompiles before launch (live_reviewer_rework_fixture.ex:140-187). Moving it outside the checkout without an explicit canonicalization and scope assertion can select the wrong login or fail trust. **Fix:** create the directory, resolve it with `realpath`, pass that exact path through launch context, and audit effective scope/trust before provider dispatch.

8. **Advisory — the live run has no demonstrated time margin.** The fixed ExUnit timeout is 1,200,000 ms (live_reviewer_rework_test.exs:13-18); prior Codex reviews reached roughly 5 and 16 minutes and one run timed out (reviewer-context-diagnosis-2026-09-25.md:8-19). A 4,000-token output cap does not bound command count or model time. **Fix:** add a deterministic offline packet-size/command-shape rehearsal and retain per-review elapsed evidence; do not raise the timeout or lower effort.

9. **Advisory — scope exceeds one bounded change.** The Draft combines recursive-record storage, a new review-packet protocol, global Codex transport configuration, fixture relocation, and settlement semantics (INTENT.md:42-80). These are separate controller, harness, fixture, and outcome changes, increasing self-hosting and regression risk. **Fix:** split objection settlement or Codex transport into separate Intents, or explicitly justify them as inseparable acceptance prerequisites.

10. **Advisory — planted-defect controls do not prove unchanged strength.** The Draft relies on existing offline controls (INTENT.md:84-89), but a packet implementation could satisfy them with fake Reviewer inputs while omitting real Candidate inspection. **Fix:** add a negative control where the packet is correct but the Candidate defect remains, and assert the Reviewer path still detects it without weakening existing assertions.
