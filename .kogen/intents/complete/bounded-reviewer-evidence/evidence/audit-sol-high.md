1. **Blocking — self-hosting makes the controller scenarios unprovable in this Build.** The Draft says new code takes effect only on the next Build (`INTENT.md:120-123`), while `mix kogen.build` invokes the already-loaded `Kogen.Build` module (`lib/mix/tasks/kogen.build.ex:32-35`). Thus this Build’s parent controller will still self-embed records, omit packets, and stop superseded objections; only the child live fixture loads the new code. **Fix:** split this into a bootstrap Build plus a subsequent Build that exercises the new controller, or explicitly remove these as current-Build acceptance claims.

2. **Blocking — approval state is contradictory and Build-ineligible.** The package remains under `drafts/` and has `status: draft` (`intent.yaml:1-4`), but `approval.md` claims approval carried from an external driver (`approval.md:3-17`). Build reads only `.kogen/intents/approved/<slug>` (`lib/kogen/build.ex:50-53`), and shaping requires same-conversation approval followed by moving the directory (`shaping.md:38-50`). **Fix:** keep it honestly draft, or perform the required approved-directory move and reconcile approval metadata before Build.

3. **Blocking — packet and sidecar mutation is not bound to controller integrity checks.** `bound_inputs_unchanged/3` checks Tracking, Approved bytes, references, Candidate, and Verification only (`lib/kogen/build.ex:806-819`); `.kogen/runtime` is explicitly volatile to guarded-path checks (`lib/kogen/build/guarded_paths.ex:4-5,39-66`). The Draft nevertheless requires packet and sidecar mutation to stop the Build (`scenarios.yaml:7,25-27`). **Fix:** store packet/sidecar paths, digests, byte counts, and attempt/Candidate bindings in controller state, then verify them before and after Review and throughout publication; add mutation controls through the real route.

4. **Blocking — the paid proof cannot establish packet-first Reviewer behavior.** The current context exposes `tracking_path` as the main evidence locator (`lib/kogen/build.ex:876-893`), and the current Reviewer prompt tells the model to read the raw record (`priv/kogen/prompts/reviewer.md:46-53`). Raw-stream persistence records provider output, not the input prompt (`lib/kogen/harness/codex.ex:313-340`; `lib/kogen/harness/claude.ex:399-433`), so “raw stream references packet path” can pass without the model reading the packet. **Fix:** retain the rendered Reviewer context and/or audit structured tool calls, requiring packet read before any record read and requiring Candidate inspection.

5. **Blocking — the 64 KiB packet contract is underspecified.** The scenario requires valid JSON, complete required sections, digests/locators for every omission, and a hard byte bound (`scenarios.yaml:19-35`), but defines no canonical serialization or truncation algorithm. A wrong implementation can byte-slice serialized JSON or silently discard findings while passing a size-only assertion. **Fix:** specify canonical encoding, bounded-field allocation, required keys, omission records, and tests that parse the packet and account for every omitted byte range.

6. **Blocking — sidecar evidence is not integrated with resolution or publication.** `Evidence.resolve/2` validates only the summary’s full record bytes (`lib/kogen/build/evidence.ex:10-23,68-80`); current publication checks Tracking, references, target evidence, and package entries (`lib/kogen/build.ex:1137-1165`). A sidecar can therefore be tampered with or lost while retained evidence still resolves. **Fix:** make sidecar validation part of `Tracking.verify_reference/3`, `Evidence.resolve/2`, and `publication_unchanged/2`, including legacy inline snapshots.

7. **Blocking — fixture cleanup loses artifacts required by the new contract.** The fixture preserves only verification history, `evidence.md`, record JSON, and summaries (`test/support/live_reviewer_rework_fixture.ex:190-223`), then removes the fixture (`:121`). It does not retain packet files, sidecars, or the complete package, although the Draft requires those retained artifacts (`scenarios.yaml:55-71`). **Fix:** copy the complete package, packets, sidecar tree, audits, and raw evidence to the log directory; rewrite relative locators and verify them after fixture deletion.

8. **Blocking — moving the fixture changes provider identity and may remove login.** Claude and Codex project selectors hash `Path.expand(project)` (`lib/kogen/claude_code.ex:161-181`; `lib/kogen/codex/state.ex:4-22`), while Codex trust is keyed to the exact project path (`lib/kogen/codex/environment.ex:407-412,417-426`). A temp fixture can therefore fall back to an unconfigured shared scope or lack the expected project trust. **Fix:** require and audit the selected shared/project scope for the canonical temp path before dispatch, or provision the matching scope; fail closed before spending a provider call. Also define realpath handling explicitly—Codex currently checks lexical expansion, not symlink resolution (`environment.ex:482-493`).

9. **Blocking — declared proof/affected paths omit required callers and ledger consumers.** The packet/self-reference changes affect `LiveReworkAudit` callers in both live owners (`test/kogen/live_shape_to_build_test.exs:475-476,557-558`; `test/support/live_rework_audit.ex:117-135,229-247`) and fake context consumers that read `tracking_path` (`test/support/scenario_response.py:25-37`; `test/support/scenario_lifecycle_harness.py:25-34`). Editing cataloged tests also requires refreshing the reliability ledger (`scripts/check/README.md:166-171`), whose catalog/remediation consumers are not listed in affected paths. **Fix:** add these callers, ledger consumers, and any needed `lib/kogen/build/guarded_paths.ex` change to the guarded/affected-path contract, or narrow the design so they need not change.

10. **Blocking — planted-defect selectors do not exercise the packet route.** `scenario_semantic_test.exs` validates response semantics only (`:14-75`); `reviewer_mutation_test.exs` and `two_outer_resumptions_test.exs` use fake harnesses. A packet could be omitted or could direct a real Reviewer away from Candidate files while all named proofs pass. **Fix:** add an offline controller lifecycle with a real packet and planted missing/incorrect Candidate file, plus a wrong control proving packet omission or Candidate avoidance fails.

11. **Blocking — superseded-objection proof does not isolate attempts.** Current `settle_outcome/7` blocks on any objection before considering verification (`lib/kogen/build.ex:403-420`). The Draft lists failed-then-passed, single-pass, and exhausted cases (`scenarios.yaml:73-89`) but no case where a prior *different* attempt failed and the current attempt passes first cycle. **Fix:** add that cross-attempt control, exact `cannot_comply` assertions, and an assertion that the superseded item appears in the packet.

12. **Advisory — Codex cap proof and paid-target selection do not match the claim.** The only paid target is default-route Claude (`INTENT.md:93-100`), while the Codex probe is mainly a personal CLI experiment and explicitly does not measure a whole Review (`evidence/codex-output-limit-probe.md:4-15`). **Fix:** narrow the scenario to deterministic launch-argument construction and directly test `Environment.prepare/6` for every role/helper; defer provider-effect claims to the Codex-owned Intent rather than adding a second paid target.

13. **Advisory — timing risk remains unproven for the Codex route.** The retained evidence reports a 240-second native-turn kill budget and Reviewer failures at roughly 219–237 seconds (`cross-harness-adversarial-roles/evidence/compatibility-diagnosis-2026-09-25.md:56-72`), while the live target remains under the fixed 1,200,000 ms ExUnit timeout (`test/kogen/live_reviewer_rework_test.exs:13-18`). **Fix:** make the live audit retain per-turn durations and fail on a bounded regression; do not raise the timeout or lower Reviewer effort.
