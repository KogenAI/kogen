## Important finding not in the table: defect (d) is NOT actually fixed at 7ed41f66

The Draft's `investigation.md`/`PROBES.md` state defect (d) — "the scope hash is not canonical" — "moved to `isolated-candidate-workspace`" as if that package would resolve it. At 7ed41f66:
- `Kogen.ClaudeCode.project_id/1` (lib/kogen/claude_code.ex:238) still does `:crypto.hash(:sha256, Path.expand(project))` — plain expand, no symlink resolution.
- `Kogen.Codex.State.project_id/1` (lib/kogen/codex/state.ex:7-8) is identical: `Path.expand(project)`, no realpath.
- `isolated-candidate-workspace` *does* add a `Kogen.Build.Workspace.canonical/1` helper (lib/kogen/build/workspace.ex:90-101, using `/bin/realpath`) and its own `project_id/1` (workspace.ex:48-50), but that is a **separate, workspace-directory-naming id**, distinct from the login-scope-key `project_id` functions above, which remain uncanonicalized.
- Net effect: the canonical-path scope-key defect (d) is still open at 7ed41f66. This Draft explicitly disclaims depending on it ("Both change ... which live-native owns. They move to isolated-candidate-workspace"), so no Draft edit is strictly required, but the Draft's evidence file overstates what landed; a corrective note in investigation.md/PROBES.md would be accurate but is not required functionally since the Draft's scenarios don't rely on the fix.
