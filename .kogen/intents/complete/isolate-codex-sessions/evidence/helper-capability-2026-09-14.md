# Helper-kind uncertainty resolved by native controls

See [reproduction and limitations](prototypes/helper-schema/README.md). Managed
Codex 0.154.0 executed actual explorer, worker and default spawn calls with
Luna-low, Luna-medium and Sol-medium respectively when standalone agent definitions
were loaded. The disconfirming unchanged-context run did not expose agent_type
according to its parent, and made no calls. A second successful control used only
an unrelated custom definition, preserving built-in kinds. Native metadata, not
parent prose, establishes executed child roles, profiles and completion.

This resolves whether the pinned runtime can meet the accepted kind requirement.
No product choice to remove kinds or change the pin is necessary. Existing inline
agents.<role>.config_file entries are insufficient in the tested managed context.
The Developer must load valid standalone definitions through Kogen-owned discovery,
retain built-in kind semantics, and verify the actual production placement and
native routing. Use meaningful Kogen helper definitions rather than shipping the
probe-only capability_marker. Do not place managed files in the user's source tree
merely because the probe used a temporary project. Treat managed definition files
as generated Kogen-owned settings under the existing settings lifecycle: validate
recognized existing bytes, refuse unrelated occupants, preserve credentials and
sessions, and prevent active-definition rewrites across overlapping operations.
Final placement, regeneration and concurrency remain integration proof obligations.

The user requested verification and then explicitly requested subagent assistance
and a finite remaining-proof inventory. The root executed the adaptive native
controls; the existing read-only scout supplied an inventory. Root source checks
rejected stale scout claims that the resume consumer still lacked role preservation
and that selected_session_root still unconditionally used shared scope. Those
repairs exist in current source; combined acceptance still belongs to Build.

No new shaping visit, approval, baseline change, source edit or Build restart.
