# Enforce structured Developer handoffs

## Outcome and appetite

One Build makes the ordinary fresh and resumed Build Developer handoff schema-constrained, then validates its meaning before independent Review. A passing application Check must not leave final-response formatting entirely to prompt compliance. Schema compliance does not establish truthful claims, complete unique coverage, safe citations, passing gates, or acceptance.

Use one Developer conversation with the configured two outer resumptions. Keep the existing JSON wire envelope and collections. Do not bundle gate relocation, verification counters, a new retry allowance, transport/parser recovery, authentication changes, CLI installation, stopped-Build continuation, or Reviewer schema redesign. The Shaper selected preservation of the existing correction budget in this conversation.

## Producer and consumer contract

For every real Build attempt, derive the schema from controller-owned current contract, attempt token and open findings, and pass it through an explicit internal interface to both fresh launch and exact-session resume. Do not scrape prompt prose or let the Developer supply the schema. No unconstrained fallback is permitted for a Build invocation when schema setup or provider support fails.

Preserve top-level keys `attempt_token`, `scenarios`, `risks`, `findings` and all current per-entry/reference keys. Require all object properties and prohibit extras. Constrain token to its current value, collection cardinalities to the current required counts, IDs to current allowed IDs when nonempty, status values to the documented wire enums, nonempty textual fields with supported minimum lengths, and reference arrays to at least one item. Zero required risks/findings means an empty array; do not generate invalid empty enums. Use the supported schema subset demonstrated in evidence. Array order is not a new requirement except existing risk-link order. Exact uniqueness/coverage, whitespace-only text, risk links, safe existing regular references, and the meaning of claims remain runtime/Review responsibilities. No tuple schema or unsupported uniqueness promise is required.

Keep `incomplete` scenario and `blocked` finding reporting available in the producer schema and instructions. The current consumer rejects those as unready; schema enforcement must not coerce a false `ready`/`addressed` claim. Keep `disputed` responses available for independent assessment.

The existing Contract.handoff authority still checks current binding, exactly one entry per scenario/risk/open finding, readiness, complete exact risk links, useful nonblank claims/responses/locators, nonempty references, traversal/NUL/absolute/symlink rejection, and existing regular-file paths. Build retains its reference snapshots and current Candidate/gate bindings. Review assesses substantive truth and dispositions; neither a schema nor a handoff may certify a gate.

On a successfully settled provider invocation, consume only its fresh owned final-output file. Retain the exact message before temporary cleanup; do not use an earlier file or an earlier intermediate agent message as fallback. Missing, empty, truncated or malformed final output from an otherwise settled invocation is a handoff-structure failure with the validated Developer session retained. Provider nonzero exit, error/failed events, absent settlement or conflicting session identity remain provider/transport failures and cannot be converted into handoff success or an invented resumable session. Distinguish those failures from structurally valid semantic validation errors in retained diagnostics. Never repair output by inventing missing claims, IDs or citations.

The low-level native-helper routing fixture also uses Harness.launch_developer but has no Build contract and intentionally returns a short collection confirmation. Preserve that separate transport use through an explicit internal route or updated fixture adapter; it does not excuse an unconstrained Build path. All affected fake providers and role-count assertions must identify actual role independently of schema-flag presence, since both roles now use that flag. Keep injected harness support, configured profiles, stdin handling and hostile inherited-role overrides.

## Accepted correction policy

Retain current bounded outer rework for settled invalid handoffs. Provide actionable structure-versus-semantic diagnostics and re-enter the exact Developer session with a fresh token/schema/output location. Invalidate old Check evidence and require a new matching Stop Check before the full declared non-check sequence and fresh Review. With outer_resumptions=2, an initial attempt and two corrections can run; another failure stops. Handoff correction consumes the existing shared allowance, is labelled handoff failure, and does not create Review findings or a separate retry pool. Provider failures still stop. This policy matches the separately approved Unify verification preservation clause. This package does not authorize editing that separate Intent.

## Ownership and retention

Create a private invocation directory with collision-safe ownership and restrictive permissions. Existing paths must never be clobbered or adopted. Keep schema and output location available throughout Stop-blocked continuation; exact-session outer resume gets a different directory and schema. Capture final bytes and required diagnostics into controller-owned retained attempt evidence before cleanup. Capture schema bytes or a retained exact-byte snapshot with digest, attempt/session identity and outcome so Review can inspect what was enforced without a removed temp file. Failure receipts must not require optional raw logging to retain essential diagnostics. Remove only owned temporary files on success and handled failure; abrupt process death may leave disposable files, never reusable input. Do not make temp files user-owned configuration or add new configuration keys.

Retained records remain controller-owned and subject to existing integrity/snapshot/publication rules. Extend the existing evidence layout only as needed. Independent Review inspects the retained schema, handoff, diagnostics, Candidate and owned receipts. The outer native test driver alone observes ephemeral callbacks and session transitions; it retains and audits these before fixture cleanup. Nested Review must not reconstruct callbacks from inaccessible native state or certify future events.

## Walkthrough and adversarial challenge

Starting from a clean checkout with dependencies, Git, Make and authenticated configured Codex, a human-approved package enters Build. Build freezes its contract and issues token A. The Developer uses schema A, makes allowed changes and encounters a real failed Stop Check; the same native turn corrects the Candidate and passes Stop, then settles with current structured output. Runtime rejects any unsafe/stale/incomplete handoff before targets/Review. Valid output and references are retained, declared targets run, and independent Review assesses actual behavior. A rework verdict resumes the exact Developer session with token B, current findings, schema B and a fresh output location; passing current gates and a fresh accepting Review permit existing publication.

A plausible wrong implementation adds the schema flag only on fresh launch, treats all schema calls as Reviewer in fixtures, accepts duplicate IDs because cardinality matches, or reads yesterday's output after provider failure. Component formatting tests could pass while resumed Builds fail or false acceptance becomes possible. Linked scenarios therefore require the actual fresh/Stop/resume consumer route, duplicate/stale/missing controls, retained evidence after cleanup, and preservation of existing Review and publication safety.

## Verification and completion

Use existing `check` and `live`; no target or gate ownership change. Offline fixtures must rehearse orchestration before provider-backed execution and include positive controls alongside failure injections. Existing connected Shape-to-Build and Build-only Reviewer-rework cases are affected even if their test filenames would otherwise remain unchanged. Preserve their genuine failed-then-passed Stop sequence, exact Developer resume, new token, fresh independent Reviewer and committed result. Audit native-helper dispatch preservation as well.

The Developer may run focused non-gate checks only. Its Stop owns `check`; Build owns `live` after matching Check settlement. Native test drivers retain inspectable current-run receipts, schema/output evidence, callback observations and raw streams before cleanup. Independent Review assesses those receipts and Candidate separately from the outer driver's sequence audit. Complete when all linked scenarios pass their targets and independent Review accepts; shaping probes are feasibility evidence, never a substitute for this implemented route.
