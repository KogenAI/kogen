# Keep Build evidence out of oversized commits

## Outcome and appetite

One Build changes Kogen's publication boundary so a successful Build produces a small, useful committed Intent, while exact verification evidence remains locally inspectable outside Git. A oversized publication must stop before a commit is made, naming the offending paths and byte counts. questions.md records the resolved policy choices; intent.yaml maintains current approval metadata.

The user stopped a push whose Developer-handoff Complete record contained 1,857,665,506 bytes. The following Unify verification record contained 165,683,775 bytes. A separate, explicitly requested repair archived both records and rewrote the two unpublished commits without changing implementation. The repaired outgoing pack measured 1,158,672 bytes. That repair is complete historical work, not part of this Build.

Keep appetite to one Developer conversation with the configured two outer resumptions and separate two Stop verification retries. The scope is compact publication, retaining its exact evidence, updating directly affected consumers and enforcing a final publication budget. Runtime snapshot deduplication and removal of recursive record embedding are explicitly deferred: this Build prevents their bytes entering commits but does not claim to fix runtime growth.

## Publication contract

1. Keep the complete, controller-owned tracking record in its existing ignored `.kogen/runtime/scenario-tracking/<build-id>/record.json`. Preserve its exact bytes, existing schema, per-role/per-attempt snapshots, required uncited target artifacts, failed attempts and finding history. Do not truncate, filter, rewrite or discard the authoritative evidence to make publication small. No new storage service, credentials or user setup is required.
2. New Complete packages contain a distinctly named/versioned compact summary (for example collision-safe `build-summary.json`) and readable evidence navigation. Do not write a partial record under a name/schema implying it is full scenario tracking. Retain the frozen Approved package unchanged, including its supplied evidence; do not silently strip large files from it.
3. The summary uses an explicit field allowlist, not recursive key deletion. Retain Intent/Build identity, accepted Candidate identity, attempt numbers/tokens and role session bindings, settled target names/statuses/exit codes/timestamps and their Candidate bindings, final per-scenario results, risk IDs, finding origins/current dispositions, and final independent Review outcome. Preserve every required row; fail the budget rather than silently omit or truncate meaningful identities or coverage. Include the full record's repository-relative locator, SHA-256, exact byte count and format/version. Full claims, schemas, transcripts, output bodies, artifact bytes and historical record snapshots remain in the local record. Generated evidence.md must not re-embed the full verdict or logs and thereby defeat the compact projection.
4. Clearly state that a fresh clone contains the contract and concise results, while exact evidence requires the local archive. A hash identifies evidence; it does not prove semantic inspection or make missing bytes available. Document resolution and digest verification from the checkout root. An unavailable archive after a later user cleanup is reported as unavailable; do not fabricate results, fetch automatically, or treat a compact summary as equivalent to the full evidence. Build must verify the archive exists with the correct bytes before publication and preserve existing post-publication integrity checks.
5. Fixed policy: maximum 5 MiB (5,242,880 bytes) per added/modified file and 10 MiB (10,485,760 bytes) in aggregate across all added/modified files in the final staged tree relative to starting HEAD. Equality is allowed. Count full uncompressed blob length per changed destination path, including renames and deliberately staged ignored files; do not use compressed pack size, filesystem apparent size, only positive line deltas, or only the Complete folder. Deleted paths contribute zero. Unchanged preexisting files do not consume the budget. These are explicit constants documented with the implementation, not invented missing configuration defaults. No override or new configuration interface is included.
6. Reject newly added/modified staged entries under `.kogen/runtime/` regardless of size. Ignore rules alone are insufficient: Git can force-stage ignored evidence. Check actual final staged entries using unambiguous NUL-delimited paths, including whitespace/newline names. A symlink or submodule must not cause the guard to read outside the checkout; preserve established Candidate/path protections.
7. Preflight already oversized Approved inputs before provider launch where their sizes alone establish failure. Recheck the complete staged publication immediately before commit so generated files and late changes cannot bypass the budget. Preserve all existing Candidate, Approved input, tracking, verification, target-evidence, and staged-tree integrity checks. A limit failure makes no commit, leaves source work and full evidence available, restores the original Approved package if publication began, removes only owned incomplete Complete output, and follows established index rollback behavior. The error identifies each file over its limit, measured total/limit, and enough largest contributors to explain aggregate failure, plus locations of preserved work/evidence. It does not silently drop files, rewrite history, invoke another paid role, relax limits or report success. Reducing an Approved package requires returning to Shaping; this is not authority for Developer to modify approval.

## Consumer and lifetime preservation

Runtime Review continues reading its bound full tracking record and actual Candidate. Summary generation happens after existing acceptance and never substitutes for Review. Controller retention of required artifacts remains distinct from Reviewer semantic citations. Stop still owns all gates/retries; this change neither grants extra attempts nor allows Developer/helpers to run gates.

Update consumers that currently parse Complete/scenario-tracking*.json as a full record. Offline lifecycle and live rework audit must resolve the full archive by its bound locator and verify the digest before inspecting attempts, schemas, target artifacts or record versions. Keep support for existing full-record Complete fixtures/history through explicit format handling; do not bulk-migrate completed Intents or interpret the two historical cleanup receipts as full evidence. A summary of unknown version, missing archive or digest mismatch must produce an actionable error, never a passing audit.

The live outer driver already copies full runtime records into its per-run log directory before deleting fixtures. Extend that owner to retain the compact summary plus its bound full record with a stable copy locator/digest, then audit from the retained copy after deleting the original fixture in deterministic coverage. Copying a locator alone is insufficient. `KOGEN_LIVE_LOG_DIR` and the existing default remain the destinations. Do not make the root checkout depend on a removed fixture, temporary dependency or another user's machine. The outer driver owns ephemeral sequence/cleanup evidence; independent Review inspects retained receipts, summaries and exact artifacts rather than reconstructing vanished interactions.

Legacy schema v1 runtime records and existing records remain unchanged. New summary readers may distinguish new compact format from old full Complete records; no new restart/checkpoint authority or rewrite of historical acceptance is introduced.

## Walkthrough and challenge

Starting from a clean attached checkout with installed dependencies and an Approved Intent, Build runs the existing Developer, Stop and independent Review sequence. A large required artifact is captured in the actual target receipt and remains available to Review. After acceptance, Build retains the full record locally, creates a small allowlisted summary, validates its digest and the actual staged publication budget, and commits the reviewed implementation plus concise Complete package. A maintainer can read outcomes from a clone, and inspect exact evidence when the local archive is present. The live fixture driver exports evidence before cleanup.

A plausible wrong implementation removes only content_base64 from one output file. It passes a small-file test but leaves giant verdict strings or copied Approved evidence in the commit, loses uncited artifacts, or publishes a stale archive locator. The linked scenarios require a real accepted fake-harness lifecycle, an oversized artifact, current per-role bytes, uncited required evidence, cleanup survival, whole-staged-tree budget tests and corruption failures. Another wrong implementation merely blocks the old 1.86 GB record: that prevents a commit but never delivers a successful small Build. A positive large-runtime/small-commit case is mandatory.

## Verification and completion

`check` must exercise the actual public fake-harness Build through commit/rollback, not just a summary helper. Add boundary tests at exactly and one byte above each accepted limit; multiple individually valid files must exceed the aggregate limit. Include forced staging, renamed/whitespace paths, late publication mutation, untouched historical large blobs, source preservation, archive tamper/missing controls and a fresh-clone availability case. Rehearse live archive resolution, copy and cleanup deterministically before paid execution.

`live` is required for affected connected Shape-to-Commit and Reviewer-rework consumers and their retained evidence. Use the existing declared target rather than inventing a make target. The outer driver retains native sequences and archive-copy results; Review assesses those receipts and the Candidate. No provider call or gate was run in this Shaping session. Existing cleanup measurements are reused, not presented as future implementation verification.

Completion requires all linked scenarios, preserved authority and evidence, documented limits/retention/recovery, and ordinary independent Review. A package or publication failure is not an accepted Build. Approval authorizes only normal narrow Intent approval bookkeeping here; source implementation belongs to the later Developer.

## Non-goals

No recursive runtime-storage redesign, content-addressed store, general archive manager, compression/LFS/cloud upload, automatic pruning, global Git hooks, arbitrary manual-push protection, historical Git cleanup, resumed Build support, changed attempt budgets, model/profile changes or broad diagnostics work. No guarantee of small local runtime files or protection for commits made outside Kogen. The already completed repair remains archived separately.
