# Add opt-in native no-progress stops

Implement K-NOPROG for MECHANISMS `loop-no-progress-hook` (provisionally started by main 28 Oct). Add an internal per-role native run option, default false. Use `project.Role.NoProgress bool` with JSON omission when false; do not add a YAML parser key or CLI flag. Programmatic role settings enable it. Preserve it in enabled run custody where role settings are already retained. Only native Build honors its own role's setting, without affecting external executors. Manual Shape, Refine, worker and independent Review loops ignore their NoProgress role setting; document these roles as unsupported for now. Do not add fingerprint or streak logic to those manual loops.

For each continuing native Build provider round, hash the ordered sequence of tool names and hashes of their exact argument strings. Use SHA-256 and unambiguous JSON array framing, lowercase hexadecimal; ignore call IDs, response text, results and usage. Clear the batch between rounds. Supply `loop.Hooks.Progress` on the native builder, using the pinned `loop.NoProgressRounds` and `loop.NoProgressError`, not a new configurable threshold or a separate streak implementation. Terminal/no-call completion is not a continuing round. Three identical consecutive fingerprints stop; a differing fingerprint restarts the streak at one. Scope streaks to one native Build conversation invocation, not unrelated verification passes or roles; no new resume guarantee is introduced. The unchanged model describes this supported native Build policy only.

Propagate the stop through Build's existing error/finalization path. Record a truthful no-progress reason, fingerprint and count 3 (and matching round numbers where available) in existing JSON event/result custody, using a `native_no_progress` event with `fingerprint`, `count` and `rounds`. Do not label this as a provider failure or external executor round limit. Retain existing user-visible output formats and normal no-commit-on-stop behavior. No new output format or other limit changes. With the option false the hook is nil and requests, records and behavior remain byte-identical, including omission of new false/zero metadata.

## Decisions
- Internal only, per role, default off; no CLI or project.yaml exposure. (source: request)
- Native Build only, through loop.Run and loop.Hooks.Progress. Manual Shape, Refine, workers and Review ignore NoProgress and are documented as unsupported for now. (source: request)
- Stop repeated tool-call rounds with the existing threshold, retaining truthful reason and fingerprint count without a new output format. (source: request)
- Shared host: temporary directories only; never kill by process name/pattern, only owned PIDs; no synthetic CPU load. (source: request)
