# Explain approval timeouts and command failures

Slug: k-approve-deadline
Model: .kogen/intents/k-approve-deadline/model.qnt invariants=Safe seed=7 samples=30 steps=10
Acceptance:
- .kogen/intents/k-approve-deadline/acceptance.feature
- features/steps/k_namedfeedback_steps.js

Make `kogen intent approve <slug> [<hash>]` stop accurately and retain useful diagnostic evidence, without a shared deadline attributing accumulated work to the last command. Split expensive execution into independently bounded steps, keeping the historical 120-second bound for each executed step, not increasing it or introducing any retry, public option, environment knob, or asynchronous approval protocol. A successful collection of individually timely steps may exceed 120 seconds overall. A step exceeding its bound still refuses, but reports a step timeout, not a diagnosis that Git or the host is defective. Include time spent in preceding steps. Host contention cannot be reliably distinguished from a hang using elapsed time alone; make that limitation explicit instead of asserting an unobserved cause.

The current Go implementation already has no shared approval deadline: `runEngine` passes the signal context to `shape.Approve`, `Readiness.Check` runs clean setup and acceptance, and `sys.Session.Run` combines stdout and stderr. Do not restore the historical shared deadline or rerun configured checks merely to reproduce an obsolete architecture. Preserve exact-tree readiness reuse, clean-scratch setup, accounting, mutation guards, source custody, card/hash semantics and explicit approval. Configured checks run only where they already belong, including checks invoked by a project's acceptance wrapper; this change does not add them to readiness. A failure of such a wrapper must expose its own check diagnostic. Approval needs no provider calls.

## Decisions
- Prefer splitting work over raising limits; no retries or new knobs. Tests use sleeping/blocking owned fixture processes, never synthetic CPU load. Support macOS Apple Silicon and Linux x86-64 glibc. (source: request)
- When work stops, show which steps actually ran, their elapsed wall times and statuses, and which step timed out or failed; do not blame a fast snapshot for earlier work. (source: request)
- Include the failing command's own bounded stdout and stderr in both refusal and retained local evidence, with secrets redacted before excerpting or persistence. (source: request)

## Execution contract

The named Go tests are implementation tests, not protected acceptance files. Add them to package main in `cli/` and exercise the real built CLI with temporary installations/projects using existing test utilities. The protected Cucumber harness independently requires each exact test to execute once and pass, not just `go test` exit 0. Do not satisfy it with skipped tests, source inspection, fake CLI output or model-only assertions.

1. TestApproveDeadlineSplitCLI: use an unapproved valid `goose-labels-go` fixture with no reusable readiness. Setup and acceptance/check-wrapper each sleep 65 seconds and succeed; the wrapper supplies a valid accounted report. Total exceeds 120 seconds but neither command does. Snapshotting uses real Git and a fresh private index; include `vendor/` data and ignored `node_modules` without depending on historical size/profile. Run the card and require exit 5, full hash and usable approval command, then approve the exact hash and require exit 0 and matching marker. Count setup/wrapper invocations to prove no retry and normal unchanged reuse. Assert HEAD/index unchanged by card/refusal paths. Commands may label fixture work `npm ci` and `go build ./...` in output, but must not install external packages or use expensive cold compilers instead of deterministic waits.
2. TestApproveDeadlineHungCLI: fixture setup writes its PID and stderr diagnostic then blocks, with a child in its owned group. Drive real approval, allow the unchanged 120-second per-step watchdog plus normal teardown, and fail the test if it waits indefinitely. Require refusal naming setup and step timeout, numeric elapsed duration, earlier completed steps and their durations; never call a later `git add -A -- .` the cause. Require no approval, no later acceptance/check invocation, one invocation of the blocked command and terminated owned processes. Harness teardown kills only owned groups on failure. Do not add a production timeout knob to shorten the test.
3. TestApproveFailureOutputCLI: independent fresh fixtures for acceptance `exit 134` without writing a report, setup `exit 23`, and acceptance wrapper check `exit 17`. Each writes distinct `command-stdout-diagnostic` and `command-stderr-diagnostic` markers. Acceptance first prints `kogen: running setup-1: fixture`, reproducing the historical prefix. Assert nonzero refusal, true command/exit attribution and both markers in CLI refusal AND retained evidence after exit. For exit 134 retain report_missing context and command diagnostic; do not infer the original crash cause. Wrapper check diagnostic must name `go build ./...`. Never execute a real abort. No approval/commit, rerun or later work after definitive failure.
4. TestApproveFailureEvidenceCLI: read persisted attempt evidence referenced by refusal; assert executed steps in order with identity, monotonic nonnegative duration, terminal status/exit and timeout boolean where applicable. Include completed setup then failing acceptance, and setup failure with acceptance not run. Unexecuted work gets no invented duration/output. Compare displayed durations with the same attempt's retained durations allowing rounding, not exact scheduling assertions. Refused evidence is distinguishable from ready version-3 evidence and never makes Cached accept the task. A fresh subsequent invocation still runs normal checks. Evidence survives scratch cleanup. Failure cannot overwrite unrelated attempt evidence or successful source history.
5. TestApproveFailureBoundsCLI: commands emit a known fake secret via stdout, stderr and a command argument, harmless diagnostic head/tail markers and oversized UTF-8 output. Supply fake credentials/environment only in isolated HOME. At minimum mask known credential values available to Kogen and nonempty environment values whose names identify TOKEN, KEY, PASSWORD or SECRET; mask Authorization Bearer values and secret assignments in diagnostic text. Do not dump the environment or read unrelated credential stores. Assert no supplied secret in refusal, attempt evidence or logs; redact before bounding so boundary splits cannot leak it. Keep existing 16384-byte display, 1 MiB recorded-output cap and Excerpt line policy rather than enlarging them or dropping stderr. Fitting nonsecret diagnostics remain. Redaction cannot promise detection of arbitrary unlabeled unknown secrets; document supported treatment honestly.

Retained attempt evidence is private local diagnostic custody, not approval authority. Place it under `.kogen/local/readiness/` in a separate per-attempt file/directory, print its inspectable path in refusal, use private new directories/files (0700/0600), and keep successful `<slug>.json` readiness format/reuse separate. Record failures before returning, including output when the acceptance report is absent. Include the terminal in-progress step on timeout without pretending subsequent work ran. Cover snapshot/materialization and execution phases actually reached by approval, not a fabricated historical list. Normal interrupts preserve signal exit semantics and cleanup; do not reclassify them as check failures. Changes can stay in owned cli code: the protected loop exposes timeout/cancellation/combined-output facilities and must not be edited.
