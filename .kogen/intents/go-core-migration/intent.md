# Rewrite the Kogen core in Go

Slug: go-core-migration

Replace the entire current Elixir Kogen core with native Go behind the existing `kogen` command. Preserve maintained behavior on main `76109e1a`, not merely either earlier port's behavior. This includes every command, all four providers, exact approval and protected baselines, user files and credentials, history, verification evidence, independent Review, private custody and safe explicit continuation. The result is one approved, sequentially staged Build, full final verification and fresh independent review, then one commit. A milestone is historical evidence, never partial delivery.

### Implementation contract

**Native runtime.** Extend the Go module in `cli/` using cohesive packages for project/Git/authority, provider transport, agent tools, verification and lifecycle orchestration. Keep a thin CLI dispatcher and reuse its working command executor and local-facts interfaces where applicable. This is an implementation decomposition, not a new public API. Remove active `lib/`, `config/`, `rel/`, `mix.exs`, `mix.lock`, the Go↔Elixir launch/protocol path and obsolete core ExUnit/Elixir test drivers after porting their useful assertions. No Go command may invoke Mix, Elixir, Erlang, BEAM or a hidden old core to implement Kogen. Project commands may legitimately invoke those tools. Preserve cancellation, isolated process groups, descendants/watchdogs, binary output and signal-to-exit mapping. Do not retain a second active engine or a runtime migration toggle.

**Authority and data.** Preserve the path-sorted SHA-256 approval baseline algorithm, exact protected bytes, modes, symlink safety, index/HEAD handling, locks, Git hooks/signing, original request/Q&A/source receipts and receipt history. Existing `.kogen/project.yaml`, Intent Markdown/Gherkin/Quint, approval markers, private run/log/result/review data, usage records, readiness, source provenance and custody stay readable with their current meanings. No silent data reset, reapproval, approval transfer, red-to-green conversion or use of stale evidence. Use native Go readers for Elixir-produced version-3 checkpoints, including the base64 Erlang external-term `state`; validate schema and all existing path/tree/hash/custody bindings before effects. Continue supported builder and reviewer owners in the SAME checkout with the saved conversation and lineage. Legacy/version-2 checkpoints remain inspectable but unsupported, not migrated into authority. New Go state may use an explicitly versioned JSON checkpoint representation with equivalent validation; retain old checkpoint/result bytes unchanged. Reading historical ETF is data decoding, never execution/deserialization of callable code. Current Elixir configuration provenance hashes must remain verifiable: do not invalidate existing receipts merely by changing serialization language.

**All maintained lifecycles.** Port init/discovery, Shape/Q&A/optional workers, native documentation records, accumulated proposals and exact-red acknowledgment; clean Snapshot-based readiness/setup and exact candidate-tree reuse; Refine ownership/rollback/revocation; approval cards and stale-approval receipt recovery; Build/verification/Review/commit; explicit Resume, protected-blocker recovery, read-only context/list/inspect/preflight/usage and completion. Port working windows, source parts, private archives, images and evidence summaries for every owner, not only Build. Keep complete next-request accounting at the inclusive **524288 UTF-8 bytes**, with **131072 tokens** reserved; equality fits, 524289 does not. Keep the 16384-byte native text-result bound (4096-byte prefix, UTF-8-safe suffix, exact omitted-byte marker, idempotent replay) and uncut private originals. Preserve selected PNG limits (1..131072 original bytes; static non-interlaced RGB8; dimensions 1..2048), frozen typed delivery and independent fresh Review pixels. Text paths/base64 are not pixel interpretation. Preserve honest external pixel handoffs and unsupported provider-image outcomes.

Preserve transient in-stream retry's current deadline/cancellation and uncertain-effect rules, complete safe tool batches/replay, bounded local windows and missing/altered custody refusals. Staged Builds keep the same owner and one approval, ordered scoped gates, fresh setup, durable tree-bound `stage_progress`, explicit same-checkout continuation, final whole gates and independent final-tree review. Historical milestone evidence must not authorize a later edited tree. A builder-reported protected contradiction is an unproven stop. `intent recover <build-id> --output <new-external-directory>` must preserve before/candidate/index/approval/checkpoint and clear only the recorded implementation delta; no auto-refine/approve/resume/import or old-green reuse. Preserve normal failure classifications and exit codes.

**Providers.** Reconcile current ChatGPT, SuperGrok, OpenCode Go and Anthropic behavior, credentials and offline status. Omitted role provider stays ChatGPT. Preserve per-role selection, authentication, private modes, stateless replay, tool/image capability handling, stream assembly, retry deadlines, usage uncertainty, bounded cache-parameter refusal and no paid-route fallback. The known models (`grok-4.7` with `low/medium/high/xhigh`, `kimi-k3` with `high/default`, Anthropic `claude-opus-5-5`/`claude-sonnet-5-5` with `low/medium/high/max`) become recommended defaults and documentation hints only, per Open model selection. API keys are not subscriptions, and local key storage is `key saved (not verified)`. Reproduce current wire/observable semantics using real local HTTP fixtures; do not copy the external port's known SuperGrok header defect. Anthropic remains not live-qualified. Do not introduce speculative API changes from fetched material.

**Prompt caching (KOGEN-054, research/PROMPT-CACHING-GUIDE.md).** This is the one deliberate behaviour change. Every model conversation (shaper, each shape worker, refine, builder, each reviewer, init) gets one cache identity, at most 64 characters, created when the conversation starts, saved in its checkpoint/records and reused for every later request of that conversation, including retries, transient-stream retries, working-context resets and explicit resume; different conversations never share one. The front of every request is frozen for the conversation: identical instructions bytes, the same tool definitions in the same order with deterministic JSON, and no clock time, request id, random value or counter in instructions or tool descriptions. History is append-only: each request's input is the previous request's input plus the previous output items plus new items; tool output is cut once when recorded and replayed as stored; reasoning items (with encrypted content) and Anthropic thinking blocks are replayed verbatim. The only planned prefix break is an existing bounded working-context reset, which keeps instructions and tools identical. Per provider: ChatGPT sends `store:false`, `include:["reasoning.encrypted_content"]`, `prompt_cache_key` = the cache identity without a private-backend session header, and never sends `prompt_cache_options` or `prompt_cache_breakpoint` (so the retired cache-option rejection is absent; an exact routing-key refusal may strip only that key once, preserving replay, as recorded below); SuperGrok sends `prompt_cache_key` = the cache identity; OpenCode Go sends `x-opencode-session` = the cache identity on every request; Anthropic marks `cache_control: {"type":"ephemeral"}` on the last tool definition and the last system block, plus one rolling breakpoint on the last block of the newest message, never more than four, with the default five-minute lifetime. Usage records keep each provider's raw cache fields (Responses `input_tokens_details.cached_tokens`; chat-compatible `prompt_tokens_details.cached_tokens`, `prompt_cache_hit_tokens` or `cached_tokens`; Anthropic `cache_read_input_tokens` and `cache_creation_input_tokens`, where total input is input + creation + read) and `kogen intent usage` reports cached share from them. Cache settings never change which model, effort, tools or provider a role uses.

**Open model selection (KOGEN-057).** The second deliberate change, approved by Almir on 24 October. No provider has a model or effort allowlist. `.kogen/project.yaml` accepts any nonempty `model` and `effort` string for every role and every provider, and Kogen sends them unchanged (OpenCode Go and OpenAI-compatible effort `default` still means "send no `reasoning_effort`"). Known models are only defaults, docs and hints. A provider's model refusal (404, or `model_not_found`/invalid-model/invalid-effort codes) keeps today's first line, such as `provider/model_unavailable: <model> is not available to this <Label> account`. It adds one line naming the configured model and effort and the fix: change `model`/`effort` for that role in `.kogen/project.yaml`. The provider's own text appears where it is safe: ChatGPT and SuperGrok first lines already carry it, an OpenAI-compatible host's error text is shown as one sanitized line (`OpenAI-compatible said: …`, no control characters, at most 300 bytes, the saved key redacted), and OpenCode Go and Anthropic keep main's rule of never echoing body text (only the allowlisted `provider failure:` code/type line). There is never a retry or a fallback model. A fifth provider, `openai-compatible`, serves local and self-hosted models (Ollama, LM Studio, vLLM and other OpenAI-compatible hosts). Each role using it needs `base_url` (an `http://` or `https://` URL ending before `/chat/completions`, for example `http://localhost:11434/v1`), and `base_url` is refused on any other provider. It speaks the same non-streaming Chat Completions wire as OpenCode Go, at `<base_url>/chat/completions`. An API key is optional: `kogen provider login openai-compatible` saves one with the same echo-off stdin and 0600 storage, `kogen provider list` shows `openai-compatible: key saved (not verified)` once a key is saved and otherwise leaves the list unchanged (a keyless local host needs no login), and without a key no Authorization header is sent. The help page, Zsh completion, the unknown-provider message and the uninstall message name the new provider. Its cache routing sends no vendor field or header, because strict hosts refuse unknown fields; the frozen front and append-only history still apply, and usage reads `prompt_tokens_details.cached_tokens`, `prompt_cache_hit_tokens` or `cached_tokens` when reported. A role without `provider` stays ChatGPT, and configuration provenance hashes of roles without `base_url` are unchanged. Superseded accumulated scenarios (declared by exact name and example row in the acceptance): `opencode-go-subscription` "Unqualified Go models and efforts are rejected before inference", and the two `claude-api-key-provider` rows of "Select documented Claude models and the initial Kogen effort subset independently" that expect `claude-invented`/high and `claude-opus-5-5`/xhigh to be refused (its unknown-provider row is still refused). Changed step expectations: in `supergrok-subscription-20261022`, the `bad_model` and `bad_effort` configuration-refusal cases now expect the request to be sent unchanged and the fake's model refusal to produce the clear error with exactly one request. `bad_provider` keeps its refusal, with the list now naming `openai-compatible`.
