Make the existing review-card, exact approval and Refine workflow usable for ready current packages despite nonmatching older approvals. Reconcile the outcome of the signed parallel branch with current main, not its implementation wholesale. Replace circular provenance/stale-marker refusals with supported correction and preserved history. Update README, maintained SHP-11/AUT-1/AUT-2 prose and scenarios, and focused implementation tests. No new revoke command, manual marker deletion, different-slug workaround, automatic continuation or approval transfer is needed.

## Decisions
- `kogen intent approve <slug>` checks the current package and displays `SHA-256: <full 64 lowercase hex>` plus an approval command with that full hash, exit 5. It does not approve or start Build. A nonmatching marker is visibly labelled `Stale approval`, with its full old hash and an explanation that it does not authorize current content. Existing supported 6–64-character approval prefixes remain supported. A mismatching prefix refuses with `intent/hash_mismatch`, the full current hash and the usable card command. (source: request)
- The card retains actual readiness observations, source comparison/path/hash/binding, protected file list and the complete ordered `Staged plan` (all titles, goals and check commands). Inspect intrinsic parse/lint failures as such rather than misdiagnosing an older receipt contract as custody corruption; an invalid Model declaration after shared-helper drift must report `intent/lint`, not `candidate/source_provenance_changed`. A failed readiness gate cannot publish approval. (source: request)
- Separate intact historical source custody from current contract identity. For listed shared-helper drift, the unchanged receipt is valid historical diagnostic source, not proof of current readiness. Show its full prior contract hash alongside the full current hash and explicitly say that Shape has not run again. Cards leave the approval and successful receipt/history unchanged. After ordinary readiness, explicit current-hash approval may publish a current-bound receipt retaining exact original request/Q&A/origin/corrections, with previous receipt path/hash and prior/current contract identities. Preserve the prior receipt byte-for-byte in native hash-named history before changing current.json. Do not claim another Shape occurred or grant authority from originals. (source: request)
- For successful fresh same-slug Shape after parking, resolve the stale approval's displaced current.json reference only by its exact pinned digest in safe native receipt history. Do not rewrite the old marker to pretend its original reference was different. Before superseding a nonmatching approval, archive its exact original bytes privately under local history and print the inspectable archive path. A matching approved-current package still requires its pinned current custody to be intact; an archive is not permission to bypass tampering. Missing, altered or unsafe custody is never ignored or relabelled legacy. Genuine receipt-less legacy packages remain supported. (source: request)
- `kogen intent refine <slug> <full-current-sha256> <correction-file>` treats a nonmatching marker as unrelated stale authority, not an approved-current precondition. Permit normal correction of the ready unapproved current package, including the historical legacy-marker case, without Build-clean restrictions solely because that stale marker exists. Preserve original-ready checks, ownership/shared-file limits, authentication, scratch setup/readiness, mutation guards and the original full-hash requirement. Freeze stale marker bytes and resolved source custody throughout; archive/revoke the marker only on successful correction. Matching approved-current Refine still enforces normal Build-clean paths and protected-blocker recovery. Refine never approves. (source: request)
- Freeze package/readiness identity, current and resolved pinned source custody and marker bytes around execution/publication. On refusal, failure or cancellation, do not replace the package, approval or successful source custody; preserve HEAD/index. Do not overwrite concurrent external changes while rolling back this operation's writes. Existing source drift during readiness/inference remains a refusal. Report the actual path/hash or changed fact: hash mismatches point to the usable current card; custody errors name restoration of the exact missing/changed/unsafe receipt from preserved history before the card, not “obtain fresh approval” as a cure for the command that refuses. If exact custody cannot be restored, stop honestly. (source: request)
- Stale approvals never authorize Build. Keep `intent/changed_since_approval`, protected-baseline and readiness protections, exact version-3 baseline/HEAD/Snapshot-tree evidence reuse, full fresh Build verification and independent final-tree review. A successful fresh Build consumes the new approval normally. No old Build green, review, checkpoint, approval or production is imported. (source: request)
- Preserve current-main protected-blocker `intent recover`, transient retry, deterministic Mix gate, bounded tool results, staged one-Intent Builds (including card plan and stage_progress), and KOGEN-053 reference-based Shape/Refine history/documentation handoffs. The inclusive 524288-byte ceiling and 131072-token reserve, models/providers/efforts, configured commands and protection remain unchanged. The human's overnight observation request uses existing read-only `kogen context` / `kogen intent inspect`; this change adds no scheduler, 30-minute polling, automatic retries, cancellation or interference. Ordinary implementation red still goes to its repair owner; a protected contradiction remains a BUILDER-REPORTED unproven stop using explicit recover, independent Refine, new exact approval and a production-clean fresh Build. (source: request)
