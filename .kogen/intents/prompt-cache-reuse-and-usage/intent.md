# Preserve prompt reuse and explain usage

Slug: prompt-cache-reuse-and-usage
Model: .kogen/intents/prompt-cache-reuse-and-usage/model.qnt invariants=CountOnce,Continuity,ScopedComparison,BoundedCompatibility,CacheIsNotAuthority seed=21 samples=200 steps=30
Acceptance:

Improve useful prompt-prefix reuse at the real Sign in with ChatGPT Responses boundary, preserve valid stateless continuation, and make retained Shape/Build/review attempts locally analyzable. Deliver this cohesive feature in one future implementation commit in the existing Elixir engine and Go CLI, not the paused Go port. Replace lossy replay, uninstrumented implicit-only caching and summary-only usage investigation; preserve existing approval, verification, review independence, checkpoint safety, credentials, permissions and retention choices. Cache reuse never substitutes for inference, tools, fresh checks or authorization. No percentage, speed, weekly-quota or dollar-saving guarantee.

The supplied read-only investigation is evidence, not acceptance or an account ledger: migration Build f4637b88 had 84 completed requests, input 28,312,420, cached 5,974,784 (21.10%), plus one failed request with unknown usage; its separate Shape had 27 requests, input 3,546,834 and cached 245,120. The scoped 30-Build corpus had 1,079 rows, input 110,976,672 and cached 19,635,584 (17.69%). These are weighted ratios. Their request sums matched attempt_usage; cumulative usage, review summaries and Shape summaries must not be added again. No historical provider IDs or missing wire fields can be recovered from aggregates. Neither replay loss nor any other single explanation is established as the cause of those misses. Caching cannot fix the migration's context exhaustion or incomplete implementation.

## Decisions
- Keep one local CLI feature, with human output and versioned JSON, in the existing intent investigation command family; no dashboard, service or account query. (source: request)
- Preserve complete authoritative originals and settled Q&A in Shape, and exact approved Intent/acceptance/model/project rules/protection in Build/review, without passing raw shaping originals into phases that currently consume only the approved contract. (source: request)
- Keep independent phase histories, existing model/effort/service defaults, full manual HTTP replay, and best-effort diagnostics; never optimize a cache score by reducing approved scope or review independence. (source: request)
- Use 30m for frequent session reuse, retain implicit lookup, and do not prewarm. 12h is only a measured supported long-gap option, not a blanket default or deletion deadline. (source: request)
- Shape only now; no Build, approval, installation, publication, migration resume, paid compatibility/baseline/prewarm/benchmark calls or benchmark sweep is authorized. (source: request)

### Provider policy and authoritative prefixes

Implement at the existing provider/context owners (ChatGPT, Shape including workers/refinement, Build and Review; shared replay also serves Init). Do not introduce a general cache framework or a new provider/transport. Continue public `https://api.openai.com/v1/responses`, `store:false`, `stream:true`, Kogen-owned OAuth and account model availability. Never emit HTTP `previous_response_id`, `conversation`, `truncation`, legacy `prompt_cache_retention`, private backend-api requests, unsupported SIWC tools, or random cache keys. Omit prompt_cache_key absent a real existing isolation need. No filler to reach the 1,024 visible-token cache minimum, extra inference, compaction, context-budget redesign or reasoning-context change for caching.

Build phase-specific deterministic prefixes: unchanged policy first, unchanged tools/schema/order, then stable authoritative contract, before candidate text, diff, verification/pass/repair data, timestamps and changing manifest/file-list material where existing authority permits. Preserve all content and authority labels, including lower-authority selected evidence and optional Build diagnostic context. Split blocks rather than summarizing, promoting user/evidence text to developer authority, or silently retaining stale candidate data. A dynamic suffix must not regenerate or move an earlier stable block. Keep earlier messages/results append-only within a conversation. Change only the affected segment fingerprints for an intended policy/tool/schema/contract change.

On documented GPT-5.6+ models (including configured gpt-6.1-sol), send `prompt_cache_options:{mode:"implicit",ttl:"30m"}`. Move top-level instructions unchanged into an initial developer message with `content:[{type:"input_text",text:<same policy>,prompt_cache_breakpoint:{mode:"explicit"}}]`; omit redundant top-level instructions. This preserves developer precedence without elevating the contract's original role. Put the complete stable contract in a separate original-role input_text block with the same marker before dynamic blocks. Two stable explicit markers plus the implicit slot use three of four possible writes. Do not add markers to instructions, tools, function_call or unsupported item shapes. Keep markers on historical blocks unchanged instead of sliding them by rewriting history. Respect the four-write limit (implicit consumes one); the current guide's first two/latest 50 explicit lookup behavior is a placement constraint, not permission to trim replay. No explicit-only default, effort-switch feature, prewarm or legacy 24h field. No new user TTL setting is needed: retain/report provider-supplied 12h counts and document that enabling 12h later requires stable cross-gap reuse evidence, exact account acceptance and its 2.5x rather than 1.25x write rate.

Compatibility is bounded and visible. Earlier or unrecognized models omit new cache controls and markers, retain safe existing inference semantics and record `cache.status:"unsupported"` or `"unknown"`, not applied. For a definite nonexecuting HTTP 400 cache-capability/unknown-parameter refusal naming prompt_cache_options or prompt_cache_breakpoint (including nested cache fields), permit at most one compatibility retry per independent conversation: remove new controls/markers, retain policy/content/authority/model/effort and full replay. Retain the refused attempt and its unknown usage; mark unsupported and do not renegotiate on subsequent turns or resume in that conversation. This retry shares the existing absolute response deadline. Do not retry after a possible executed, failed/truncated/invalid stream just to strip fields, or reinterpret model, login, policy, usage-limit, context-limit or unrelated refusals as cache incompatibility. Preserve ordinary retry/cancellation classifications and limits. A valid response with absent/unavailable diagnostics is still valid; it needs no fallback or extra request. Unknown application of policy must never be reported as proven effective TTL.

### Replay, comparison and continuation

Replace Shape.replay_item's flattening/dropping behavior with schema-aware replay of valid supported output: opaque encrypted reasoning, assistant role/phase and output_text/refusal content, required IDs/call_id/name/arguments/status and supported replay fields in their original order. Do not blindly echo arbitrary output-only fields into request items. Preserve the received valid reasoning item's encrypted_content and summary without decrypting it. Never manufacture absent legacy items/phase/IDs. Append tool outputs and new turns after those items. Maintain this representation in existing checkpoints, with optional new conversation/cache state defaulting to unknown for safe old v2 checkpoints; do not change the existing refusal of unsupported/damaged checkpoints or uncertain tool/commit execution. Existing roles have fixed effort. No observed within-conversation effort switch requires configuration_update; do not add one. Any truly necessary preservation of an existing legitimate switch must use its documented restrictions, not rewrite earlier request effort.

Retain the latest validated completed response ID in that independent conversation. First call has no comparison; next already-required call on a supported route uses `prompt_cache_options.comparison_response_id`. This is diagnostic comparison, never conversation loading, output reuse or authorization. Keep comparison/policy capability state through safe checkpoint/resume; a new reviewer starts with neither builder transcript/reasoning nor builder comparison ID/cache continuation. A review retry stays with its saved reviewer and fresh verification. Missing/expired baseline, unavailable diagnostics and unknown legacy state are normal. Stale cache metadata cannot replay tools, reuse invalid checks, clear blockers or accept changed approval/tree/index.

### Per-transport evidence

Extend existing local records append-only; never rewrite old files. Keep existing compatible aggregates for callers, but analytical truth uses nullable measured fields, not adapter zero defaults. Build/review record each actual transport attempt as `event:"provider_attempt"` in the existing run log. Extend Shape/refinement/worker `provider_call` attempt evidence, not a second spend ledger. A completed logical request summary must be linked by operation ID and never counted in addition to its transport rows. Each new attempt has a `provider` metadata object with:

- `operation_id`, `attempt_id`, `conversation_id`, `timestamp` (UTC RFC3339); phase/role; available run/slug/lineage/pass/repair identities; provider_response_id and provider_request_id (actual response.id and HTTP x-request-id, absent null).
- configured_model/effective_model, configured_effort/effective_effort, requested_service_tier/effective_service_tier, requested_reasoning_context/effective_reasoning_context. Do not copy configured values into effective fields without response evidence; absent returned values are null.
- `cache:{configured_mode,applied_mode,configured_ttl,applied_ttl,status,boundaries,comparison_response_id,diagnostics}`. Status is requested/applied/unsupported/unknown; `applied` means accepted controls, not a proven physical write or hit. Boundaries identify locations, not content, at most four. Absent TTL acknowledgement may be null even after acceptance. Diagnostics contain only bounded classified type/reason/counts, or null. Keep cache_hit, cache_miss, comparison_response_not_found and unavailable distinct; unfamiliar categories become other, not raw provider text.
- `fingerprints:{policy,tools,schema,contract,prefix}`; each available segment has `{sha256,bytes}` of deterministic local UTF-8 representation. Schema includes tool parameter/output schema where supplied. Prefix identifies the stable prefix through the contract boundary, not the changing suffix. Label these as local-byte fingerprints, never provider token/rendered-prompt/cache facts. Absent segments are null. Fingerprints may explain changed local categories but never become provider-classified miss reasons.
- `usage:{input,cached,write,write_30m,write_12h,output,reasoning}`, each nonnegative integer or null; `usage_state` known/partial/unknown/inconsistent. Map writes from usage.input_tokens_details.cache_write_tokens and cache_write_tokens_details.ttl_30m_tokens/ttl_12h_tokens. Reasoning is a subset of output; cached and writes are disjoint subsets of input; lifetime writes sum to total writes when all supplied. Validate before arithmetic. Keep inconsistent evidence labelled and excluded from token aggregates, not clamped or repaired.
- `wall_ms` (response attempt wall), separately `ttft_ms` only if actually measured, otherwise null; outcome completed/failed/cancelled and a bounded classified error, not arbitrary raw bodies.

Bound diagnostic object encoding to 2,048 UTF-8 bytes, identifier strings to 256 bytes and boundary lists to four. Do not let malformed optional diagnostic metadata invalidate otherwise valid output. Failed/malformed/truncated/unconfirmed attempts have unknown usage even if untrusted terminal fragments contain numbers. Preserve existing credential, permission and retention choices; do not add raw prompt/payload/tool-body/encrypted-continuation snapshots to analytical records or reports. Opaque continuation remains only in existing conversation/checkpoint custody, never report text. Provider IDs are analytical identifiers, not bearer authorization.

### Local report interface

Add `kogen intent usage [RUN-ID] [--lineage] [--project DIR] [--json]` to the local facts/inspection family, with matching help/scoped documentation. No RUN-ID selects bounded history in the one canonical checkout chosen by --project (default current); RUN-ID selects that attempt, --lineage includes its root and descendants without double-counting inherited summaries. --lineage requires RUN-ID. It is read-only, works without credentials/provider/core inference, and never authorizes resume. Preserve existing context/inspect/list/preflight output and completion performance; context and completion must not begin history scans.

Support exact-match filters `--slug`, `--phase`, `--role`, `--model`, `--effective-model`, `--effort`, `--effective-effort`, `--outcome`, `--pass`, `--repair`; configured model/effort are distinct from effective. `--since` inclusive and `--until` exclusive take UTC RFC3339 timestamps from retained attempts. Unknown timestamps/fields do not match a specified filter and are disclosed, not guessed from weekly quota or file mtime. `--group-by` is a comma-separated list of project,slug,lineage,phase,role,model,effective-model,effort,effective-effort,outcome,pass,repair; default phase,role. Unknown grouping keys use null. Project scope is one explicit checkout per invocation; combining independently exported reports is not automatic account-wide accounting.

`--limit 1..100` (default 20) bounds returned request rows, newest timestamp then source path/line deterministic tie-break. Totals/groups cover all selected valid scanned rows, not just displayed rows; disclose omitted rows. Bound discovery to 10,000 immediate directories in the known .kogen/local/runs, shaping and refinements roots, 256 MiB scanned bytes total, 4 MiB per line and 100,000 attempt rows. Never recursively discover projects, follow run-directory symlinks into archives, or count nested acceptance fixtures, copied repos or arbitrary archive folders. Skip unrelated event kinds; do not load checkpoint.json, tool bodies or giant cumulative artifacts for routine totals. On a scan cap, missing/malformed/truncated record, return useful partial known totals with limitations, source provenance and `truncated:true` for capped scans; do not pretend completeness. Do not silently discard an entire history because one line is damaged.

Reuse the facts envelope: one JSON object/newline `{schema_version:1,kind:"usage",checkout,data,error}`. Success exit 0, including empty history; retain facts conventions for usage exit 2, absent project exit 3 and unknown run exit 1. `data` contains `scope` (canonical project_root, run_id or null, lineage boolean, filters), `totals`, `groups`, `requests`, `limitations` (sorted machine category strings), `truncated`, `omitted_rows`. Requests expose the safe provider fields above plus source/run/slug/lineage/pass/repair provenance, never raw events. A legacy normalized row uses available old role/model/effort/at/wall_ms/usage and nulls for absent new fields.

Totals fields: `requests`, `completed`, `failed`, `cancelled`, `unknown_usage` (any missing input/cached/output/reasoning or inconsistent usage), `inconsistent`, `duplicate_responses`, `legacy_without_ids`, `known_input`, `known_cached`, `known_write`, `known_write_30m`, `known_write_12h`, `known_output`, `known_reasoning`, `cached_input_percent`, `zero_hit_requests`, `response_wall_ms`, `phase_wall_ms`, `miss_reasons`, `unknown_fields`. Known sums add only supplied validated counts (0 if none); unknown_fields counts missing observations for each token category, so known_write:0 with missing rows is not zero writes. cached_input_percent is 100*sum(cached)/sum(input) over rows with BOTH counts valid, null for a zero denominator; disclose paired denominator/coverage when partial. Never average percentages. Count zero hits only when input>0 and cached=0 are known. Sum available response wall separately from retained measured phase elapsed/interval unions; missing phase wall is null, not response wall labelled phase duration. Groups use the same aggregate fields and explicit `key` object. Human output exposes the same scope, weighted ratio, known/unknown counts, writes/lifetimes, failures, time and miss categories, clearly saying local retained evidence, not account/weekly usage. No dollar or ChatGPT quota conversion; omit optional hypothetical API cost estimation entirely.

Deduplicate nonempty new provider response IDs within selected evidence, including copied retry/resume records, retaining all operation/attempt provenance and reporting duplicate count. Identical duplicates contribute once; conflicting same-ID usage is inconsistent and excluded with provenance rather than arbitrarily choosing. Without IDs, keep distinct legacy observations and disclose `legacy_without_ids`; only explicit same operation/attempt provenance can identify a repeated new observation. For old runs use request rows once; never add result.json cumulative usage, attempt_usage, review totals, checkpoint totals or Shape summaries. attempt_usage can cross-check request sums when available, not add to them or manufacture rows. Do not double count logical request summaries beside new transport attempts. Do not sum inherited unknown_requests counters as distinct failed calls. If only summary evidence survives, describe it separately as summary-only/unknown request detail, not invented attempts.
