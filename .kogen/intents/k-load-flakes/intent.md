# Make preflight and shape tests independent of load

Slug: k-load-flakes
Model: not applicable — a test's start synchronization and test fixtures' script execution change; Kogen's product state and behavior do not change
Acceptance:
- .kogen/intents/k-load-flakes/acceptance.feature
- features/steps/k_load_flakes_steps.js
- features/steps/k_load_flakes_driver.go

Two Kogen Go test problems under host load (change_type: fix, Studio issue e6e116d3-fc74-4b79-bd3f-db07112809de). No new command, flag or option; no timeout, retry or limit increase; no production code changes.

**1. TestPreflightStopsOwnedChildren** (`cli/executor/claudecode/preflight_process_test.go`, subtests `early_exit` and `cancelled`) today gives its fake `claude` a fixed 5-second `context.WithTimeout` to write its `ready` file and fails with `preflight did not start` when the deadline passes. Replace that fixed wall-clock bound: the test waits until either the `ready` file exists (the preflight's own observable start) or `a.run` has returned. If `a.run` returned and `ready` still does not exist (checked after the return), the subtest fails with exactly `preflight did not start`. The run's context is cancellable (`context.WithCancel`) with no deadline; a fake that hangs is caught by go test's own unchanged package timeout. Everything else stays: the fake's background child (`sleep 0.5; echo survived`), `cancel()` in `cancelled` and `wantError(t, err, "executor/interrupted")`, `t.Fatal(err)` for an `early_exit` error, the 700 ms negative observation and the `preflight child outlived its command` assertion.

The test gets one test-only seam, named exactly: a package-level `var preflightFakeStart string` in `preflight_process_test.go` (package `claudecode`), empty by default. The fake's script is `"#!/bin/sh\n" + preflightFakeStart + <the current script text unchanged>`, so its text runs first, before the background child and before `ready` is written. The acceptance mounts `features/steps/k_load_flakes_driver.go` with `go test -overlay` as `cli/executor/claudecode/k_load_flakes_acceptance_test.go` (do not create a real file at that path); its `init` sets `preflightFakeStart` from `KOGEN_K_LOAD_FLAKES_START` plus a newline: `sleep 6` delays the start past 5 s with no CPU load, `exit 0` makes the preflight end without ever starting. No production file references the seam.

**2. kogen/shape** must stay well inside go test's unchanged 10-minute package timeout under load, without host-side `-run` name sharding. Shaping found the cause (Feasibility): on the macOS build host, the first exec of every newly written executable file waits on the host-wide XProtect assessment (0.4–2.9 s per new file measured at load 6–9, longer under load), while `/bin/sh <file>` of the same new file takes 3–7 ms. Shape fixtures configure `acceptance: {run: ./accept.sh}` and Kogen's readiness materializes a fresh scratch tree for each runner check and acceptance run, so every run execs a never-executed copy of `accept.sh`. Change the kogen/shape test fixtures so that a fixture script run as a project command is started through `sh` (for example `run: sh accept.sh`) instead of exec'ing the freshly written file, in `newShpFx` (`cli/shape/helper_test.go`) and the other kogen/shape fixtures that configure `./accept.sh` (for example `shpWorkersConfig` in batch_test.go, approve_test.go, contract_test.go, lineup_shape_test.go, shape_test.go), and likewise for other fixture scripts run by path as setup, fix or check commands. Keep direct execution where a test asserts it. Keep `./accept.sh` for `TestShapeForceWireCompatibility`'s fixtures: `cli/shape/testdata/force_ordinary_golden.json` records bytes from before enforcement existed and must not be regenerated. Where an expectation quotes the fixture's command literal (for example the rendered `acceptance: ./accept.sh` in context_test.go and `Acceptance: ./accept.sh` in refine_test.go), either keep `./accept.sh` for that fixture or change only that literal. Same tests, names, subtests, skips and assertions; no test removed, weakened, renamed or moved; no `-timeout`, `-parallel`, `-p`, `GOMAXPROCS` or `GOFLAGS` set anywhere; accept.sh contents and behavior otherwise unchanged (TestShapeAcceptanceFitsLimit still edits its text). Before finishing, run `(cd cli && GOFLAGS=-trimpath go test -count=1 ./shape/)` unsharded once; it must pass. Load measurement on the build host is delivery's after landing, not an acceptance threshold.

## Decisions
- No new command, flag or option; no timeout, retry or limit increase; problem statement only, implementation settled by shaping. (source: request)
- The start check waits on the preflight's own observable start, not a fixed wall-clock bound, so the test proves the same behavior whatever else runs on the host. (source: request)
- Acceptance is one fast check well inside approval's 120-second step limit, needing no model: the test passes when the preflight's start is slower than 5 s, delayed by the test itself with no extra CPU load, and still fails when the preflight really does not start. The configured checks pass. (source: request)
- kogen/shape stays well inside the unchanged package timeout without host-side sharding; load measurement on the build host is delivery's after landing. (source: request)

## Tests
- The preflight start check waits on the preflight's own start, so a start slower than 5 s passes: acceptance scenario "A preflight whose start is slower than five seconds is waited for" running the real test with `sleep 6` (regression)
- A preflight that never starts still fails both subtests with "preflight did not start", by ending, not by a timeout: acceptance scenario "A preflight that really does not start still fails the test" with `exit 0` (regression)
- An immediately starting preflight still passes, its children are still stopped and cancellation still reports executor/interrupted: acceptance scenario "A preflight that starts at once passes as before" and the test's unchanged assertions (existing)
- kogen/shape fixtures run their project-command scripts through sh, with the same tests and assertions: the existing kogen/shape tests, configured go-test and one unsharded `(cd cli && GOFLAGS=-trimpath go test -count=1 ./shape/)` (existing)
- Configured checks stay unchanged and pass: configured verification (existing)
