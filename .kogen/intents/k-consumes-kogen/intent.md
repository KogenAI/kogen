# Add consumes suites for kogen's dependencies

Slug: k-consumes-kogen
Model: not applicable — the change adds test-only Go suites and their READMEs; kogen's behaviour, commands and state are unchanged
Acceptance:
- .kogen/intents/k-consumes-kogen/acceptance.feature
- features/steps/k-consumes-kogen__suites.js
- features/steps/k-consumes-kogen__inventory.js
- features/steps/k-consumes-kogen__control.js

Kogen's repositories depend on each other through Go modules (kogen requires the component modules in `cli/go.mod` and vendors kogen-loop under `cli/third_party/kogen-loop`, replaced as `kogen-loop`). Each producer keeps a contract/ suite of what it provides, but nothing in kogen states what kogen consumes, so a producer's landing has to build and test kogen in full (the blanket consumer check), which is slow and misses uses no test exercises. This change adds the consumer side of the two-sided contract: one Go test suite per Kogen dependency that kogen's non-test code uses, each stating, as tests, exactly what kogen relies on from that dependency.

Outcome. The `kogen` Go module (`cli/`, module path `kogen`) gains exactly these seven directories, one per dependency, named after the dependency's module (last path element):

- `cli/consumes/kogen-build/` (import path `kogen/consumes/kogen-build`)
- `cli/consumes/kogen-coordinator/`
- `cli/consumes/kogen-executor/`
- `cli/consumes/kogen-setup/`
- `cli/consumes/kogen-shaping/`
- `cli/consumes/kogen-verification/`
- `cli/consumes/kogen-loop/`

No other directory is created under `cli/consumes/` (in particular no `kogen-review`: see Source comparison). Each directory holds `*_test.go` files of one in-package test package named `consumes` (no non-test `.go` file, no external `_test` package) and one `README.md`. Because they are packages of the `kogen` module, `(cd cli && go test ./...)` (the configured `go-test` check, which runs it with `GOFLAGS=-trimpath`) runs them, and they pass at the dependency versions `cli/go.mod` pins now.

What each suite asserts. A suite is written only against its producer's public, exported API and asserts exactly the behaviour, types, functions and formats kogen's own non-test code relies on, and nothing kogen does not use:

- Every identifier in that producer's inventory below is referenced by the suite and covered by an assertion: signature and type pins (for example `var _ func(context.Context, *sys.Session, setup.InitInput) (int, error) = setup.Init`), struct field presence and type, and the behaviour and formats kogen's call sites depend on (for example exit codes and error types that kogen's `exitFor` maps, the configuration fields kogen reads, the messages and paths kogen prints or uses). Derive what kogen relies on from kogen's call sites in `cli/engine.go`, `cli/facts.go`, `cli/main.go`, `cli/native.go`, `cli/readiness.go` and `cli/readiness/readiness.go`.
- The suite references no other identifier of its own producer except named types that appear in the signatures or types of inventory identifiers (for example `sys.Error`, the result of `sys.AsError`). Exported identifiers of another Kogen dependency may appear only as fixtures the producer's API needs (for example `*sys.Session`, `*provider.Client`, `verify.Tools` in the kogen-build suite).
- Isolation in the same style as the producers' contract/ suites at the pinned versions (for example kogen-setup's `contract/README.md`, `main_test.go` and `helper_test.go`): a `TestMain` that removes inherited `GIT_*` and `KOGEN_*` variables, gives the process a HOME of its own and sets `GIT_CONFIG_GLOBAL=/dev/null` and `GIT_CONFIG_NOSYSTEM=1`; synthetic fixtures under `t.TempDir()` only; any model or sign-in traffic only to a loopback `httptest` server on a free port, never the network; no fixed port, no host path (nothing matching `/Users/<name>/`, `/home/<name>/` or `/var/folders/`) and no real user HOME; imports only the standard library and packages of Kogen dependency modules, never a `kogen/...` package (no private helpers such as `kogen/readiness` or `kogen/internal/testrelease`); no `t.Skip`/`Skipf`/`SkipNow`, no `time.Sleep`, no build constraint or OS-specific file name; deterministic, passing with `-count=1`, `-trimpath` and `-race`.
- `README.md` in the style of the producers' contract READMEs: what the suite pins, how it is isolated, how coverage was checked (the identifiers kogen's non-test code uses from this dependency were listed per dependency by type-checking kogen's non-test packages, as the inventory helper in `features/steps/k-consumes-kogen__inventory.js` does, and each is mapped to its tests), and an Inventory table with one row per inventory identifier, written in backticks exactly in the qualified form below, naming kogen's call-site file and the covering tests.

Qualified form: `pkg.Name` for package-level identifiers, `pkg.Type.Field` for struct fields and `pkg.Type.Method` for methods (pointer receivers without `*`), where `pkg` is the Go package name.

## Decisions
- One suite per Kogen dependency used by kogen's non-test code, in `cli/consumes/<module name>/`, so that the module's normal `go test ./...` runs them; the request's `consumes/kogen-build kogen-coordinator kogen-executor kogen-setup kogen-shaping kogen-verification kogen-loop/` names these seven directories (source: request)
- Each suite uses only its producer's public exported API, is isolated and deterministic like the contract/ suites (no network, no host paths, no private helpers), and asserts exactly what kogen relies on and nothing it does not use (source: request)
- How coverage was checked is stated per suite in its README by listing every identifier kogen's non-test code uses from that dependency, with the tests that cover it (source: request)
- No behaviour change, no new command, flag or option; go.mod and go.sum unchanged (source: request)
- Needs human evaluation at review: whether each suite matches the style of the producers' contract/ suites (the TestMain isolation of GIT_*/KOGEN_* variables, its own HOME and Git configuration, synthetic t.TempDir fixtures, the README structure with pinned items and an Inventory table naming call sites and covering tests); the isolation rules no step observes (no network, only loopback httptest servers on free ports, no fixed port, no real user HOME, no time.Sleep, determinism with -count=1 and -race); and whether each referenced identifier is covered by a meaningful assertion of what kogen relies on. No scenario claims these hold (source: request)
