# Retry transient provider stream failures

Slug: transient-stream-retry

Acceptance:

Extend the shared ChatGPT/SuperGrok Responses transport's existing bounded transient retry classification. Do not add a second retry loop in Shape, Build, Refine or Review. Replace immediate refusal of `server_is_overloaded` stream failures with the existing transient outcome. Also recognize the observed codeless SuperGrok message under the narrow rule below. Update GPT-8 in `spec/prose/08-chatgpt.md`, its specification scenarios and affected implementation tests to describe these cases explicitly.

The in-stream code allowlist retains `server_error`, `rate_limit_exceeded`, `subscription_sharing_usage_unavailable` and `subscription_sharing_user_unavailable`, and adds `server_is_overloaded`. These recognized codes use the existing retry for nested SSE `error`, flat SSE `error` and `response.failed` error objects on the shared Responses routes. A flat frame's `type: error` remains an event kind, not an error subtype.

The additional message rule is restricted to SuperGrok: code and error subtype must each be absent, null or the empty string, and message must equal `Internal error during token generation` exactly. This rule applies to the same stream error envelopes, not HTTP errors or `response.incomplete`. Explicit unknown codes, malformed codes, conflicting nonempty error subtypes, other messages, and the same codeless message on ChatGPT do not qualify. No substring, case-folding, generic type-only or catch-all retry is added. Existing non-transient classification still wins for usage limits, model/context/authentication errors and other refusals.

Every retry resends the unchanged complete logical request and discards failed partial output. Preserve three total transient attempts, 2 s then 8 s backoff, the entry-established fixed 1,800,000 ms monotonic budget (including credential/refresh/compatibility work), single-attempt behavior, prompt cancellation and all existing error/exit conventions. Exhaustion is `provider/unavailable` exit 4, with the last actual allowlisted provider diagnostics; codeless errors never acquire a fabricated code. Failed attempts retain separate unknown usage; successful usage is not invented or charged to failures. No tool from a failed stream executes, and already completed tools are not repeated. No paid fallback, provider/account/model switch, new authentication input or API key is added. OpenCode Go's non-stream adapter is unchanged.

The installed local-fake Build cases must prove both recovery inside the same Build and honest exhaustion: one completed shell edit runs once; failed partial shell output never runs; recovery goes through verification and fresh independent Review to a clean landed commit consuming approval. Exhaustion leaves the edit unlanded, HEAD/index/approval unchanged, with final safe diagnostics. Read approval optionally after execution: landing legitimately consumes it. Tests must not pin compiler chatter or assert that a landed Build retains approval.

- Keep this a transport fix, not staged Intents, context room (KOGEN-048), the Go migration, Studio, release or deployment. No scheduler or automatic Build resume is added. (source: request)
