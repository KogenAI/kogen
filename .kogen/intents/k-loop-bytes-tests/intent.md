# Pin Kogen's own request bytes, not the loop's

Slug: k-loop-bytes-tests
Model: not applicable — changes only what six Go tests compare; Kogen's runtime behavior, request bytes and state are unchanged
Acceptance:
- .kogen/intents/k-loop-bytes-tests/acceptance.feature
- features/steps/k_loop_bytes_tests_steps.js

This is a fix (repo kogen, request K-LOOP-BYTES-TESTS, Studio kogen issue 4ce98f12-b24a-452f-8088-33b3ca581519). Six Kogen tests compare exact request bytes or exact tool-definition text stored in Kogen (golden files, byte counts, SHA-256 digests) that include text the pinned kogen-loop renders. So every loop wording change turns them red, although it keeps the loop's documented contract (`cli/third_party/kogen-loop/docs/contract/loop-v1.md`). Two re-pins needed adaptation Builds for this: 1a3eb18 (K-REPIN-ADAPT) and af456d5 (K-REPIN-ADAPT-AF456D5). The six tests are `TestResearchRemovalDefaults` (cli), `TestDefinitionsMatchTheElixirDefinitions` (cli/agent), and `TestKRevodGatePartsUnchanged`, `TestNamedFeedbackCompatibility`, `TestContextExternalNativeBytes` and `TestKReviewRetryUnchangedValidRequests` (cli/build).

After this change these tests assert what Kogen owns and read what the loop owns from the pinned loop at test time. A contract-preserving loop change then lands with only the sync-script re-pin. The tests still fail when Kogen's own request content changes. Replaced: stored copies of loop-rendered text inside these tests' goldens, byte counts and digests. Not changed: Kogen's production code, prompts, tool definitions and the requests Kogen sends; `cli/third_party/kogen-loop/` and `cli/loop-pin.json` (protected); every configured check and its settings. No new command, flag, option, timeout, retry or limit.

## Decisions
- Ownership. Loop-owned: the definitions of the generic tools the pinned loop supplies (`shell`, `view_image`, `read_file`, `write_file`, `list_files`, `search_text`, `documentation`, as `tools.Definition` returns them) and the provider wire rendering the loop performs. Kogen-owned: its instructions (`cli/agent/prompts/`), roles, model and effort selection, every input message Kogen builds (Intent, authority, context, diagnostic, approvals, review material, source parts, reset handoffs, verification feedback), its own tool definitions (`cli/agent/defs.go`: finish, report_blocker, probe, propose_files, submit tools, shape_batch, worker_result), and which tools it offers, in which order and with which tool choice. (source: request)
- Each of the six tests keeps asserting all the Kogen-owned content it asserts today, exactly as it does now: bytes stay bytes, digests stay digests. Where it needs loop-owned text or rendering, it gets it from the pinned loop when the test runs. Examples: substitute `tools.Definition(name)` for a generic tool, normalize each generic tool definition to a placeholder before measuring or hashing, or render an expected request through the pinned `provider.Client.Body`. A stored golden, byte count or digest must not contain a generic tool definition, and must not pin request envelope fields that the loop renders and Kogen does not set (for the ChatGPT wire, for example `include`, `store`, `stream` and the key order). Kogen-set fields stay asserted: model, effort, instructions, input, tool list and order, Kogen tool definitions, tool choice and the presence of the cache identity. The executable proof covers the wording case. Goldens may be regenerated from the current tree under the new comparison, and their comments must say what they hold. (source: request)
- `TestDefinitionsMatchTheElixirDefinitions` keeps comparing every Kogen-owned definition with its golden. For each generic tool it checks that Kogen offers the pinned loop's definition unchanged. (source: request)
- `TestResearchRemovalDefaults` keeps all its subtests: window, cut, documentation defaults, no authority boundary, and the request measured as sent. Its plain-request comparison keeps Kogen's own tool definitions and the fixture's Kogen-supplied content in its golden. It already placeholders the documentation definition; it now treats every loop-owned definition the same way. (source: request)
- The four cli/build tests keep their other assertions unchanged: request counts, prefill, reset and read markers, the no-`on_demand` checks, the empty-source controls, feedback text, tool name lists, `"tool_choice":"auto"`, events and outcomes. Their goldens keep the Kogen-owned request content: instructions, input, Kogen tool definitions, tool order. (source: request)
- Proof, loop side: in a scratch copy of the working tree (never the Build's tree), the sentence `stdin is closed; stdout and stderr are combined.` in `cli/third_party/kogen-loop/tools/defs.go` becomes `Standard input is closed, and standard output and standard error are combined.`; all six tests then pass. Other tests that check the vendored copy itself (for example cli/loop_pin_test.go and the loop's own tests) may fail in that copy and are not part of this proof. (source: request)
- Proof, reviewer instructions: in another scratch copy, the sentence `You do not see the builder's conversation.` in `cli/agent/prompts/reviewer.md` becomes `The builder's conversation is not shown to you.`; TestKRevodGatePartsUnchanged, TestKReviewRetryUnchangedValidRequests and TestContextExternalNativeBytes then fail. (source: request)
- Proof, builder instructions: in another scratch copy, the sentence `Do not commit, push, stash, reset or switch branches; Kogen commits after verification and review.` in `cli/agent/prompts/builder.md` becomes `Do not commit, push, stash, reset or switch branches; Kogen makes the one commit after verification and review.`; TestNamedFeedbackCompatibility and TestContextExternalNativeBytes then fail. (source: request)
- Proof, Kogen tool definition: in another scratch copy, `Say the implementation is complete.` in `cli/agent/defs.go` becomes `State that the implementation is complete.`; TestDefinitionsMatchTheElixirDefinitions and TestResearchRemovalDefaults then fail. (source: request)
- Scope stays with tests that compare stored loop text. Tests that follow a changed documented contract, like the 1a3eb18 shell yielding adaptations (TestSilentBuildShellNotStopped, TestSilentReviewShellNotStopped, TestNativeConformance and the building scenario), are not changed. (source: request)
