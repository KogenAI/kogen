# Make release archive modes explicit

Slug: release-archive-public-modes
Model: not applicable — this is a stateless normalization of a disposable packaging payload, not a new lifecycle or state machine
Acceptance:
- .kogen/intents/release-archive-public-modes/acceptance.feature
- features/steps/release_archive_public_modes_steps.js
- features/steps/release_archive_public_modes.py

Make the public application payload produced by `sh packaging/package.sh` explicitly readable/traversable by other users: regular non-executable files 0644, regular executable files 0755, directories 0755, including the archive's top-level directory. Apply this only to the disposable assembled payload before archiving. Replace inherited umask/copied-file permissions, not payload contents or executable classification. Preserve paths, bytes, filesystem types and symlink targets; do not follow symlinks when normalizing. Any execute bit on an assembled regular file means executable. Do not make data executable or strip executability from tools. A caller umask alone is insufficient because copied owner-only files/directories also need normalization.

The regression runs the real packaging script twice, under umask 077 and 022, with owner-only copied assets in an isolated source copy. Real npm and tar are observed through delegating PATH wrappers, never mocked: npm's output tree records its original executable distinctions, and the pre-tar staging snapshot records generated bytes. Independent copied-source expectations and npm output expectations are compared with every application archive member. An owner-only copied executable, non-executable, directory and symlink to a private outside-stage sentinel exercise the distinction and no-follow boundary.

Every real npm ci in these rows runs with explicit --offline and isolated configuration. Preparation is local only: once per combined packaging lockfile identity, qualify only lock-pinned SHA-512 content blobs read from ~/.npm/_cacache, and atomically publish a test-owned content-only seed at /tmp/kogen-public-npm-<uid>/<identity>. The identity is SHA-256 of the canonical mapping from the two packaging lockfile paths to their exact byte hashes. This private 0700, current-uid-owned store and its lock files are deliberately retained prepared input across disposable readiness/verification directories, not user npm cache state. Preparation copies neither request index entries nor auth/config/credentials, and never invokes npm against the donor cache. Selected donor blob bytes/modes/mtime and donor index-directory mtime are checked across preparation. Existing seeds are completely revalidated, never silently repaired or downloaded. Missing or invalid content is an explicit offline prerequisite failure, not network fallback. One nonblocking preparation lock prevents concurrent duplicate publication; contention stops rather than retries.

Each pass copies the qualified seed's _cacache into its disposable test-owned npm cache, uses it for both rows, and compares complete cache manifests (paths, bytes, types and modes) after every npm call and at cleanup, on success and failure. npm logs are disabled and routed outside the cache; temporary npm homes/configuration, Go cache, outputs and working cache are removed with surfaced removal failures. Seed preservation is also checked. Offline controls independently exercise both bundles under both umasks, seed reuse with an unavailable donor, incomplete preparation cleanup, corrupt-seed rejection and real npm ENOTCACHED for removed yargs-parser content. This changes only regression preparation/delegation, not real package.sh, npm installation semantics, or tar behavior; ordinary configured setup/check commands remain unchanged.

Update current INS-2 in `spec/prose/10-install-and-uninstall.md` to own these mode guarantees. Add maintained regression coverage to the current install feature/steps or ordinary packaging checks, reusing this regression where practical rather than creating a second packaging matrix. The new Intent is not the sole long-term specification owner. Existing install scenarios and configured checks remain intact. Do not edit historical Intents, `.kogen/project.yaml`, installer behavior, version/identity algorithms, frozen prefixes, credentials, account homes, receipts, real caches or source permissions. The sole donor access exception is read-only qualification of the selected public lock-pinned cache content described above. No push, release, approval or Build is part of preparation. Existing release/platform qualification requirements remain; a local readiness run is not both-platform release qualification.
