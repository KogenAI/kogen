# Bound native Shape repository navigation

Slug: shape-context-index
Model: not applicable — this replaces generated navigation data, without adding or changing conversation, custody, approval or readiness state transitions
Acceptance:
- .kogen/intents/shape-context-index/acceptance.feature
- features/steps/shape_context_index_steps.js

Replace native Shape's eager whole-repository `Context index: <JSON>` in its mandatory initial user message with a fixed-shape `Context navigation: <JSON>` descriptor. Repository growth must no longer grow that generated mandatory navigation payload. This is not a promise that every request fits. Exact authority can still exceed the unchanged guard and must stop honestly.

## Decisions
- Keep exact request, Q&A, README, testing rules, configured commands, protection patterns/matches and automatic baseline in full, in their existing authority position. Do not strip a literal index, path list or other text supplied inside the caller's request. Only Kogen's generated repository inventory is replaced. (source: request)
- Supply navigation, not an automatically chosen subset or summary of repository facts. Shape discovers relevant files itself with existing native tools; receiving a descriptor does not satisfy inspection or documentation gates. No new tool, setting, pagination protocol, external service or automatic Intent splitting is needed. (source: request)
- Keep native Shape's existing contract content-block separation. Its generated dynamic block is exactly `Context navigation: ` followed by single-line JSON and a newline. The JSON has exactly `root`, `revision` and `retrieval`. `root` is the resolved checkout root; `revision` has exactly `head` and `tree`, with the existing `Kogen.ShapeContext.revision/1` semantics (including nonignored candidate changes, excluding `.kogen/local`). `retrieval` is exactly `read_file exact bytes and line ranges; list_files directories; search_text exact signatures`. Do not include entries, directories, signatures, counts, path inventories, per-file hashes/sizes/ownership, source excerpts or relocated copies of those inventories anywhere else in the mandatory Shape prompt. Descriptor size depends on root/revision, not repository cardinality or source content. (source: request)
- Use this descriptor on the initial native `kogen intent shape <slug> <file|->` invocation and the reconstructed invocation after product answers. Existing in-process working windows retain it alongside complete authority; they must not restore the inventory. Do not automatically rewrite caller originals or prior custody. (source: request)
- Preserve full rendered JSON measurement, the inclusive 524288 UTF-8 byte ceiling and 131072-token reserve. Measure policy, tools, envelopes, cache controls and complete replay, not the descriptor alone. Keep safe-boundary resets, exact unsent custody and `candidate/context_budget_exceeded` for irreducible material. No larger ceiling, weaker reserve, clipping, summarizer, automatic split or retry-as-recovery. (source: request)
- Leave Refine's frozen-original context index and explicit excerpt behavior unchanged. This change is confined to native Shape's generated mandatory inventory; it does not change providers, caching, Studio, workers, release/deployment, Go migration implementation or periodic monitoring. Existing native discovery/documentation evidence, source provenance, readiness identity and independent review remain required. (source: request)

Implementation boundaries: change the native Shape context construction in `lib/kogen/shape.ex` and the navigation renderer in `lib/kogen/shape_context.ex` as needed; do not merely hide the old JSON while still eagerly reading/hashing/scanning every source body to build it. Reuse revision identity and retrieval tools. No production abstraction solely for tests is needed. Keep Refine's existing inventory API/semantics. Update the Shape-specific text in README, `docs/configuration.md`, `spec/prose/02-shaping.md` and affected maintained tests/scenarios; supersede only assertions that require the removed native Shape inventory. Preserve useful Refine, excerpt and safety coverage. Required implementation paths are not protected by this Intent's baseline; the proposed acceptance driver remains independent of implementation tests and must not be changed by Build.

The local acceptance driver uses the repository's installed-release fixture and loopback scripted provider. The feature's source packet is consumed verbatim as the native request and checked against private source provenance. Historical measurements are inputs, not assertions of access to the operator's archive. A generated 1800-file/deep-directory/declaration corpus reproduces inventory-driven pressure without requiring the private archive or a live provider. An additional 40-read journey exercises a completed-boundary working-window reset. An irreducible request adds 600000 literal bytes to the exact source packet and must remain unsent. Each successful journey attempts submission before inspection, attempts a fabricated documentation citation after inspection, then publishes a genuinely executed local fixture scenario; navigation must not bypass either gate. The Q&A journey retains an actual answered product question. No test reads operator credentials or uses paid inference.
