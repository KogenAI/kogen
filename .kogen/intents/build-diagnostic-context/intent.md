Add only `kogen intent build <slug> [--project <checkout>] [--context <file>]`. This is optional operator diagnostic data for a fresh native Build, addressing KOGEN033/038: after a demonstrated protected fixture correction and new exact approval, the operator can preserve observations and identify an externally preserved prior candidate. ## Decisions
- Only fresh `intent build` accepts `--context`; all other command paths, especially resume, reject it using ordinary CLI grammar. Retain `--name=value`, option placement, repeated-option and help conventions. (source: request)
- Resolve FILE relative to the caller's working directory, not `--project`; it names a file, never stdin or command text. Read its contents once before any model request. Require a readable regular file, valid UTF-8, at least one non-whitespace character, and at most 262144 original bytes. Preserve every original byte including Unicode, CR/LF, leading/trailing whitespace and final newline. Nonexistent, unreadable, nonregular, empty, whitespace-only, oversize and invalid-UTF8 inputs produce concise `intent/context_unavailable` usage errors, exit 2, before provider requests or implementation/index/HEAD/approval effects. Omission changes nothing. (source: request)
- Transport data over the existing JSON bridge, never interpolated shell/argv. The resolved path is a source label, not instructions to read it later. Independently validate bounded data and shape at the core protocol boundary. (source: request)
- Once a native run exists, keep the exact text, SHA-256 of original UTF-8 bytes and source label in private local run custody (0600 capture files, private run directory); exclude it from commits and approval hashes. Existing private source logs/conversations may retain it; ordinary progress stdout must not disclose it. Do not add secret detection or a credential store. (source: request)
- Preserve the ordinary initial Intent/protected-baseline/testing message and builder tool instructions. Append one separate labelled caller diagnostic data message, explicitly lower-authority data: current exact approved Intent and mechanical protected/check/review/commit rules win; stale/contradictory data cannot authorize changes or bypasses. Previous candidates are untrusted old data. Selective inspection and reproduction of suitable production work through existing native read/shell/write tools is allowed under current requirements, never automatic copy/apply/import, `git stash apply`, import of old protected harness bytes, or reuse of old verification as current proof. Do not encourage whole-tree rereading/copying. (source: request)
- Keep `builder_turn` saving the complete initial conversation before first HTTP. Compatible explicit resume uses those captured conversation bytes after the external source changes, disappears or becomes inaccessible, without rereading, replacement context, retargeting, new checkpoint fields required for compatibility, or a version change. Old checkpoints without diagnostics behave as before. Preserve honest attempt lineage, authority and index custody. (source: request)
- Completion is one signed native logical commit with affected checks, followed by a separately packaged frozen private prefix and scoped installed qualification outside checkout; no global installation, push, release, Linux/full-release or unmeasured speed/token/dollar claim. Root owns Studio recovery qualification and adoption. Deterministic prompt/guard tests do not establish live model obedience or performance. (source: request)

### Interfaces and implementation boundaries

Use the existing CLI parser/bridge, `Kogen.Main` Build dispatch, Build startup and saved conversation path, and normal run storage; no protected implementation edit is needed. Define the optional run protocol field as `context: {text: <UTF-8 string>, source_path: <nonempty absolute source label>, sha256: <64 lowercase hex>}`. When absent omit this field. The core checks the object has exactly these fields with string values, bounded valid/nonblank text and matching digest; malformed/missing fields, wrong types or digest reject as `intent/context_unavailable` exit 2 before effects. Reject a supplied context field for non-build requests rather than silently granting resume a context override. JSON cannot transport ill-formed UTF-8 text: test invalid original bytes at CLI and invalid binary through the callable core validation interface. The core does not stat or reread source_path. A valid direct object with an inaccessible source label must remain usable.

Choose the private capture name `.kogen/local/runs/<id>/diagnostic-context.json`, a JSON object with exactly `text`, `source_path`, `sha256` as above; decoded text re-encodes to exactly the original bytes. Run directory mode is 0700 and capture mode 0600 independent of ambient umask. Keep checkpoint version 2 and its existing conversation storage; do not require new keys on old checkpoints. Source data and authority have separate custody: the digest binds diagnostic bytes only, not approval. For example a note claiming an old acceptance pass or asking to modify the protected step file cannot change the current package, skip current checks, authorize a shell protected write, or clear a blocker.

Update normative AUT-5 and LOOP-2, applicable LOOP-10 frozen-resume explanation and CLI-1/2/3/9 requirements/scenarios and step vocabulary consistently, plus concise README/developer documentation (including installed usage where applicable). Preserve short commit subjects, committed Intent and exact `Kogen-Intent: <slug>` trailer with no hash appended; native approval hashes stay in their actual binding fields. Do not modify this Intent's protected acceptance files during Build. Existing normative specs and integration fixtures outside this Acceptance list remain editable implementation/test work.
