Add one shared `view_image(path)` tool to native Shape, Build and the existing fresh independent Review. Replace the text-only limitation for this explicit image operation, not for shell, read_file or browser captures. Supply frozen local PNG bytes as Responses typed function output. No browser capture, hosted service, Files API, image generation, new agent/critic/stage, provider/model/effort change, global image cache, screenshot sweep or automatic design approval. Ordinary non-image work stays unchanged. Update README, usage/testing guidance and affected maintained prose/Gherkin/Quint specifications to distinguish this capability from text-only tools; retain the distinct `cd spec && sh check.sh` gate alongside configured checks.

## Decisions
- Use one read-only tool with one required string argument `path`, resolved like read_file (repository-relative or explicitly selected absolute local path). No scanning or capture. Missing/expired artifacts get an honest actionable tool error. (source: request)
- Support only static, non-interlaced 8-bit RGB PNG, matching the demonstrated 384x256 RGB PNG controls. Each invocation selects one image; accept 1..131072 original bytes inclusive and width/height 1..2048 inclusive. Do not transcode, resize or claim additional formats/detail guarantees. Multiple invocations are permitted only subject to the complete request budget; there is no new configurable limit or total-run cap. (source: request)
- Freeze selected bytes once and preserve private replay/checkpoint custody and fresh reviewer ownership; filenames, hashes and successful capture are not visual assessment. (source: request)
- Keep exact approval, protected contracts, external verification and exact-final-tree commit eligibility. Visual observations cannot override failed, unrun, stale or unknown checks, grant writes, transfer approval, auto-refine or clear blockers. (source: request)

### Tool and evidence contract

`Kogen.Tools.defs(["view_image"])` describes this same tool in the three existing native tool loops. `Kogen.Tools.run("view_image", %{"path" => path}, ctx)` returns an ordinary bounded `error: ...` string for invalid arguments, absent/unreadable/nonregular artifacts, unsupported PNG encoding, malformed PNG data or exceeded image bounds. Name the failed fact, selected path where available, implemented limits and an ordinary external image-preparation/capture handoff. Never mark such a result as pixels viewed. Validate PNG signature, chunk framing/CRC, required IHDR/IDAT/IEND and bounded decompressed RGB scanline data (including legal filters), not just its filename or signature. Refuse animation and unsupported encodings. Validation and decompression must themselves be bounded by the declared dimensions/scanline size; a corrupt/compressed bomb must not evade the limits.

On success return a Responses content array in this order: `[{"type":"input_text","text": JSON metadata}, {"type":"input_image","image_url":"data:image/png;base64,<exact selected bytes>"}]`. Metadata is a JSON object with `version: 1`, `path`, `sha256` (lowercase SHA-256 of original bytes), `bytes`, `format: "png"`, `width`, `height`, `read_candidate`, `capture_candidate`, `route`, `viewport`, `fixture_state`. `read_candidate` identifies the actual native repository candidate at read time when established, otherwise `"UNKNOWN"`. The path-only API cannot establish capture provenance: the last five capture/context fields other than read_candidate remain `"UNKNOWN"` unless separately established evidence actually supplies them. Never infer route, viewport, fixture state or capture-candidate binding from a filename or the current checkout. Model-authored contextual claims stay labelled observations, not native facts. No `detail` setting or resolution guarantee is introduced; provider preprocessing may change resolution.

`Kogen.Shape.output(call, result)` preserves this array as `function_call_output.output`, with the exact call_id. Shared text limiting (`Tools.cut`) must pass typed results through unchanged, while retaining existing caps for text. All native consumers must retain the array: never stringify it, route data URLs through text caps, silently clip it, substitute paths/base64 text, or use hosted URLs. Preserve assistant item order, phase, encrypted reasoning, other supported replay fields and complete parallel tool pairs. Unsupported-cache fallback may remove only the existing cache controls; the image content and replay remain semantically identical (JSON object key order is immaterial, arrays/strings are not).

Freeze the successful output in the existing conversation at read time. Subsequent requests, local windows and safe checkpoint/resume use those exact bytes even if the selected path changes or is deleted. Build/Review archives and active checkpoints retain the full ordered typed output with their existing hash links, source/approval/candidate binding, owner, findings and progress. Never reread the selected filename to reconstruct an earlier output or replay a tool to manufacture a pair. Missing/altered/unsafe referenced custody remains an actionable refusal before inference/mutation. Keep version-3 checkpoint validation and existing legacy/uncertain-tool/uncertain-commit refusals. No persistent Shape resume or Shape working-window redesign is added: its in-memory conversation freezes pixels until the operation ends.

Measure the complete actual serialized outbound JSON including typed envelopes, base64 overhead, policy/developer content, tools, cache controls and replay via `Kogen.WorkingContext.measure(body_map)`: ceiling **524288 UTF-8 bytes**, equality fits, reserve **131072 tokens**. A file-size bound is not sufficient. Preserve delivered Build/Review completed-boundary window reduction, newest complete exchange, exact mandatory authority and private full archives. For image-bearing Shape requests add only the minimal complete-request guard (no reset). Irreducible image-bearing requests stop as `candidate/context_budget_exceeded` before sending the oversized request, without repeated identical retries, text substitution, silent truncation, automatic splitting, scope/approval changes or a raised budget. Report owner, measured/mandatory bytes, ceiling, reserve and retained custody where applicable, plus actionable external image preparation or ordinary Refine/new-approval guidance. Provider failures below the proxy stay honest failures.

Independent Review starts its existing fresh conversation without builder transcript/reasoning or builder visual judgments masquerading as inspection. It has its own view_image invocation and typed pixels. Evidence is reusable only while its candidate/capture provenance remains relevant; where that cannot be established obtain fresh capture through existing means or report the external handoff. No mandatory image invocation for unrelated/nonvisual work is introduced.

Keep compact telemetry bounded and factual. In existing Shape events.ndjson and Build/Review log.jsonl record `image_read` facts on successful selection (`owner`, `call_id`, artifact metadata, `status: "read"`) and `image_delivery` facts per logical image-bearing request (`owner`, `call_id`, `sha256`, `status`, request identity and nullable response identity). Use delivery status `completed` only for a validated completed provider response to that request, `failed` for explicit rejection and `unknown` for an uncertain transport outcome. A successful read is not completed delivery. A completed request is not the model's explicit visual observations. Observations remain identifiable assistant content in private replay, with their candidate/provenance limitations, not an inferred success flag. Logs/console must not contain raw data URLs, base64 pixels, credentials or opaque reasoning; individual image events are at most 8192 UTF-8 bytes (bound long identity/path text explicitly rather than logging raw payloads). Raw retained image/history/checkpoint custody uses 0700 directories/0600 files even under umask 022; no public original screenshots or private human originals in fixtures or commits.

Real UI assessment must still name the pages, states and viewports actually inspected and retain final candidate-bound evidence. A hash proves identity, not that the intended candidate was served. DOM/action/accessibility/layout checks, capture/export, completed pixel delivery, explicit fallible visual observations and required human/designer decisions remain distinct. When native image input is unavailable/refused, retain a truthful outside pixel-review handoff. Local scripted-provider tests qualify plumbing and custody, not actual pixel interpretation or visual approval.
