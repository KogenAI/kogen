# Resume stopped Builds without rebuilding

Slug: resume-failed-builds
Model: .kogen/intents/resume-failed-builds/model.qnt invariants=SafeCommit,NoReplay,SameReviewer,GuardedResume seed=19 samples=1000 steps=40
Acceptance:
- .kogen/intents/resume-failed-builds/acceptance.feature
- features/steps/resume_failed_builds_steps.js

Add `kogen intent resume <build-id> [--project <checkout>]`: explicitly continue a checkpoint-capable failed/interrupted Build in the same checkout, preserving its candidate, completed work and relevant conversation. Replace the current terminal-only treatment of recoverable stops, not the native Build/review engine. Extend the existing owners: `Kogen.Build`, `Review`, `Run`, `Snapshot`, `Lock`, the CLI/bridge and their maintained tests. Align CLI/help/README and the affected maintained prose/Gherkin/Quint specification. No protected configuration edit is needed.

New Builds publish versioned local `.kogen/local/runs/<build-id>/checkpoint.json` atomically, with durable references/state sufficient for continuation: repository/worktree identity, original HEAD and index, exact approval and complete protected baseline/configuration, candidate contents/modes, excluded Intent custody, phase and repair owner, builder/reviewer replay input including tool results, completed verification/review provenance, pending request/tool/commit boundaries and known cumulative usage/counters. Use JSON `version: 1`; refuse incompatible versions. Save before requests and side effects and after durable completion, not only in handled exception paths. Never serialize credentials, tokens, auth headers or the caller's entire environment. Capped diagnostic logs alone are not a complete conversation checkpoint.

Acquire the ordinary repository Build lock first; reject a live owner with existing `environment/build_running` semantics. Before model calls or project/index/HEAD mutations, validate checkpoint shape/compatibility and all saved identity, authority, contents and index-custody facts. Refuse moved HEAD, another checkout (even a copied repository), changed approval, changed helpers/checks/models/configuration/protected baseline, candidate drift/unrelated edits and newly staged changes. Original staged owned acceptance files allowed by ordinary Build preflight remain valid custody, not newly staged drift. Check additions/deletions/modes as well as bytes. Refusal must preserve project files, index, HEAD, approval and prior evidence; do not stash/reset/checkout/discard or repair/reapprove automatically. Lock acquisition and local refusal evidence are not destructive recovery.

Use `candidate/resume_refused: <reason>` (exit 1) for damaged/incompatible/unsafe state and `candidate/resume_unsupported: <reason>` (exit 1) for absent/legacy state; include build ID, the mismatched fact/path and an actionable inspect/correct/fresh-approval instruction as applicable. Unknown or missing checkpoints must not fabricate conversations or green evidence. A protected-contract blocker remains blocked and requires normal correction and fresh approval. `already landed` is an explicit successful no-op (exit 0), with the existing commit identified and no provider call or second commit. Detect it before treating the expected landed HEAD and consumed approval as ordinary drift, but never use this exception to accept an unrelated HEAD.

Continue the saved phase: pre-review failures stay with the saved builder; review failures stay with the same independent review/fix conversation, never a new builder or critic. Preserve the recorded replay input prefix; append honest recovery/verification context when needed. Pending verification and reviewer repairs get external verification; failures return to that same owner. Reuse completed green/review evidence only if complete provenance still binds the exact relevant tree and approved baseline/commands/model. Re-run invalid/incomplete evidence, but impose no universal second green pass. A completed unchanged green pass followed by provider review failure needs no duplicate check pass.

An in-flight request is not evidence that tools executed. Persist response/tool execution boundaries and results so completed effects are not replayed. If death leaves execution/candidate provenance uncertain, either refuse explicitly with the uncertainty and inspection instructions, or conservatively reinspect/reverify and continue without replaying possibly executed effects or discarding edits. This includes shell effects outside tracked source. A death inside ordinary `git commit` must reconcile an exact already-created commit or safely refuse, never invoke a second commit. Honor normal hooks/signing, parent and final exact-tree checks. Restore the original user index on handled non-landed outcomes; recover abrupt index custody only when proven safe, otherwise refuse without overwriting it.

Preserve the original failed attempt's result and artifacts byte-for-byte; logs may append but never truncate. Record each resumed attempt in a new run, its parent/root lineage and per-attempt outcome, plus cumulative known usage/pass/review/repair counters. Print resumed lineage including the requested ID. A resumed landed `result.json` uses the existing `usage` fields for cumulative known usage; retain per-attempt data as well. Count only reported usage, marking failed/incomplete request usage unknown rather than inventing tokens. Accumulate measured active intervals; never count stopped downtime as active model time or relabel total elapsed as model work.

Authorization is Almir's 19 October 2026 Studio/Kogen request, permitting delegated inspection/approval and one signed local commit per complete repair, not push/release/deployment. Preserve historical Skeptic.bot Builds `1de86a76` and `fca63cc0` and their stashes as evidence, not migration targets. Keep current `gpt-6.1-sol` shaping/review high and building medium. No service, scheduler, planner, automatic contract repair/reapproval, provider switch, indefinite retry, new product hard limits or generic workflow framework.

## Decisions
- Use explicit `kogen intent resume <build-id>` with the ordinary `--project` option, no automatic restart. (source: request)
- Continue the existing candidate and relevant independent conversation; conservative uncertainty refusal/reinspection is acceptable. (source: request)
- Refuse unsafe drift non-destructively and explain legacy/no-checkpoint and already-landed outcomes clearly. (source: request)
- Preserve previous attempts and expose resumed lineage and honest cumulative accounting. (source: request)
- Keep historical runs/stashes untouched and retain ordinary hooks, signing and exact-tree commit safeguards. (source: request)
