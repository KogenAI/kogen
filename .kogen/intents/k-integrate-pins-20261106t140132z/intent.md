**What changes in kogen.**
1. Product: readiness's models line (`cli/readiness/readiness.go`, the report that ends `kogen init`). Today it takes the roles from `ParseConfig`/`ReadableConfig` of `.kogen/project.yaml`, which now always give the defaults, so a claude-code-only project gets `fail models - shape: chatgpt has no stored login; build: chatgpt has no stored login; review: chatgpt has no stored login` and `  fix: kogen provider login chatgpt`. The models line instead examines the roles of `project.LoadConfig(root)` (defaults < `.kogen/models.yaml` < `.kogen/local/models.yaml`), with its existing wording, order, login checks and fix list otherwise unchanged. The config line keeps validating `.kogen/project.yaml` with `ParseConfig` as now. When `LoadConfig` refuses, the models line is a fail line whose detail is the refusal's lines joined by `; ` (its detail when it has no lines), prefixed by the repository-relative path of the file it names and `: `, and whose fix is `edit <that path>`. A project without `.kogen/models.yaml` (for example one initialized in a repository without commits) keeps the default lineup and its chatgpt line, which is correct there.
