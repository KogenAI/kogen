# Shorten Go checks with bounded test concurrency

Slug: kogen-check-time
Model: not applicable — this changes scheduling of existing independent tests, not product state or lifecycle rules
Acceptance:
- .kogen/intents/kogen-check-time/acceptance.feature
- features/steps/kogen_check_time_steps.js
- features/steps/go_driver_support.js

Reduce the elapsed time of Kogen's uncached, race-checked Go check on current main `687f140700426b3b4ad3e3eae7f1d854762dad31`. Deliver the smallest investigated test-only slice: allow the six existing expensive `kogen/build` tests listed in acceptance to run concurrently using Go's existing test scheduler. Their bodies, assertions, subtests, fixtures and cleanup remain unchanged except for a leading `t.Parallel()` in each top-level test. All other CLI inputs remain byte-identical. This deliberately does NOT adopt the external draft's 340-test parallelization or production temporary-path refactor. `shape` remains serial. Its runtime limits the possible whole-check saving; measure that limit rather than promising the external draft's speedup.

The implementation is six scheduling annotations in `cli/build/context_test.go`, `cli/build/recover_test.go`, `cli/build/resume_test.go` and `cli/build/review_test.go`, plus the measurement report described below. Do not modify production code, test fixtures, other tests, configured commands, suite selection, packaging, providers or project configuration. No prerequisite protected edit is needed for this slice. If evidence disproves its useful whole-check saving, report the actual result; do not silently broaden the implementation or weaken the measurement gate.

Use independent disposable copies of baseline `687f140700426b3b4ad3e3eae7f1d854762dad31` and final CLI inputs on the same host, toolchain and recorded environment. Dependencies/tools must already be installed; report preparation separately. In each copy run, from `cli/`, exactly `go test -race -count=1 -json ./...`. This is the configured Go check with machine-readable reporting, not different coverage. Use default parallelism: no `-parallel`, `-p`, `-run`, `-short`, result caching, test filters or tuning between variants. Record command wall time using a monotonic clock around the entire Go process, including compilation, not summed per-test elapsed values. Record UTC start, load averages before and after, host identity/OS/architecture/CPU count, tool versions and the explicit non-secret environment allowlist enforced by acceptance. Do not manufacture a quiet host by cancelling unrelated work. If the host cannot supply comparable observations, retain the limitation and stop rather than call incomparable numbers a pass.

Acceptance requires one comparable successful pair with a strictly smaller observed final wall time. No minimum percentage or statistical/general performance guarantee is claimed. This is a one-host observation, not a flake-rate estimate or Linux qualification.

Report schema (all values are observations, never invented):
- Root: `version: 1`, `baselineRevision` as above, nonblank `preparation` describing tool/dependency preparation and concurrent work, and `baseline`/`final` objects.
- Each observation: `cliSha256`, `command` (the exact argv array), `cwd: "cli"`, `host: {id, os, arch, cpus}`, `tools: {go, git, node, python}` containing full version strings, `environment` containing exactly the allowlisted keys used by the observer (unset is JSON null), `startedAt` (UTC ISO timestamp), `loadBefore` and `loadAfter` (three load averages each), positive `elapsedSeconds`, `status: 0`, `packages` (sorted exact array of the nine package names in acceptance), `tests: {passed, failed: 0, skipped: 0, inventorySha256}`, and `raw: {stdout: {path, sha256}, stderr: {path, sha256}}`. Raw paths are private absolute regular-file locations, not credentials or a reference to the external draft.
- The inventory hash is SHA-256 of sorted `Package + NUL + Test + LF` rows, once for every completed passing top-level test AND subtest in the raw Go JSON. Any duplicate, missing terminal event, failure or skip invalidates an observation. Baseline/final passing counts and hashes must agree. Package completion must also be complete and successful. Review checks this against raw output; acceptance also directly runs the six changed tests and checks every reported subtest.
- CLI identity is SHA-256 of sorted `repository-relative-path + NUL + sha256(file bytes) + LF` rows for all Git-listed tracked/nonignored-untracked CLI files, deduplicated. The frozen baseline has 331 files and digest `b1ab0f3faccc277419dda2ec444a4398178c4dbf7a39e84508694edaad4793b8`. The acceptance harness checks the final CLI inputs against this exact baseline after removing only the six allowed leading scheduling annotations. The final observation must bind the actual unnormalized CLI digest. This narrow source lock prevents a speedup by deleting assertions/tests, shrinking fixtures or altering production behavior; it is not a universal environment-equivalence or safe-reuse theorem.

Native Build must still perform ALL normal setup, acceptance and configured checks on its fresh exact candidate, then fresh independent Review and changed-final-tree verification. A measurement report never exempts those executions. Run `sh test/suite.sh` once against final executable inputs before delivery, retaining its complete deterministic-layer results; reuse an already valid run of those exact inputs rather than redoing it for report-only prose edits. Do not present native macOS delivery as a qualified release: README's Linux, installed real-use and supported-platform release gates remain separate and unchanged.
