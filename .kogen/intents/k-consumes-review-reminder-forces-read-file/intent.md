# Accept forced read_file reminders in strand test

Slug: k-consumes-review-reminder-forces-read-file
Model: not applicable — a test-only change to how one consumer contract test recognises the reviewer's forced reminder; no product state changes
Acceptance:
- .kogen/intents/k-consumes-review-reminder-forces-read-file/acceptance.feature
- features/steps/k-consumes-review-reminder-forces-read-file__steps.js

kogen-review's candidate review-reminder-reads-unread-parts (Build c2e401c0, 3c28d26a) changes the reviewer's reminder on purpose: after a turn with no tool call, while pinned parts are still unread, the reminder request forces read_file instead of submit_review, and forces submit_review only once every pinned part has been read. kogen's TestKReviewVerdictStrandPinnedResume in cli/buildprogram/k_review_verdict_strand_test.go encodes the old contract: it counts only requests whose tool_choice names submit_review as the forced reminder, so kogen-review's consumer contract check fails with `k_review_verdict_strand_test.go:221: review 1's conversation has no request that names submit_review as its tool choice`.

The test must accept the forced reminder as either a request whose tool_choice names submit_review, or one whose tool_choice names read_file while that review has unread pinned parts, so that it passes with kogen-review both before and after the candidate. Every other assertion of the test stays unchanged. Where an assertion inspects "the forced request", it applies to the last forced reminder of either kind in that conversation. Those assertions are: review 2's last forced request carries the working-window reset, the forced_tool_not_called provider faults, the review_invalid stop after the automatic retry is spent, and the fresh resumed review that is refused, approves and lands. When a reviewer conversation has no forced reminder, the test's failure message changes to the wording in the Decisions below; it replaces the old submit_review-only message.

No other test in this repository compares tool_choice with the forced submit_review value, so no other test changes. No non-test code changes. After the change, run the package tests: `go test ./buildprogram` in `cli`.

## Decisions
- TestKReviewVerdictStrandPinnedResume counts a reviewer request as its review's forced reminder when its tool_choice equals the existing forcedSubmit value {"type":"function","name":"submit_review"}, or equals {"type":"function","name":"read_file"} while that review has at least one pinned part file under review-source/<review>-<green tree>/ of the stopped run that the request does not show as delivered by a completed read_file in its window, a native prefill message, or a current reset handoff that does not list it as unread (decision: D1, round 1) (constraint: Every other assertion of the test stays unchanged) (constraint: The working-window reset assertion applies to review 2's last forced reminder of either kind) (evidence: cli/buildprogram/k_review_verdict_strand_test.go; cli/buildprogram/review_delivery_test.go; cli/buildprogram/k_reviewretry_test.go) (source: request)
- When a reviewer conversation has no forced reminder the test fails with the message review %d's conversation has no forced reminder: no request names submit_review, or read_file while pinned parts are unread, as its tool choice (decision: D2, round 1) (constraint: The message names the review number and replaces the old submit_review-only message) (evidence: cli/buildprogram/k_review_verdict_strand_test.go) (assumption: the failure wording is chosen by this shaping; the request only requires that the test accept either forced reminder) (source: request)
- Only TestKReviewVerdictStrandPinnedResume changes: it holds the repository's only tool_choice comparison with the forced submit_review value; no non-test code and no other test changes (decision: D3, round 1) (constraint: Changes stay in _test.go files of cli/buildprogram) (evidence: cli/buildprogram/k_review_verdict_strand_test.go; cli/buildprogram/k_reviewretry_test.go) (source: request)
