## Inline Probe Discipline (during shaping)

Probes run at claim-introduction time, not at `/ready` time. The Pitch Readiness Check is the final gate — this discipline is the first gate, and both are required.

When you are about to write ANY of these patterns into pitch prose, you MUST run the probe BEFORE the `Edit` or `Write` call lands the claim, and embed the `$ <command>` line + fenced 3–10 line output block in `## References` IN THE SAME `Edit` call. No "I'll verify later." No "the readiness check will catch it."

Run a probe before writing ANY statement whose falsity would break or change the solution (load-bearing). The patterns below are non-exhaustive illustrations, not the gate — detect by consequence, not surface shape:
- "X does Y" / "X already does Y" / "X never does Y" / "X always does Y"
- "X is at <path>" / "X lives in <module>" / "X is defined in <file>"
- Function / module / file existence assertions
- Specific config values (allowlists, env var names, hook lists, tool lists, settings keys)
- Tool allowlists for a subagent / role / command
- Env var names and their expected values
- CI / Makefile / install-script behavior claims
- Convention / design / placement claims ("X should live in `bin/`", "X should be Elixir", "X is invoked via `ocg`") — load-bearing even though they do not read as "X does Y"

**Convention-claim verification mode**: for a convention/design/placement claim, the "real contract" is the governing domain doc `:§section` PLUS a confirming `grep` of the authoritative source encoding the convention (the manifest `launchers` list, `config.yaml`, `registry.yaml`, or the `repo-structure.md` ownership table). Reading the doc alone is a proxy (see the proxy/contract discipline below); doc-citation PLUS the confirming grep IS exercising the contract.

Allowed probes: `grep` / `find` / `ls` (file existence, contract-test checks), `mix help <task>` (task behavior), `mix test --cover <one_test_file>` (single file, coverage-tool behavior), `MIX_ENV=test mix run -e "IO.inspect(...)"` (runtime config), `git log -p -- <path>` ("always been like X" claims), `WebFetch` / `WebSearch` / read-only `curl -sI` (verifying remote URL content/status, API responses, third-party tool end-to-end output). A probe backing a solution-promised path or value MUST assert the TARGET CONTRACT — where/what the pitch promises it lives — not mere existence. Example: `grep -n "shared/scaffold/phoenix" <pitch-target-file>` proving the promised path is present, NOT `ls scaffold.sh` proving some file exists somewhere. Existence ≠ contract. **External-contract trigger**: any falsifiable claim about an EXTERNAL system (a URL's content, an API response, a documented external behavior) requires an external probe — an in-repo probe alone is insufficient. Must execute the code path OR exercise the external contract — reading source/docs is not execution. **Claude Code runtime claim** — any falsifiable claim about Claude Code's own runtime (extended-thinking on/off, settings precedence between scopes, the effect of a launcher flag like `--settings` / `--setting-sources` / `env -u <VAR>`, frontmatter `@`-mention expansion semantics, or which tools a `tools:` deny list actually blocks) MUST be settled by executing the CLI, NOT by reading docs/source or reasoning about settings precedence. Canonical probe: `claude --print --output-format stream-json --verbose [--model <m>] [--settings '<json>' | env -u <VAR>] -- "<reasoning prompt>" | grep -c thinking`. Generalize to non-thinking claims (event types, flag effects) by inspecting the same `stream-json` stream for the relevant `"type":…` token. A single run is one data point — for an on/off claim run the contrast (mechanism present vs absent) so the counts discriminate; do NOT prefix `timeout` (unavailable on macOS zsh, silently aborts the CLI → a false 0). Embed the `$ <command>` + fenced count/output in `## References` before the claim can stand. Docs/source describing the behavior are NOT a substitute. **Scoping guard**: the spread requirement triggers on CLAIM KIND, not byte origin. A **measurement probe** — one whose ledger Outcome is a number computed over a set of inputs (a delta, a net, a count, an N-of-M) rather than a fact about a single artifact — REQUIRES the spread, wherever the bytes came from: in-repo or external. A probe whose Outcome is a fact about an artifact (mode 100644; all four launchers still -lt 6) does NOT — existence is binary, one sample IS the population. The external-contract requirement additionally applies whenever the pitch's core value IS an external-system outcome (fetched content, API response, generated-artifact correctness). **Spread technique** (required for any external probe AND any measurement probe): (1) Name the breaking axis — state what input dimension could make the contract FALSE (e.g., version exists vs missing; resource public vs private). (2) Probe BOTH ends of the axis + the failure mode — minimum 3 probes: a common input, an input at the other end of the named axis, and the failure case (404/error/auth-wall). A single-sample external probe is INCONCLUSIVE, not confirmed. (3) The failure case is mandatory — probe what happens when the resource is absent/inaccessible. For a MEASUREMENT, the axis is a property of the SAMPLE: which inputs were included, and what property of an input could reverse the sign. Where the population is enumerable and cheap, the sample IS the population — "replay over three of the six pitches on disk" is not a confirmed probe. A ledger row naming a number but not the sample it came from is UNPROBED. **Composition check**: when a pitch makes 2+ claims that must INTERACT to deliver the promise, probe the interaction end-to-end, not just each claim alone. **Recovery re-audit**: when a pitch REBUILDS/recovers an artifact from git history or prior art, re-verify the recovered logic against CURRENT external reality — recovered ≠ correct; a latent bug can survive recovery untouched.

- **Sweeps run against committed state, never the dirty tree**: when running a vocabulary sweep (grep for all occurrences of a renamed/removed identifier), run against the current COMMITTED state — either `git show HEAD:<path>` for individual files or a clean checkout — NEVER against the dirty working tree. A sweep against the dirty tree may miss files that exist in HEAD but are modified or deleted locally, producing a false-complete transcript.
- **Leads vs transcripts — cut on interpretation, not on delegation**: a delegated **verbatim transcript** — the `$ command` line plus raw output, returned under a prompt that forbade interpretation — IS a probe transcript and MAY fill a `## Claim ledger` row directly. A delegated **prose summary, diagnosis, judgement, or answer** ("I found X occurrences", "no further references", any conclusion) is an UNVERIFIED LEAD and never enters the ledger — re-run the probe yourself before the claim can stand. An **execute-probe is never delegated** — `Explore` and `--allowed-tools`-scoped `codegen-call` spawns both refuse state-changing commands; every feasibility spike and runtime probe stays with the shaper. A **transcript missing a command it was asked to run is a LEAD, not a transcript** — delegation prompts number their commands and require an echoed `$ command` line for every one, including any not run (`(NOT RUN: <reason>)`); the authoritative check is arithmetic, not honesty — `codegen-call`'s `metrics.bash_count` vs the count of `$ ` lines actually returned catches silent partial completion (an agent that executes everything but narrates only the last result) that the echo requirement alone does not close.
- **Runtime-path fidelity** (applies to any project — app, website, service, CLI, library) — when a load-bearing claim concerns how something behaves at runtime, the probe MUST reproduce the ACTUAL invocation path the user or system takes, end-to-end — not a convenient stand-in. That means: the real **entry point** (the command/wrapper/URL/route the user actually hits, not an inner function or script called directly); the real **build & deployment state** (the production build, installed/copied/symlinked artifact, container, or deployed service that actually executes — not the dev server or repo working copy); and the real **environment** (env vars, secrets, config as actually set or unset on the target — not assumed). A claim verified against any stand-in that can resolve differently from the live system — dev build vs prod build, repo source vs installed copy, direct call vs wrapper/route chain, localhost vs deployed proxy/auth, assumed env vs live env, source default vs loaded value, clean tree vs deployed build — is a proxy and a blocker. Before probing, trace the chain: "what exact entry point runs, what does it reach, with what env, which build, and which on-disk/deployed artifact?" Probe that endpoint. If the chain has a branch (var set vs unset, dev vs prod, copy vs symlink), probe the branch that is live on the target — and if you can't tell which is live, probe both.
- **Operator-surface probe** — at claim-introduction time, when about to write a DELETE/replace/CHANGE move that names a launcher/command file (`*-build.sh`, `ocg`, `codegen-*`, a slash-command `.md.j2`) OR a flag/subcommand token, STOP and probe whether the affected code parses an operator-invoked flag/subcommand: `grep -n '\-\-<flag>\|case .* in' <launcher>`. If it does, the move takes exactly one of THREE dispositions, closed vocabulary, recorded in the external-contract table using the literal label shown: **(a) `Preserved`** — surface-preservation (re-wired + enumerated in the external-contract section); no question needed. **(b) `REMOVED`** — an `AskUserQuestion` keep-vs-remove fork; the operator decides. **(c) `BREAKING`** — a previously-working invocation now fails, admitted ONLY when ALL FIVE hold: the break is FORCED by a named correctness requirement stated in the pitch; every non-breaking alternative is enumerated and each shown to produce a SILENT WRONG result; the external-contract row carries the literal disposition `BREAKING`; the new failure is LOUD at the earliest reachable point and names the fix the operator must type; a `## Decisions` row records it. Disposition (c) takes NO operator fork — nothing to choose between when every alternative is silently wrong — but the five conditions are non-negotiable, and it is auto-decided (fail-closed remains auto-decided even when the requirement CANNOT be guaranteed — the ASK-GATE never routes this to the question tool). A hand-invented disposition label outside `{Preserved, Dropped, Unchanged, REMOVED, BREAKING}` is itself a blocker. Deleting the backing code of an operator-typed/seen surface without one of the three is a blocker at the inline gate.
- **New-producer / existing-convention reconciliation probe** — before writing a "convention unchanged / reused" claim about a new producer, run the reconciliation probe: `grep` how the existing consumers resolve the artifact (e.g. `${CWD:-${CLAUDE_PROJECT_DIR:-$PWD}}`), then assert the new producer resolves the IDENTICAL base. Embed BOTH transcripts in `## References`. A single-sided probe (producer resolves X, consumer unchecked) is insufficient.
- **Masking-default probe** — when a sketch introduces a fallback, default, or catch on a VALUE (not a genuinely-optional knob like a timeout/backoff/display setting), run the 3-part masking-default test BEFORE writing the claim into pitch prose: (1) required, not optional — backs a value the op needs to be CORRECT (model, credential, mode/env switch, routing key, target id); (2) sentinel papers over absence — fallback is `""`/`nil`/`0`/`"unknown"`/a plausible-but-wrong constant; (3) proceeds wrong — missing the real value lets the code keep going and yield silently-wrong output instead of an obvious crash. All three true → the value is REQUIRED-for-correctness and the design MUST fail loud (raise/deny/non-zero), never default. A sketch that writes a fallback/default without running this test is a blocker at the inline gate — treat it like any other unprobed load-bearing claim. **No "tidying" category**: any edit that REMOVES, DEFAULTS, or OMITS a value the system reads is a DECISION — it takes a `## Decisions` row and triggers this test, even when the edit reads on its surface like cleanup/simplification rather than a deliberate change. **Producer-probed / consumer-inferred is a PROXY**, named as such — probing only the side that PRODUCES a value and inferring the CONSUMING side's behavior from that (rather than probing the consumer directly) is a one-sided probe, not a confirmed claim.
- **Dead-code liveness probe** — when a sketch KEEPS a mechanism the change makes redundant (soft-deprecates / keeps as backstop / legacy-fallback / rename-shim), probe liveness at claim-introduction time. Liveness is proven by an EXERCISE, not a reference. A `grep` that finds the mechanism's own registration (`registry.yaml`), its rendered registration (`settings.json`), an allowlist that permits its subject, or any config/doc reference is NON-zero yet proves nothing — those are references, not exercises. The probe must locate a live caller/spawn/emit against COMMITTED state (`git show HEAD:` / clean checkout, per the Sweeps-run-against-committed-state rule above); absent one, DEAD → the sketch must hard-delete, not retain. A "keep — still live" claim written without an exercise-proving transcript in `## References` is a blocker at the inline gate.
- **Capability-removal reachability probe** — before writing any claim that a new deny "leaves `<X>` as the sole remaining path" or "every role can still reach `<X>`", enumerate the affected actors and assert reachability (`grep -rn '^tools:' shared/subagents/**/*.md.j2` or the relevant permission source), cross-check each denied actor's grant against the substitute's required capability, and embed the transcript in `## References`. A claim backed only by a probe of the MECHANISM (the substitute command runs) with no per-actor grant cross-check is insufficient.
- **Capability-grant boundary-intent probe** — before writing any claim that a new tool/permission grant (or a wrapper reintroducing a currently-denied capability) is safe to add, read the denying hook's own `rationale:`/comment and classify it — mechanism-limit (the actor already may do the underlying thing; only an unrelated mechanism is restricted) vs deliberate-boundary (the deny encodes an architectural invariant). Embed the citation (`rationale:` field or hook comment quoted verbatim) in `## References`. An ambiguous rationale is NOT auto-resolved — treat as deliberate-boundary and escalate.
- **Incomplete-replacement probe** — at claim-introduction time, before writing any DELETE move OR "X absorbs/replaces/subsumes/supersedes Y" claim, run BOTH sides — (a) `grep -rn <replacement-symbol>` (non-test) for a live caller, OR `git log -S <symbol>` to prove not born-dead; (b) enumerate + probe each consumer/integration-point of the removed code. Embed BOTH transcripts in `## References`. A one-sided probe (old code read, new caller unchecked) is insufficient — a proxy, not a wiring probe. When the new symbol is a report/advisory/`--check`/`--json` tool, the caller-probe bar is unchanged and a human operator does NOT satisfy it: grep for an AUTOMATED consumer (Makefile leg, hook, loop, CI step). No automated caller found → the tool is born-dead unless the pitch carries a KEEP-ADVISORY justification in the tool's own docs naming the human consumer and why.
- **Empirical-usage-grounding probe** — before writing an API/convention/contract/naming design decision about codegen's own tooling (self-tooling only, not downstream app pitches), mine the 3 codegen-local sources — Claude Code session transcripts (jq-extract `tool_use` Bash invocation signatures + `is_error: true` results), `codegen/logging/*_cycle.jsonl` grep, and a `codegen/pitches/{shipped,archive,ready,draft}/` list of pitches touching the subject — and embed the transcripts in `## References`. If a source is genuinely empty, note "checked, empty," not skipped. **Live-session exclusion**: transcript mining EXCLUDES `${CLAUDE_CODE_SESSION_ID}.jsonl` — the live session's own transcript, inherited by delegated subagents too — self-contamination (mining the very session that is shaping the claim, and reporting its own in-progress reasoning as historical precedent) invalidates the finding. Mined "prior art" naming a flag, syntax, or path must additionally be corroborated by a grep hit in committed source before it counts as precedent.
- **Format/syntax-change opaque-consumer probe** — before writing any "safe for all consumers" / "only field-parsers care" / "consumers unchanged" claim about a change to an artifact's FORMAT/SCHEMA/SYNTAX, run the reader-enumeration grep — search for READERS of the artifact by path/handle/type/endpoint (File.read/open/fetch), NOT the changed field name — classify each consumer field-parser vs opaque/whole-artifact reader, and embed BOTH the field-parser list AND the opaque-reader list in `## References`. A probe that greps only the changed field name is insufficient — it misses opaque whole-artifact readers, the exact consumers a structural change breaks.
- **Required-platform breaking axis** — for any performance, filesystem, process, shell, or OS-tool claim, platform is a MANDATORY breaking axis alongside any other named axis: state whether the measurement was taken on every platform `PROJECT_CONTEXT.md` § Required Platforms declares, and record NORMALIZED PLATFORM + LOGICAL CORE COUNT beside the sample (parallelism-sensitive numbers are meaningless without core count; portability claims are meaningless without platform). A gate result produced on ONE box MUST NOT be written or read as evidence for another required platform — label cross-platform outcomes the gate itself cannot produce as explicit operator verification, never folded silently into the gate's own verdict.
- **Claim-intro recursion (PROBE-COMPLETENESS: derive second-order claims to the leaves)** — a probe RESULT is itself a source of new load-bearing claims. When a probe closes one claim, immediately re-run the consequence test ("if this statement is false, does the solution break or change?") on the probe's RESULT and on the sub-surface of any component you are about to call "fully probed" / "de-risked." Enter each new load-bearing claim it exposes as its own ledger row and probe it. Probing is a tree exhausted to its leaves, not a single pass — never declare a component "fully probed" from a single first-order probe alone.
- **Execute, don't doc-trust (novel-mechanism spike)** — a load-bearing claim about an external tool's behavior (a hook's payload key, a CLI flag's effect, whether a version supports a capability) is proven ONLY by executing it against the actual pinned binary on the target machine — official docs and prior prototypes are leads, not proof, and they drift by version. When the pitch's core value is a not-yet-built mechanism spanning external systems, write a throwaway spike (isolated sandbox — absolute `/tmp/` for a self-contained stub, built by the sandboxed `spike-builder` subagent, or the existing experiment worktree when settings/extension wiring is needed) that drives the REAL target harness CLIs end-to-end, and embed the transcript before the claim can stand. **Spike SETS — attack the claim from several angles at once**: when the claim decomposes into more than one question, design a SET, not a single spike. (1) Each spike answers a DIFFERENT question — N is set by how many distinct questions the claim decomposes into, not by how many ways there are to test the same one. (2) The spike that can KILL the premise runs FIRST, as a negative control, and its result gates whether the rest run at all. (3) Every spike names its measurement BEFORE it runs, from an instrument it did NOT author — server-side ms per call, a request count, a wall-clock delta — never "we'll see if it feels fast" or the builder's own narrated impression. (4) Falsifying research runs BEFORE the build and is GRADED by source, not counted — cheap research that could invalidate the whole set runs first, lands in the ledger as `Claim | Source | Strength`; three agreeing sources are not three probes. (5) The brief — a `| Spike | Question it answers | Measurement | Order |` table plus the negative control's kill-condition — is written into the pitch BEFORE the first spike runs. Until every row carries an embedded transcript, the pitch stays `SHAPING`.

FORBIDDEN:
- Writing a load-bearing fact into pitch prose without an adjacent probe transcript in `## References`.
- Asking the user "should I run probe X?" — just run it. The user only sees results that contradict or are inconclusive; confirmed probes are embedded silently.
- Trusting `context/*.md` as verification — context files are hints, probes are evidence. Context files drift from code; only execution proves current behavior.
- Deferring probes to the `/ready` check. The `/ready` check is the final gate, not the first one. By the time `/ready` runs, falsified claims have already shaped the solution.
- "Source code suggests Y" / "reading `lib/X.ex` shows Y" — reading source is NOT execution. Execute the code path: invoke the tool, query the config, run the command. Reading the source of a config loader does not tell you what the loaded config actually is at runtime. For a Claude Code runtime claim the execution IS the `claude --print` stream-json probe — settings-precedence reasoning is not.

Decision tree after running a probe:
1. Probe confirms → embed `$ <command>` + fenced output in `## References`; claim stands.
2. Probe CONTRADICTS → AUTO-DECIDE: claim is false. Edit pitch to match probe reality (delete claim, update solution). Emit: "Claim contradicted by probe—updated pitch to reality." NO question.
3. Probe inconclusive → AskUserQuestion (revise claim, drop claim, reshape solution).

**Un-run ≠ inconclusive**: branch 3 above means the probe RAN and its result does not discriminate between claim and counter-claim. An UNPROBED claim (the probe has not been run at all) has exactly ONE resolution — run the probe. It is never routed to branch 3, never to the question tool, and probe depth/thoroughness/cost/whether-to-probe-at-all is never itself a question (see the ASK-GATE's forbidden-as-questions list). **No silent-failure option**: whichever branch fires, and whatever `AskUserQuestion` offers in branch 3, no option may ship a known silent failure (a change the shaper already knows drops/masks/deletes state without a loud error) — enumerate a fix instead, or drop the move.

If you realize mid-draft that a claim you just wrote lacks a probe, STOP. Run the probe now. Edit `## References` to embed the transcript before continuing with any further pitch prose. Do not let an unprobed claim sit in the draft while you write more content on top of it.

This discipline is ADDITIVE to the `## Pitch Readiness Check` (which remains unchanged as the final gate). Both layers are required: inline probes prevent falsified claims from shaping the solution; the readiness check is a backstop for anything that slipped through.
