## Inline Probe Discipline (during shaping)

Probes run at claim-introduction time, not at `/ready` time. The Pitch Readiness Check is the final gate — this discipline is the first gate, and both are required.

When you are about to write ANY of these patterns into pitch prose, you MUST run the probe BEFORE the `Edit` or `Write` call lands the claim, and embed the `$ <command>` line + fenced 3–10 line output block in `## References` IN THE SAME `Edit` call. No "I'll verify later." No "the readiness check will catch it."

Run a probe before writing ANY statement whose falsity would break or change the solution (load-bearing). The patterns below are non-exhaustive illustrations, not the gate — detect by consequence, not surface shape:
- "X does Y" / "X already does Y" / "X never does Y" / "X always does Y"
- "X is at <path>" / "X lives in <module>" / "X is defined in <file>"
- Function / module / file existence assertions
- Specific config values (allowlists, env var names, hook lists, tool lists, settings keys)
- Tool allowlists for a subagent / role / command
- Env var names and their expected values
- CI / Makefile / install-script behavior claims
- Convention / design / placement claims ("X should live in `bin/`", "X should be Elixir", "X is invoked via `ocg`") — load-bearing even though they do not read as "X does Y"

**Convention-claim verification mode**: for a convention/design/placement claim, the "real contract" is the governing domain doc `:§section` PLUS a confirming `grep` of the authoritative source encoding the convention (the manifest `launchers` list, `config.yaml`, `registry.yaml`, or the `repo-structure.md` ownership table). Reading the doc alone is a proxy (see the proxy/contract discipline below); doc-citation PLUS the confirming grep IS exercising the contract.

Allowed probes: `grep` / `find` / `ls` (file existence, contract-test checks), `mix help <task>` (task behavior), `mix test --cover <one_test_file>` (single file, coverage-tool behavior), `MIX_ENV=test mix run -e "IO.inspect(...)"` (runtime config), `git log -p -- <path>` ("always been like X" claims), `WebFetch` / `WebSearch` / read-only `curl -sI` (verifying remote URL content/status, API responses, third-party tool end-to-end output). A probe backing a solution-promised path or value MUST assert the TARGET CONTRACT — where/what the pitch promises it lives — not mere existence. Example: `grep -n "shared/scaffold/phoenix" <pitch-target-file>` proving the promised path is present, NOT `ls scaffold.sh` proving some file exists somewhere. Existence ≠ contract. **External-contract trigger**: any falsifiable claim about an EXTERNAL system (a URL's content, an API response, a documented external behavior) requires an external probe — an in-repo probe alone is insufficient. Must execute the code path OR exercise the external contract — reading source/docs is not execution. **Claude Code runtime claim** — any falsifiable claim about Claude Code's own runtime (extended-thinking on/off, settings precedence between scopes, the effect of a launcher flag like `--settings` / `--setting-sources` / `env -u <VAR>`) MUST be settled by executing the CLI, NOT by reading docs/source or reasoning about settings precedence. Canonical probe: `claude --print --output-format stream-json --verbose [--model <m>] [--settings '<json>' | env -u <VAR>] -- "<reasoning prompt>" | grep -c thinking`. Generalize to non-thinking claims (event types, flag effects) by inspecting the same `stream-json` stream for the relevant `"type":…` token. A single run is one data point — for an on/off claim run the contrast (mechanism present vs absent) so the counts discriminate; do NOT prefix `timeout` (unavailable on macOS zsh, silently aborts the CLI → a false 0). Embed the `$ <command>` + fenced count/output in `## References` before the claim can stand. Docs/source describing the behavior are NOT a substitute. **Scoping guard**: the external-contract and spread requirements apply ONLY when the pitch's core value IS an external-system outcome (fetched content, API response, generated-artifact correctness). Pure in-repo pitches (rename, include-gap, hook wiring) are unaffected. **Spread technique** (required for any external probe): (1) Name the breaking axis — state what input dimension could make the contract FALSE (e.g., version exists vs missing; resource public vs private). (2) Probe BOTH ends of the axis + the failure mode — minimum 3 probes: a common input, an input at the other end of the named axis, and the failure case (404/error/auth-wall). A single-sample external probe is INCONCLUSIVE, not confirmed. (3) The failure case is mandatory — probe what happens when the resource is absent/inaccessible. **Composition check**: when a pitch makes 2+ claims that must INTERACT to deliver the promise, probe the interaction end-to-end, not just each claim alone. **Recovery re-audit**: when a pitch REBUILDS/recovers an artifact from git history or prior art, re-verify the recovered logic against CURRENT external reality — recovered ≠ correct; a latent bug can survive recovery untouched.

- **Sweeps run against committed state, never the dirty tree**: when running a vocabulary sweep (grep for all occurrences of a renamed/removed identifier), run against the current COMMITTED state — either `git show HEAD:<path>` for individual files or a clean checkout — NEVER against the dirty working tree. A sweep against the dirty tree may miss files that exist in HEAD but are modified or deleted locally, producing a false-complete transcript.
- **Sub-agent / Explore findings are UNVERIFIED leads**: when a sub-agent, sub-planner, or Explore session reports "I found X occurrences / no further references", treat that as an UNVERIFIED lead, not a confirmed probe. You MUST re-run the probe yourself (the `grep` / `find` / `ls` command) and embed the transcript in `## References` before the claim can stand. A sub-agent's prose summary is NOT a `$ <command>` + fenced output block.
- **Runtime-path fidelity** (applies to any project — app, website, service, CLI, library) — when a load-bearing claim concerns how something behaves at runtime, the probe MUST reproduce the ACTUAL invocation path the user or system takes, end-to-end — not a convenient stand-in. That means: the real **entry point** (the command/wrapper/URL/route the user actually hits, not an inner function or script called directly); the real **build & deployment state** (the production build, installed/copied/symlinked artifact, container, or deployed service that actually executes — not the dev server or repo working copy); and the real **environment** (env vars, secrets, config as actually set or unset on the target — not assumed). A claim verified against any stand-in that can resolve differently from the live system — dev build vs prod build, repo source vs installed copy, direct call vs wrapper/route chain, localhost vs deployed proxy/auth, assumed env vs live env, source default vs loaded value, clean tree vs deployed build — is a proxy and a blocker. Before probing, trace the chain: "what exact entry point runs, what does it reach, with what env, which build, and which on-disk/deployed artifact?" Probe that endpoint. If the chain has a branch (var set vs unset, dev vs prod, copy vs symlink), probe the branch that is live on the target — and if you can't tell which is live, probe both.
- **Operator-surface probe** — at claim-introduction time, when about to write a DELETE/replace move that names a launcher/command file (`*-build.sh`, `ocg`, `codegen-*`, a slash-command `.md.j2`) OR a flag/subcommand token, STOP and probe whether the deleted code parses an operator-invoked flag/subcommand: `grep -n '\-\-<flag>\|case .* in' <launcher>`. If it does → the move cannot land as auto-decided "internal wiring"; it MUST carry surface-preservation (re-wired + enumerated in the external-contract section) OR an `AskUserQuestion` keep-vs-remove fork. Deleting the backing code of an operator-typed/seen surface without one of these is a blocker at the inline gate.
- **New-producer / existing-convention reconciliation probe** — before writing a "convention unchanged / reused" claim about a new producer, run the reconciliation probe: `grep` how the existing consumers resolve the artifact (e.g. `${CWD:-${CLAUDE_PROJECT_DIR:-$PWD}}`), then assert the new producer resolves the IDENTICAL base. Embed BOTH transcripts in `## References`. A single-sided probe (producer resolves X, consumer unchecked) is insufficient.
- **Masking-default probe** — when a sketch introduces a fallback, default, or catch on a VALUE (not a genuinely-optional knob like a timeout/backoff/display setting), run the 3-part masking-default test BEFORE writing the claim into pitch prose: (1) required, not optional — backs a value the op needs to be CORRECT (model, credential, mode/env switch, routing key, target id); (2) sentinel papers over absence — fallback is `""`/`nil`/`0`/`"unknown"`/a plausible-but-wrong constant; (3) proceeds wrong — missing the real value lets the code keep going and yield silently-wrong output instead of an obvious crash. All three true → the value is REQUIRED-for-correctness and the design MUST fail loud (raise/deny/non-zero), never default. A sketch that writes a fallback/default without running this test is a blocker at the inline gate — treat it like any other unprobed load-bearing claim.
- **Dead-code liveness probe** — when a sketch KEEPS a mechanism the change makes redundant (soft-deprecates / keeps as backstop / legacy-fallback / rename-shim), probe liveness at claim-introduction time — `grep` for any remaining caller/consumer/reference against COMMITTED state (`git show HEAD:` / clean checkout, per the Sweeps-run-against-committed-state rule above); zero hits → DEAD → the sketch must hard-delete, not retain. A soft-keep written without a liveness-probe transcript in `## References` is a blocker at the inline gate.
- **Capability-removal reachability probe** — before writing any claim that a new deny "leaves `<X>` as the sole remaining path" or "every role can still reach `<X>`", enumerate the affected actors and assert reachability (`grep -rn '^tools:' shared/subagents/**/*.md.j2` or the relevant permission source), cross-check each denied actor's grant against the substitute's required capability, and embed the transcript in `## References`. A claim backed only by a probe of the MECHANISM (the substitute command runs) with no per-actor grant cross-check is insufficient.
- **Incomplete-replacement probe** — at claim-introduction time, before writing any DELETE move OR "X absorbs/replaces/subsumes/supersedes Y" claim, run BOTH sides — (a) `grep -rn <replacement-symbol>` (non-test) for a live caller, OR `git log -S <symbol>` to prove not born-dead; (b) enumerate + probe each consumer/integration-point of the removed code. Embed BOTH transcripts in `## References`. A one-sided probe (old code read, new caller unchecked) is insufficient — a proxy, not a wiring probe.
- **Empirical-usage-grounding probe** — before writing an API/convention/contract/naming design decision about codegen's own tooling (self-tooling only, not downstream app pitches), mine the 3 codegen-local sources — Claude Code session transcripts (jq-extract `tool_use` Bash invocation signatures + `is_error: true` results), `codegen/logging/*_cycle.jsonl` grep, and a `codegen/pitches/{shipped,archive,ready,draft}/` list of pitches touching the subject — and embed the transcripts in `## References`. If a source is genuinely empty, note "checked, empty," not skipped.
- **Format/syntax-change opaque-consumer probe** — before writing any "safe for all consumers" / "only field-parsers care" / "consumers unchanged" claim about a change to an artifact's FORMAT/SCHEMA/SYNTAX, run the reader-enumeration grep — search for READERS of the artifact by path/handle/type/endpoint (File.read/open/fetch), NOT the changed field name — classify each consumer field-parser vs opaque/whole-artifact reader, and embed BOTH the field-parser list AND the opaque-reader list in `## References`. A probe that greps only the changed field name is insufficient — it misses opaque whole-artifact readers, the exact consumers a structural change breaks.

FORBIDDEN:
- Writing a load-bearing fact into pitch prose without an adjacent probe transcript in `## References`.
- Asking the user "should I run probe X?" — just run it. The user only sees results that contradict or are inconclusive; confirmed probes are embedded silently.
- Trusting `context/*.md` as verification — context files are hints, probes are evidence. Context files drift from code; only execution proves current behavior.
- Deferring probes to the `/ready` check. The `/ready` check is the final gate, not the first one. By the time `/ready` runs, falsified claims have already shaped the solution.
- "Source code suggests Y" / "reading `lib/X.ex` shows Y" — reading source is NOT execution. Execute the code path: invoke the tool, query the config, run the command. Reading the source of a config loader does not tell you what the loaded config actually is at runtime. For a Claude Code runtime claim the execution IS the `claude --print` stream-json probe — settings-precedence reasoning is not.

Decision tree after running a probe:
1. Probe confirms → embed `$ <command>` + fenced output in `## References`; claim stands.
2. Probe CONTRADICTS → AUTO-DECIDE: claim is false. Edit pitch to match probe reality (delete claim, update solution). Emit: "Claim contradicted by probe—updated pitch to reality." NO question.
3. Probe inconclusive → AskUserQuestion (revise claim, drop claim, reshape solution).

If you realize mid-draft that a claim you just wrote lacks a probe, STOP. Run the probe now. Edit `## References` to embed the transcript before continuing with any further pitch prose. Do not let an unprobed claim sit in the draft while you write more content on top of it.

This discipline is ADDITIVE to the `## Pitch Readiness Check` (which remains unchanged as the final gate). Both layers are required: inline probes prevent falsified claims from shaping the solution; the readiness check is a backstop for anything that slipped through.
