## Guard Optional Pipeline Assertions

Pattern: guard optional pipeline assertions (e.g., `mix assets.deploy`, `npm run build`) with filesystem + config checks rather than assuming silent success means the operation succeeded. Silent-success commands (exit 0 but no output) can mask misconfiguration.

Example: `mix assets.deploy` exits 0 silently if the alias isn't defined in `mix.exs`. Assertion guard must check:

1. Filesystem precondition (e.g., `assets/` dir exists)
2. Config precondition (e.g., `"assets.deploy"` alias defined in `mix.exs`)

Only assert the output if both preconditions pass. Otherwise skip the assertion (test still passes; optional feature not available).

## Hermeticity Baseline for Hook Tests

Hook tests that invoke guards with environment-controlled behavior (e.g., guards that read `CLAUDE_ROLE` or `PI_ROLE`) must establish a clean-env baseline to prevent test artifacts from role inheritance or stale env vars. Use `env -u CLAUDE_ROLE -u PI_ROLE` before the guard invocation:

```bash
# Baseline hook invocation (when no explicit extra_env parameter)
stdout=$(printf '%s' "$input" | env -u CLAUDE_ROLE -u PI_ROLE bash "$GUARD" 2>/dev/null || true)

# Alternative: explicit env control (when tests need to pass specific vars)
stdout=$(printf '%s' "$input" | env -u CLAUDE_ROLE -u PI_ROLE MYVAR=value bash "$GUARD" 2>/dev/null || true)
```

Reason: Tests running within a role context (e.g., developer tests invoked from orchestrator within a session) inherit env vars set by the parent harness. A test that calls a guard without unsetting these vars may pass in the test harness but fail in a real agent invocation where the vars are unset or different. Unsetting `CLAUDE_ROLE` and `PI_ROLE` ensures guards see a clean baseline matching real-world conditions.

Applied to: `harnesses/claude/hooks/*_test.sh` baseline hook invocations (when not using extra_env parameter).

## Markdown Heading Patterns in LLM Output

Use case-insensitive regex `~r/##\s+<heading>/i` instead of exact-case string matching for headings generated by LLM (e.g., Shape Up section detection in test assertions).

Reason: LLM capitalisation varies (`## Solution`, `## solution sketch`, `## Solution Sketch`). Exact match `String.contains?("## Solution")` misses case variants.

✅ `body =~ ~r/##\s+solution/i` — catches all case variants
